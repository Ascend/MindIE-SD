## 1. 为什么这对 seam 特别容易「看起来生效」

稀疏注意力与并行的叠加有两类**不报错**的失败：

- **稀疏静默退化为稠密**：某些并行路径（例如环状形态的内部实现）会**绕过注意力后端**直接算
  注意力 ⇒ 稀疏配置被接受、日志无异常、输出与无损**逐字节相同**——这不是「无损」，而是
  **根本没生效**。判据必须包含「与无损档逐字节相同 ⇒ 判未生效」（见 §5）。
- **稀疏在分片上「局部生效」**：若稀疏的选块只看本 rank 的 K/V 分片，则每一片都在做**局部稀疏**，
  数值与收益都不可与全局稀疏对比——而且不报错，只是结果与预期不同。

⇒ 本 seam 的第一条纪律不是「怎么叠加」，而是**「先证明稀疏在叠加形态下真在生效」**。

## 2. 可行性判定：哪些并行形态能与稀疏共存

| 形态 | 与稀疏共存 | 判定依据 |
|---|---|---|
| 环状 CP（Ring） | **不可用** | 框架侧对 `ring_degree>1` 硬拒；且该路径会绕过注意力后端 ⇒ 稀疏静默失效（fail-closed 判「未生效」） |
| AllGather-KV CP（复合 `usp=k, allgather-degree=m`） | **可用** | 本组合实测跑通，且加掩盖后与无掩盖臂**逐字节一致** |
| 纯 Ulysses（`usp=N`） | **可用** | 基线形态 |

判据：**「框架提供该 CP 形态」与「该形态下稀疏仍生效」是两件事**，必须分别核；
支持矩阵里 CP 与稀疏是两行，叠加结论要写在 seam 表（组合层），不能只改单特性行。

## 3. 四条契约（缺一即崩或静默错）

**① 完整 KV 序列：叠加顺序必须是「先汇聚、后稀疏」。**
稀疏选块需要看到**全序列**（池化 + top-k 在全序列上做）⇒ CP 必须先把 K/V 汇聚齐，再算稀疏注意力。
「把稀疏放到汇聚之前」得到的是**局部稀疏**，数值与收益都不可比。这也解释了为何
AllGather-KV 形态天然可叠（它本来就汇聚全量 K/V），而 Ring 形态要先解决"分片可见性"。

**② 窗口/偏移记账：稀疏窗口的全局偏移 = `完整 KV 长度 − 本 rank 逻辑 Q 长度`**（**不是**
`k_len − q_len`；无 joint/拼接张量时该值为 **0**）。这是稀疏实现与 CP 记账之间的**唯一接口**，
写错会直接报 `Q window starts at X, outside the key sequence length Y`。
实践建议：把「joint 张量是否存在」判出来再决定偏移，**不要用一个统一公式蒙两边**。

**③ 块对齐：每 rank 的 KV 分片长度必须是稀疏/量化块的整数倍。**
本组合块 = 64 token：CP 形态的分片 `54784 = 64 × 856` ✓；而纯 8 卡形态的 `S/8 = 13640`
**不是** 64 的倍数 ⇒ 该形态上「量化前移」无法字节精确（同一根因，见 `quantization-dev` §四·B）。
判据式：`S % (并行度 × 块) == 0`。

**④ 掩码是 per-head 的，不能跨 head 分片复用。**
选块掩码形状 `[B, N(head), q_blocks, kv_blocks]`：不同 head 分片持有不同 head ⇒ 掩码不可共用。
想「每层只算一次掩码、各分片复用」必须先把**所有 head 的 K** 汇聚齐再做池化/选块，
那就**丢掉了分块流水**（换来的是每步上万次 kernel 启动开销，而这些 kernel 的时长合计很小
——属启动受限而非吞吐受限）⇒ 本组合实测净负，**不实施**。

## 4. 与通信掩盖叠加时的额外规则

复合形态的掩盖**不能套用纯形态那一套实现**（集合通信种类不同：Ulysses a2a + AllGather）：

- **自己的一套分块实现**：逐块「a2a → AllGather → 稀疏注意力」，块索引放最外层做一次预置换；
- **顺序规则（承重）**：**先把所有块的 Ulysses a2a 发完，再发所有块的 AllGather**。
  两个 communicator 交错下发会让 HCCL 进入不一致状态（本组合实测：交错后运行约两分钟死于
  集合通信内部错误）；
- **AllGather 对上游输出做零拷贝视图**再转置回计算流；侧流只放集合通信、块级 event 排序
  （同 `comm-masking-method.md` §3）；
- **上限算术**：复合形态每片稀疏注意力耗时 ≈ 每片通信耗时 ⇒ **流水两侧平衡 ⇒ 达成率可达 ~100%**；
  纯 8 卡形态每片通信 > 每片计算 ⇒ 达成率约六成。**即：同样的掩盖实现，在复合形态上更值钱**
  ——这是本 seam 的**正协同**来源（见 §5 第四条）。

## 5. 验收判据（seam 级，四条）

1. **稀疏真的生效**：与 lossless 档对比——若输出**逐字节相同**或日志出现 `staying dense`
   ⇒ 判「未生效」，**不得计入任何组合收益**（叠加臂的收益必须能追溯到稀疏路径的算子替换）。
2. **单变量**：叠加臂与对照臂**只差一处**（CP 形态或稀疏档），offload 档 / 量化档 / 步数 /
   seed / 窗口全部固定；形态是启动级参数 ⇒ 必须重启服务，靠**相邻窗口 + 第二窗自查**。
3. **无损性**：若叠加臂带掩盖，则其产物 md5 应与**同形态、不开掩盖**的臂一致（Ulysses a2a 与
   AllGather 都是纯置换/无规约 ⇒ 掩盖必须逐字节等价）；md5 变了先查 §3 的契约③④。
4. **报 seam 强度**：按 `combination-search.md` 的三态（独立 / 协同 / 冲突）表述，并明确
   「叠加收益相对单点收益之积是超出还是欠」。本组合观测：**CP × 掩盖为正协同**——
   掩盖在复合形态上兑现率 ~100%、在纯形态上约 60%，即 CP 让掩盖更值钱；
   但**正协同不等于整体更快**（复合形态端到端仍慢约 10%，见 `parallel-form-selection-method.md`）。

**必须同时报的对照**：叠加臂 vs 「同卡数下另一形态的叠加臂」。只报「加了稀疏更快」不足以支撑
选型结论。

## 6. 已知失效模式表

| 症状 | 根因 | 处置（先判定是否仍存在，再套用） |
|---|---|---|
| 报 `Q window starts at X, outside the key sequence length Y` | 稀疏窗口全局偏移按 `k_len − q_len` 算 | 改为 `k_full_len − logical_q_full_len`（无 joint ⇒ 0）；先确认该报错是否仍存在 |
| 无报错、无收益，输出与 lossless 逐字节相同 | 稀疏静默退化（`staying dense`，或该并行路径绕过注意力后端） | 一律判「未生效」；支持矩阵对应行的证据码不得随之上调 |
| 运行一两分钟后 HCCL 集合通信内部错误 | 两个 communicator 交错下发 | 改为「先全部 A、再全部 B」 |
| 掩盖臂与无掩盖臂 md5 不一致 | 分片块对齐错位，或掩码跨 head 分片复用 | 校验 `S % (并行度 × 块) == 0`；掩码按 head 独立生成 |
| 叠加后每步出现上万次小 kernel 且墙钟变差 | 为「掩码复用」牺牲了分块流水（启动受限） | 回退掩码复用；启动开销与重叠收益要**分别**量 |

## 7. 声明纪律

- 组合收益**只在稀疏生效判据通过后**才允许登记；未通过时按「未生效」上报，不许写 ❓ 之外的收益。
- seam 强度（独立/协同/冲突）必须带**同窗口同形态**对照；跨形态的协同度不可比。
- 不写绝对耗时；用降幅百分比、兑现率、以及「相对单点收益之积」的超出/欠缺表述。
- 与 CP 相关的结论一律带上「GQA 比例 / 跨岛比例 / 块尺寸」三个作用域变量。

## 8. 维护与更新

- **稀疏后端换代**（rf_v2 → rf_v3 / 新的块稀疏实现）：§3 的四条契约逐条复核（尤其是偏移与
  per-head 掩码），判定方法优先于当年的绕过方案。
- **框架升级**：若框架补上 Ring × 稀疏或分片感知的稀疏实现，§2 的「不可用」必须**重测后改写**
  （不要留「以防万一」的旧结论）。
- **块尺寸/量化档变化**：§3 契约③的对齐式与契约①的池化粒度随之变化。
- **新模型**：若模型带 GQA 或 joint（`txt`/`ref`）张量，契约②的偏移不再为 0，必须重新推导
  而不是沿用「= 0」。
