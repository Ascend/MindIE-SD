## 1. DiT-only 口径（强制前置）

**并行对比的所有指标只取去噪（denoise/diffuse）阶段。** VAE 解码、文本编码、权重装载、
warmup、响应编码一律在口径外。

理由（同环境实测）：少步档下固定开销占比畸高，且固定开销自身的**波动幅度**远大于并行差异。
本组合观测：同一配置相邻两次同参请求，DiT 去噪阶段波动为**个位数百分比**，而 VAE 解码阶段
波动可达**数十个百分点**——若把 decode 计入端到端，并行形态之间的差异会被固定开销的抖动
彻底淹没，量到的其实是 VAE 的噪声。这条正是「聚焦 DiT 可以不受 VAE 占比影响」的可执行化。

**取数（按可靠性排序）**：

| 量 | 取法 | 精度 | 说明 |
|---|---|---|---|
| DiT 阶段墙钟 | 日志 `[DiffusionPipelineProfiler] <Pipeline>.diffuse took <x>s` | 微秒 | 每个 rank 各打一行、彼此差 <1 ms ⇒ 取 min；**这是主口径** |
| DiT 单步 | 阶段墙钟 ÷ 实测 denoise 迭代数 | 微秒级 | 分母用**实测迭代数**，见 §7.2 |
| 逐步拆分 | 进度条 `N/M [MM:SS<MM:SS` 相邻累计值之差 | ±1 s 量化 | 用于判「首步 vs 稳态」「步间是否漂移」；**不要用 `s/it`（见 §7.1）** |
| 阶段边界自检 | 核对 `forward ≈ diffuse + decode + encode_prompt` | — | 一次即可确认口径划分正确 |

**排除项（每个配置都要在产物里显式列出）**：VAE 解码、音频 VAE、文本编码、权重装载 /
offload 首发、warmup 请求、响应编码（mp4 封装 / 帧转换）。解码替换（预览级解码器等）只影响
被排除项，**不得**用来宣称并行收益。

## 2. 矩阵设计

- **必须包含至少一对「同卡数、不同切分」**（如 2 卡 `TP1×USP2` vs `TP2×USP1`；4 卡
  `TP1×USP4` vs `TP2×USP2`）。否则无法分离「并行形态」与「卡数」两个变量。
- **每配置两档步数**：少步档（如 4 步，对应部署的少步蒸馏档）+ 一个**较高步锚点**
  （如 10–12 步）。不必跑满（如 50 步）：锚点的作用是暴露「单步耗时是否随步数变化」，
  只要锚点已远离 warmup 且覆盖足够多次迭代即可；满步只用于最终交付复验。
- **预算与删减顺序**：不足时**先保同卡数干净对**，再保 4 卡对；宁可少一格，也不要给一个
  被噪声污染的排序（见 §3、§4 的闸门）。
- **形态是启动级参数，步数是请求级参数** ⇒ 同 serve 内可**交错**发少步/锚点请求（把热漂移与
  共租抖动在步数档之间均摊）；换并行形态必须重启 serve，同卡数的一对配置应在**相邻时间窗**
  跑，并保留第二窗做冷/热自查。
- 负载、prompt、seed、几何、flow_shift 等必须跨配置完全一致；换任一 = 契约变更，旧结论作废。
- 既已被判定病态/不可行的形态（如短任务下的 4-rank 逐层通信病态）**照样纳入并保留证据**——
  那正是判据要覆盖的情形。

## 3. 噪声与漂移纪律

- `warmup 后`才计时：首个请求一律剔除（**它不承担 profiler 捕获**——捕获落点见 §7.5）。
- **每格 ≥3 次重复**，报**离散度 = (max−min)/中位**。
- **离散度 > 3% 的格标「不稳定、不可用于判据」**，不得参与排序结论（沿用本仓「<3% 视为噪声」
  规则，硬阈值）。共租宿主上这是常态而非异常：同环境实测同配置相邻两次请求离散度可达 **7%**
  量级，因此**单次 / 单窗对比不可用**。
- **冷 / 热双窗自查**：同配置先后两窗（含 profiler 开关、负载阶段差异），把两窗差值写进报告。
  首窗（冷）与末窗（热）差异超阈值时，报告须说明结论是否仍然成立。
- 同窗口、同卡组、同负载对比；多次取中位；单次结论不迁移。

## 4. 外推判据（核心产出）

把「能否外推」落到**一个可测的量**上：**DiT 单步耗时**（步数无关的辅助口径）。

设 `step(tier) = DiT 阶段墙钟 / 实测 denoise 迭代数`，`r = step(anchor) / step(few)`：

| 条件 | 判定 | 动作 |
|---|---|---|
| 所有格离散度 ≤ 噪声阈值（3%），且 \|r−1\| ≤ 漂移阈值（5%），且两档**排序一致** | **可外推**：少步排序可用于选型 | 采纳少步结论，在报告标注锚点选项数与 r |
| 排序一致但 \|r−1\| > 漂移阈值 | **不可外推**：单步结构随步数变 | 回锚点档（或更高）重测后再选型 |
| 两档**排序翻转** | **不可外推**：少步档给出的名次是错的 | 一律以锚点档（或更高）结论为准 |
| 任一格离散度 > 3% | **判据不成立** | 先修噪声（加重复 / 换窗 / 换卡组），再判 |

判据的**逻辑要点**：

1. **固定开销必须在口径外**，否则判据不成立——这是先决条件，不是可选优化（§1）。
2. **判据判的是「单步耗时是否稳定」，不是「总耗时是否成比例」**：总耗时 = 迭代数 × 单步 +
   固定项，固定项在少步档放大了占比；只有单步稳定，少步的**单步**排序才等价于全步的排序。
3. **排序（而非绝对值）是主结论**：绝对值只在本次环境成立；排序与比例关系才可迁移。
4. **通信占比也参与判据**（§6）：掩盖空间上限 = 未重叠通信占比，占比漂移同样触发复验。

## 5. 必须回较高步复验的条件

命中任一即**不得**用少步结论下选型判断：

1. 少步档与锚点档**排序翻转**。
2. 单步耗时漂移超阈值（§4）。
3. **未重叠通信占比**随步数 / 随并行策略漂移超阈值（§6）。
4. **短任务通信病态**：少步 + 多 rank 下逐层通信开销 >> GEMM 分摊收益（rank 数越多越明显，
   2 卡形态可与 4 卡形态给出相反结论）——少步档本身可能落在病态区。
5. **特性叠加改变了单步结构**：量化把 GEMM 换量化算子（compute 缩短 → 通信占比抬升）、
   稀疏换 attention 算子、缓存改变步级是否执行 forward ⇒ 必须在该**叠加态**下重采并行指标；
   无损档的并行排序**不可**直接迁移到有损/训练感知档。
6. **显存解锁类改动改变可行域**：offload / 量化会解锁此前不可行的并行形态 ⇒ 每个新档位落地后
   重跑「并行 × 显存余量」候选。
7. 出现新的固定开销项（如解码替换、响应路径变更）改变固定项与 DiT 的比 ⇒ 口径重核。

## 6. 通信占比随步数是否漂移

- 口径：**掩盖空间上限 = 未重叠通信占 DiT 单步的比例**，由单步捕获的
  `step_trace_time.csv`（`Computing` / `Communication(Not Overlapped)` / `Overlapped` /
  `Communication` / `Free` / `Stage`，单位 µs）给出；列名取**精确匹配**——
  `Communication` 是 `Communication(Not Overlapped)` 的子串，子串匹配会静默取错列。
- **占比随并行策略变化**（本仓既有结论）；实测补充：**占比也会被采集方式本身扭曲**——
  profiler 单 forward 捕获会膨胀该次 forward 的墙钟，而**未重叠通信的秒数基本不变**，
  于是「未重叠通信 ÷ 被捕获步的 Stage」是**偏低**的占比。可比口径是
  **未重叠通信秒数 ÷ 未开 profiler 的单步耗时**。判据用**占比的量级与排序**，不要用它的绝对值。
- 因此：**把 profiler 捕获放在被排除的 warmup 请求里**，计时请求全程不采集。
- ⚠️ **捕获落点还必须在「稳态」之后**，这只做了一半。本组合观测：serve 起后**前几个请求的单步明显
  更快**，之后才爬升到稳态（首请求可比稳态快**一成以上**，2–3 个请求后才平）。若捕获落在 ramp 段，
  分母（被捕获步的墙钟）被系统性压小 ⇒ **占比被系统性放大**，且放大倍数随各配置落在 ramp 的不同
  位置而不同——这会伪造成「不同并行策略的通信占比差异」。**判据**：把 `OMNI_KPROF_AFTER` 指到
  **稳态请求内部**的某次 forward（先按 §3 确认稳态从第几个请求开始），并让被捕获的那个请求不参与
  计时统计；若做不到，则只用**未重叠通信的秒数**做量级/排序比较，**不要**用占比。
- 漂移门控：同一并行形态在不同步数档下的未重叠占比漂移超阈值 ⇒ 少步测得的掩盖空间不可外推，
  回锚点档重采（与 §5.3 一致）。
- 框架若为「零重叠」（`Overlapped=0`），掩盖收益上限就是该未重叠占比；**先量占比再决定是否
  投入掩盖实现**，不要先写机制再找收益。

## 7. 踩坑清单

1. **进度条的 `s/it` 是 tqdm 的指数滑动平均速率，不是 `elapsed/n`**——用它乘迭代数还原耗时
   会得到错误值（同环境实测：同一行的 `s/it` 与累计 MM:SS ÷ N 相差约 1.5 倍）。**只用累计
   `MM:SS` 做差分**，并接受 ±1 s 量化；量级在数十秒/步时该量化 ≈ 3%，正好压在本仓噪声阈值上
   ⇒ **逐步数字只用于判「首步 vs 稳态」「步间趋势」，主口径一律用阶段墙钟**（微秒级）。
2. **`num_inference_steps=N` 与实际 denoise forward 次数不一定相等**（同环境实测无损失底路径下
   进度条总数为 `N−1`）。报告必须写明分母取法；跨配置比较时务必用**同一取法**。
3. **请求分段锚不要用 HTTP 访问日志行**：响应可能不回客户端（偶发 `(52) Empty reply from
   server`，历史运行中亦出现过），但 serve 侧的阶段计时**完整**。改为按 API server 每请求一行
   的采样参数行（如 `Video sampling params: steps=N`）分段，数据在响应失败时依然可用。
4. **绝不按进程名 / 命令行模式 pkill**：同宿主 / 同容器常有其他并行实验（别人也跑同一框架，
   只是端口与卡组不同）。只按自己启动的 **PID 树**递归 kill；并在启动前确认目标端口空闲。
5. **profiler 单步捕获会膨胀被捕获的那一次 forward**（同环境实测高于同区间未捕获步）⇒ 捕获**必须落在
   **稳态请求内部**：既不能放**首个请求**（§3 已剔除），也不能放 serve 起后前几个 **ramp 段**请求
   （ramp 段单步更快，会把占比分母压小、使占比虚高，且各配置虚高倍数不同）。
   `KPROF capturing forward #N` / `done` 行是采集生效的证据。
6. **形态是启动级参数**：不能在同一个 serve 里比较两种并行形态；步数可以。
7. **确认调试期插桩是否仍在生效**：形状打印、latent dump 等会引入每请求 I/O 噪声；查明是否有
   env 门控并显式关闭（或确认它只落在被排除阶段）。
8. **计数契约（防 no-op 假结论）**：rank 数 = tp×usp、序列并行/张量并行子组规模行、offload
   生效行、量化/稀疏/适配器装载计数——任一缺失或对不上，该格作废。
9. **`--text-encoder-tp-size`（或等价参数）必须与 DiT world 对齐**，否则编码器子组构建失败。

## 8. 采集与证据包

`scripts/fewstep_multirank_probe.py` 把本协议做成一步可跑：

```bash
# 每形态一个 serve；少步/锚点请求在同一 serve 内交错
python fewstep_multirank_probe.py --out-dir ./runs/probe \
    --config A:{cards}:tp1,usp2,dlo --config B:{cards}:tp2,usp1 \
    --config C:{cards4}:tp1,usp4,dlo --config D:{cards4}:tp2,usp2 \
    --steps-few 4 --steps-anchor 10 --reps 3

# 已有日志的离线复盘（零 NPU）
python fewstep_multirank_probe.py --out-dir ./runs/probe --parse-only
```

产物：每配置一份 `*_serve.log`、请求/响应记录、`kprof_*/`（单步通信捕获）、
汇总 `summary.json`（口径 + 计数契约 + 逐请求指标 + 逐格离散度 + 逐配置判定 +
跨配置排序一致性）、以及人读的 `evidence.md`。

## 9. 声明边界

- 本文件给的是**协议与判据**：口径划分、矩阵设计、噪声门控、外推条件、复验触发条件。
- **比例与排序**可迁移；**绝对耗时 / 绝对加速比**只在原环境成立，归档在会话产物目录。
- 「哪个形态最快」是 **本组合观测**（模型 × 框架版本 × 负载几何 × 卡组拓扑 × 时间窗的函数），
  不得写成可移植的执行序；换任一维度按 §2–§4 重跑。
- 未验证项：跨机型 / 跨互联拓扑的漂移阈值是否仍取 5%；不同框架的 profiler 膨胀系数是否同量级；
  长序列与短视频之间阈值是否可迁移。

### 9.1 适用域按形态细分（方法论示例）

**一条既有结论的适用域，常常比它自己声称的更窄；遇到反例时第一步不是推翻它，而是按变量把适用域切开。**

本组合观测的真实过程（两轮，含一次**自我纠错**）：

1. 既有结论写的是「编码器 TP 参数须与 DiT world 对齐，否则编码器子组 assert」——它取自
   **序列并行**形态的实测。把**纯 TP 形态**（无序列并行）纳入少步矩阵后，按该结论配置时
   **每个请求 fail-closed 500**。到此为止，一个「貌似合理」的归因是：*纯 TP 形态应当改用默认
   单 rank 编码器*。
2. **补对照臂后发现该归因是错的**：换成默认值再跑一次，仍然 500，只是**失败点移到了更晚的
   DiT 输入构造处**。两次失败点不同 ⇒ 真因是「**无序列并行**」这一**形态本身**，与超参取值无关。

因此结论应改写成**依赖形态的两分支**（序列并行形态按原契约；纯 TP 形态直接否决），而不是
「原结论错误」或「反过来才对」。三条纪律：

1. **判定以最新数据为准**，且新数据的价值往往是**细化适用域**而非简单翻转旧结论
   （对应 README §7「判定以最新数据为准」与「方向动态优选」）。
2. **至少要有对照臂，才允许把「形态不可用」与「参数配错」区分开**。本例只凭第一次失败就收口，
   会写出一条**错的修复开关**并进 skills——这是实测中实际发生过的返工。反例出现时先问
   「**它在哪个维度上与我不同**」（本例：有无序列并行），并**变换那个维度再测一次**，
   而不是变换第一个猜到的参数。
3. 这正是少步矩阵**必须包含「同卡数、不同切分」一对**的深层理由：只有把形态变量单独暴露出来，
   才能发现「结论依赖形态」这件事本身；而**对照臂的价值**说明矩阵里还应保留一个「只改一个
   可疑参数」的格子，否则归因不可证伪。
