# a2a 完整性审计（传输是忠实的吗）

**一句话**：当某个跨 rank 的载荷**看起来**被截断 / 陈旧 / 放错位置时，先用**零新增集合通信**的
指纹审计把责任判给**传输**还是**上游内容**，再决定往哪查 —— 否则很容易在"搬运"上耗掉整轮排查。

**先确认走对入口**：

| 你在回答的问题 | 去哪 |
|---|---|
| **搬运本身**是不是忠实（收到的字节 == 对方发出的字节） | 本文件 |
| 分片**有没有真的发生**（改了并行但不报错也没生效） | `scope-effectiveness-check.md` |
| 通信**收益**有多少、算不算数 | `perf-gate`（同窗 A/B、上限账与绑定约束） |
| 量化载荷的**数值契约**（scale 粒度 / 舍入 / 退化块） | `quantization-dev` |
| 结论**看着不对**、怀疑是静默错误而不是传输问题 | `../../accuracy-gate/references/silent-failure-localization.md` |

**为什么值得单独做**：a2a 的失败形态与"上游算错"高度重合 —— 都是"某一小段内容不对"。
本文件给出一组**免参考、免额外集合通信**的判据，能把二者分开（实测口径：跨 4 rank、
上百次调用、数万条腿对，全部一致 ⇒ 传输无责，问题在上游或下游）。

## 一、四条检查（都不新增集合通信）

1. **发送侧逐腿指纹，取两次**：在下发**之前**取一次（`Spre`），在**调用结束时**再取一次（`Spost`）。
   两者相等 ⇒ **发送缓冲在下发后没有被重填/改写** ⇒ **`Spre` 确实是"集合通信读到了什么"的证据** ✓。
   > 这条前提是**承重**的：**只在下发后取指纹是没有证据力的** ✗ —— 那时无法排除
   > "缓冲被下一次迭代重填"，而重填恰好会产生"收到上一次迭代内容"的假象。
2. **接收侧逐源指纹**：每个来源 rank 一条。
3. **跨 rank 对账**（离线，用各 rank 的日志）：`sent_me_to_peer == recv_peer_from_me` 必须**逐腿成立**。
   - 相等 ⇒ 传输忠实 ⇒ 若内容仍错，**要么发送侧内容本来就错，要么错误在消费侧或下游**；
   - 不等 ⇒ 传输 / 落位有问题（此时再看 `Spost` 是否等于 `Spre` 区分"发送缓冲被改写"与"搬运错位"）。
4. **自腿绝对校验（免参考）**：`all_to_all_single` **包含自腿** ⇒ **自己发出的那一行**必须等于
   **自己拼装出的对应分片**。这是一条不需要任何参考实现、也不需要额外通信的绝对判据 ✓。

## 二、两条纪律（否则审计本身会骗人）

- **接收侧证据必须是"被消费的那一份"**：消费方（解包 / 拼装）**当时读到的内容**才作数。
  在**调用结束时重读缓冲**得到的指纹**看不见瞬态错误** —— 若某次搬运先落后错、事后被补齐，
  事后重读必然是"正确"的 ✗。做法：拼装结果与接收缓冲**同时刻**对比，或保留消费时的副本。
  （实测教训：一条"事后重读缓冲两次都一样"的检查被当作"没有瞬态问题"的证据，
  而它按定义**永远无法反驳早读**。）
- **读出口在同一时刻、只做一次主机同步**：把所有指纹在**调用结束时**一次性打印
  （每次调用一次主机同步）。逐块打印会插入额外同步，**改变被测现象的时序** ✗。

## 三、判读表

| 观察 | 结论 | 下一步 |
|---|---|---|
| 逐腿对账全一致、自腿精确、`Spre == Spost` | **传输忠实** | 查发送侧内容（量化契约 / 拼装）或消费侧读法；不要再在搬运上投入 |
| 对账有不一致，且 `Spost != Spre` | 发送缓冲在**下发后被改写**（下一轮复用/重填） | 修缓冲生命周期（每轮新建或按流登记生命周期） |
| 对账有不一致，且 `Spost == Spre` | **搬运 / 落位**问题 | 查切分形状、对齐、每目的分片边界 |
| 自腿不精确 | **拼装 / 打包**自身的错 | 查 rank 顺序、每来源偏移、池化/尺度区的布局 |
| 逐腿对账不一致且**只在部分 rank 上** | 先按 `perf-gate/references/measurement-discipline.md` §8 做**负对照**：很可能是审计的依赖/顺序没写全 | 先修仪器，再下结论 |

## 四、反模式

- **为审计加集合通信**：会改变被测现象的时序（本仓曾因审计自身引入的依赖缺失而产出上千条假阳性）；
- **只用"事后快照"**：看不见瞬态错误（见 §二）；
- **只验首字节**：把"没写入（仍是哨兵）"与"写了陈旧内容"混成一个计数 ⇒ 分不出故障种类
  （哨兵法见 `perf-gate/references/measurement-discipline.md` §8.2）；
- **拿"某条腿错"直接断定传输有责**：必须先过 §一 的四条（尤其自腿与对账）再归因。

## 五、最小落地形态

审计应做成**默认关闭的门控**（`env` 开关 + 打印行数上限），只在排查时打开：
它本身是诊断载荷，**进不了稳态**（打印与指纹都有成本）。
可复用的分析器：`scripts/a2a_reconcile.py`（读各 rank 日志，逐腿对账并给出上面判读表的那一行）。

## 六、设备侧仪器自检三件套（单卡 / 双卡、无模型）

"仪器可信"要三条一起才有意义（口径见 `../../perf-gate/references/measurement-discipline.md` §8）：

| 环节 | 做法 | 合格判据 |
|---|---|---|
| **① 造假象** | 故意把等待**方向写反**的探针 | 必须报出 `MISMATCH` 腿 ⇒ 该缺陷确实会产出"载荷损坏"的假象 ✓（腿数与分布见归档 `{run_results_dir}/archive/`） |
| **② 改正后干净** | 有序臂（等待方向正确） | `legs_bad == 0` ✓ |
| **③ 负对照仍能检出** | 在有序臂上**故意去掉顺序** | 必须报出坏腿（数量与分布见归档 `{run_results_dir}/archive/`）⇒ **探测器不是瞎的** ✓ |

> 判据：`legs_bad == 0` **只有在第 ③ 行成立时才有意义** —— 没有负对照的"全对"，
> 无法区分"传输真的忠实"与"探针根本没在看"（同 §二 的纪律）。

## 维护与更新

- **更新触发条件**：集合通信原语（`all_to_all_single` / 变体）、后端版本、切分形状或缓冲区生命周期
  策略变化时，§一 的四条检查与 §三 判读表都要重跑一次；**换 rank 数也要重跑 §六 的三件套**
  （到达偏斜随 rank 数变化，腿数与坏腿计数的期望值都会变）。
- **复核方法**：构造一次**已知错误**（例如故意让发送缓冲在下次迭代复用）作为负对照，
  确认 §三 第二行（`Spost != Spre`）能被判出来；再对一份干净运行确认全一致。
- **失效信号**：若对账/自腿在**负对照**下不再报错，说明审计的依赖或打印时刻已失效（先修仪器）；
  若框架开始自带每腿校验和，本节可退化为"直接读框架校验结论"。
