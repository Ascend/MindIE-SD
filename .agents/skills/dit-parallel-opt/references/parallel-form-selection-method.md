# 方法：序列并行形态抉择（纯 Ulysses vs 复合 AllGather-KV × Ulysses）

> **来源环境（case 坐标）**：判据由「扩散 DiT（Q/K/V 头数相同，无 GQA）× 某三方推理框架的三种形态：
> 纯序列并行（`usp=8`）、复合「AllGather-KV × Ulysses」（`usp=4, allgather-degree=2`，卡数只用一半做
> Ulysses、另一半做 KV 汇聚）、以及 `usp=2, allgather-degree=2`」这一组合的实测回填；
> 芯片 / 卡数 / 拓扑与版本快照见会话产物归档与对应 case 记录。
> **所有比例都是这一套组合的快照**，换拓扑 / 卡数 / 框架 / 模型（尤其是 GQA 比例）必须重判；
> 方法与判据可迁移。隐私：不含主机名 / IP / 容器名 / 账号。
>
> 边界：通信量下限模型、阶段 Δ 分解、投影纪律的**通用形式**在
> `parallel-plan-attribution-method.md`；本文是把它组装成**一次抉择流程**（含前置否决关）；
> 掩盖上限算术在 `comm-masking-method.md`；与稀疏叠加的契约在 `cp-sparse-combination-method.md`。

## 1. 先纠正一个直觉

**「拓扑更优的形态一定更快」是错的。** 复合形态常有一个非常漂亮的局部读数（例如它把 Ulysses
的 a2a 全部放进**同岛**，a2a 耗时降到纯形态的 **1/4** 量级），但代价是它把 K/V 的汇聚搬到
**跨岛**链路上，而那一步的绝对耗时可以吃掉全部收益。本组合观测：a2a 省下的量级是十的二次方
毫秒级，而 AllGather-KV 跨岛多出的是**同一量级甚至更大** ⇒ 净亏。**只看「哪个通信更快」会得出
相反结论；必须比「每 rank 每层的总字节 × 各自链路带宽」。**

第二个反直觉：**纯形态的通信量并不天然更大**。在**无 GQA**（Q=K=V 头数相同）的模型上，
两种形态的**跨岛**字节几乎相同（本组合观测：差异 < 1%）。所以「复合形态更省通信」这句话
只在**有 GQA** 时成立（见 §2-G3）。

## 2. 抉择流程（七关，任一关否决即出局）

```text
G1 框架/形态可用性  →  G2 显存与驻留可行性  →  G3 每层通信量下限（跨岛/同岛两列）
  →  G4 形态自带的计算 plumbing  →  G5 掩盖上限 c/f  →  G6 同窗口 A/B + 线性度
  →  G7 投影与反代阈值
```

**G1 形态可用性（前置否决关，必须先用最小负载跑通）**
按 `framework-integration` 的框架列核对：形态是否被框架提供、是否被硬拒、是否会让某个
特性**静默失效**。本组合观测：Ring 形态在框架侧被硬拒且其路径会**绕过注意力后端**（使稀疏静默
退化为稠密）；4 卡的 `usp=2, allgather-degree=2` 在本负载下**起不来**（HTTP 5xx，未定位）。
⇒ **未跑通的形态不进候选矩阵**，更不能用「理论上更好」为它留位。

**G2 显存与驻留可行性**
更激进的形态常因单卡权重驻留超容量而不可行；先按 `framework-integration` 的 offload
章节用**无损手段**解锁（本组合观测：分布式逐层 offload 把不可行形态变可行），再比性能。
**顺序不能反**：先解锁、后选型，否则矩阵里全是不可行格。

**G3 每层通信量下限（跨岛 / 同岛两列，缺一不可）**
按 `parallel-plan-attribution-method.md` §6 建模。**GQA 比例是决定性变量**：

| GQA | 复合形态的跨岛量 | 结论方向 |
|---|---|---|
| 有 GQA（KV 头数 < Q 头数） | 按 KV 头比例下降（本组合按 7:1 估算时降到约 1/7） | 复合形态下限显著更低，**值得投入** |
| **无 GQA（Q=K=V 同头数）** | 与纯形态**几乎相同** | 复合形态**没有通信量优势**，其胜负只能来自同岛流量或计算差异 |

**G4 形态自带的计算 plumbing（不会被掩盖的成本）**
复合形态在每层多做布局转换 / 分块中间态，这部分是 `Computing` 里的**固有增量**。
本组合观测：两形态每步墙钟差里，**计算项占约 1/3**、未重叠通信占约 55%、空闲（`Free`）占约 10%。
⇒ **只算通信项会得出相反的答案**（见 §G7）。

**G5 掩盖上限 `c/f`**
用 `mask_bound_calc.py` 对**该形态**算（不同形态被掩盖的族不同：纯形态掩 a2a，复合形态掩
AllGather-KV）。本组合观测：复合形态的每片计算 ≈ 每片通信（流水两侧平衡）⇒ 达成率可达 ~100%；
纯 8 卡形态每片通信 > 每片计算 ⇒ 达成率约六成。**「谁更能被掩盖」不等于「谁更快」**：
掩盖已达上限仍可能整体更慢（本组合正是如此）。

**G6 同窗口 A/B + 线性度**
形态是**启动级参数**，必须重启服务；因此只能靠**相邻窗口 + 第二窗自查**，且两臂只有一个变量
（offload 档、量化档、稀疏档、步数全部固定）。同时测 4 卡 → 8 卡线性度：本组合观测，纯形态
4→8 卡线性度约 78%，加上掩盖后升到约 90% ⇒ **线性度差首先是「暴露通信占比」问题，而不是
「8 卡并行度不行」**。

**G7 投影与反超阈值**
给出「修好 X 就会反超」时，必须：只改被修复项、保留对方的**计算 plumbing**、标注是投影、
给出**反超阈值**。本组合观测过一次完整反转：按「修好未解释的带宽损失」投影，复合形态每步反超
约 7%；但把**两边同时**加上「通信前量化」后（载荷减半、计算项占比升高）**排名又反回去**。
⇒ 投影不把计算项一起算，结论就是错的。

## 3. 判据表（本组合观测）

| 维度 | 纯 Ulysses（8 卡） | 复合 AG-KV × Ulysses（8 卡） |
|---|---|---|
| 可用性 | ✅ 稳定 | ✅ 可跑（4 卡 2×2 变体未跑通） |
| a2a 链路 | 跨岛（4/7 流量跨岛） | **同岛**（a2a 耗时降到约 1/4 量级） |
| K/V 汇聚 | 无需 | **跨岛**，隐含带宽只有隔离微基准的**约一半**（机制未定位） |
| 跨岛字节/层/rank（无 GQA） | 基准 | 与基准**几乎相同**（差 < 1%） |
| 同岛字节/层/rank | 较低 | **约 2×** 基准 |
| 每步计算增量 | 基准 | **+1/3 的步间差**（形态 plumbing） |
| 掩盖达成率（对自身 `F(1−1/n)`） | ~60% | **~100%**（每片计算 ≈ 每片通信） |
| 端到端（各形态最佳配置，同窗） | **领先** | 慢约 10% |

**读法**：复合形态输在「跨岛 K/V 汇聚的绝对耗时 + 计算 plumbing」，而不是输在掩盖没做好。
**决定性未知量 = 那个未解释的约 2× 带宽损失** ⇒ 抉择的结论必须挂在这个量上（§4）。

## 4. 条件化结论的写法

不要写「A 比 B 好」，写**以 gating 变量为条件的结论 + 当前实测所处的区间 + 决定性未知量**：

```text
当 <GQA 比例 / 带宽效率 / 量化档> 满足 <不等式> 时，形态 X 胜出；否则形态 Y 胜。
当前实测：<gating 变量> = <值/区间> ⇒ 落在「Y 胜」一侧，差距 <比例>。
抑制结论的未知量：<未解释项>（判定方法：<一条可执行的对照实验>）。
反超阈值：<未解释项> 修复到 <水平> 以上时结论反转（预计 <比例>）。
```

本组合的实例化：**无 GQA + 跨岛汇聚带宽约为隔离值一半 ⇒ 纯形态胜，差距约 10%；若汇聚带宽
修好（或模型改为带 GQA），复合形态预计反超约 7%；但两边同时做「通信前量化」则再次反转。**
这三句话就是该抉择在本环境下的完整答案。

## 5. 必须重判的触发清单

- **模型结构变化**：GQA 比例、头数、`head_dim` 变化（直接改 G3 的两列字节）；
- **载荷变化**：任何把集合通信载荷减半的动作（通信前量化、fp8 KV、合并集合）——因为它同时
  改变 `c/f` 与「计算项占比」，本组合观测就出现过由此导致的**排名反转**；
- **拓扑/卡数变化**：跨岛比例、UB 岛结构、卡数增减；
- **框架升级**：形态实现或 offload 实现换代（G1/G4 的期望值会变，`-enablement.md` 与支持矩阵
  的 last-checked 需刷新）；
- **负载规模变化**：序列长度改变会同时改通信量与 `O(S²)` 注意力占比；
- **未解释项被定位或被修复**（本组合的约 2× 带宽损失）：一旦有结论，本抉择**立即重算**。

## 6. 声明纪律

- 形态结论必须带**同窗口 A/B**、卡组、拓扑、offload/量化/稀疏档与步数；跨窗口的绝对值不可相减。
- 不写绝对耗时；用比例、差值份额、「谁领先多少个百分点」表述。
- **未跑通的形态写「未跑通」，不写「不可用」**（前者是观测，后者是结论）；
  **未定位的机制写成未解释项**，不得当成已解释的胜负理由。
- 单选型结论（「就选 X」）只在**所有 gating 变量都已被实测固定**时才允许给出。

## 7. 维护与更新

- 框架提供新形态（如 Ring 修复、CP 与 TP 混合）时：先按 G1 跑通最小负载，再进 G3 建模；
  支持矩阵对应行按 `framework-support-matrix.md` §三刷新协议更新。
- 每次模型优化收口（S3/S4 闭环）时复核本文件 §3 的判据表是否已被新数据取代；被取代的行
  **改写而不是叠加**，避免同一维度多套数字并存。
- 与稀疏叠加时按 `cp-sparse-combination-method.md` 的契约先判可行，再回到本文 G3 比字节。
