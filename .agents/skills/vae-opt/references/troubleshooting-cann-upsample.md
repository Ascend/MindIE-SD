# 排障：CANN 最近邻上采样在大 batch 下少写尾部

**加载时机**：解码结果出现"**尾段塌陷 / 后半段全坏**"、且走的是**时间维解码器 + 大 batch 单次
上采样**这条路径时；或分片被用来"绕过设备算子缺陷"、需要确认缺陷本身是否仍存在时。

**本文件的边界**：只记该对象的**判定实验、规避手段、修复 / 回退条件**。通用定位流程（CPU 真值 →
指标量化 → 逐层打点 → 算子隔离 → 阈值扫描 → 陈旧内存判定）见
`accuracy-gate/references/silent-failure-localization.md`；状态携带切分的完整实现方法见
同目录 `sliced-state-decode.md` 与 `scripts/sliced_state_decode.py`（**手段本体属本技能，本文件只引用**）。
按数字纪律，本文件**不写**实测数字（耗时、md5、帧读数、阈值点值与首坏帧号）——那些是会话产物，
换机器 / 版本 / 形状即失效。

## 1 现象与适用范围

- **命中条件**：最近邻上采样在**单次调用的 batch 超过 kernel 可完整写入的规模**时，输出尾部一整段
  **根本没有被写入**，读回的是分配时的残留显存（陈旧内存）；
- **业务表现**：时间维解码器的某次空间上采样 batch 由"潜帧数 × 时间上采样倍率"构成，一旦越过阈值，
  成品会从某个**绝对帧号**起塌陷并持续到片尾（结构消失 + 通道漂移），前段完全正常；
- **完全静默**：无报错、无 NaN/Inf、形状正确、帧数正确、**同一进程内 md5 稳定** ⇒ 常规"查异常 /
  查 NaN / 查帧数 / 查 md5"一律抓不到；
- **触发面窄**：只有"时间维解码器 + 大 batch 单次上采样"会构造这么大的调用；逐帧小 batch 的 2-D
  预览网从不触发，所以同一份仓内代码在另一条血缘上看不出问题。

## 2 判定实验（如何确认缺陷仍存在）

按顺序做，**第 3 / 4 / 5 条同时成立即可定案**；结论是"该版本上缺陷仍在"或"已被修"，
两者都要落到报告里：

1. **算子隔离**：同一输入同一形状，CPU 与 NPU 各跑一次
   `F.interpolate(x, scale_factor=2, mode="nearest")`，逐 batch 元素比 `max|d|`，并把它与该算子
   **输入的 absmax** 相比——量级级别的大错（而不是精度级的小差）才指向"没写入"；
2. **等价写法交叉验**：`nn.Upsample(scale_factor=2)`、`F.interpolate(mode="nearest")`、
   `mode="nearest-exact"`、`size=(2H, 2W)` 四种写法是否**同样坏**。同样坏 ⇒ 同一个底层 kernel，
   改 Python 侧调用方式没用，必须绕开这个 kernel 或这个规模；
3. **规模阈值扫描**：固定输入内容，只改单次调用 batch，找出干净区上限与坏区分界，并确认坏区起点是
   **固定的绝对索引**（与 batch 总量无关）还是"后 N%"；工具
   `accuracy-gate/scripts/op_threshold_sweep.py`；
4. **陈旧内存判定**：同一进程内重跑结果一致、但**跨运行坏区内容不一致**（相关性显著低于 1）
   ⇒ 读到的是残留显存，而不是数值漂移；
5. **写出可复核的缺陷态判据**：输入形状 + dtype + 干净 batch 档 + 坏 batch 档 + 首坏索引，
   其中阈值**只写区间**（未继续二分就如实标注区间）。

**判读**：三条同时成立 ⇒ 本缺陷仍在，可进入 §3；任一条不成立 ⇒ 该版本可能已修、或形态已变，
回到通用流程重新定位。**旧结论只在原版本 / 原形状下有效**，换 CANN 或驱动后必须重做本节的 3、4 两步。

## 3 规避手段

按代价排序；"手段本体"归各技能的优化条目，这里只写"在什么条件下用"：

1. **降到阈值以下（拆调用）**：把单次调用拆成多次，每次 batch ≤ 干净区上限。逐帧 / 逐 token 独立
   的算子可以直接拆；本对象**不可整体乱拆**，因为解码器里只有状态层跨帧耦合，随意拆会改变语义；
2. **状态携带式切片**（**本技能采用的手段**）：按潜帧边界切段，并把每段末帧在状态层**输入**处的
   激活传给下一段 ⇒ CPU 上"整段 vs 分段"逐位相等，再上卡验证。实现模式见
   `references/sliced-state-decode.md` 与 `scripts/sliced_state_decode.py`；**段数以现场阈值扫描为准**，
   不要照搬任何历史值；
3. **等价重写**：`x.repeat_interleave(2, dim=-2).repeat_interleave(2, dim=-1)` 与最近邻 2× 上采样
   数值等价，但会**新建整张输出张量**——在显存紧张的多卡服务里可能直接 OOM
   ⇒ **等价 ≠ 可用，先算峰值内存**；内存不许可时选第 2 条而不是本条。

## 4 修复与回退条件

不满足以下前提就**不要**以"无损"名义上线：

- **逐位前提**：CPU 上"整段 vs 目标段数"`max|d| = 0`。不为 0 时先查状态搬运的三个常见错因：
  ① 存的是块**输出**而非块**输入**；② 未 clone / 跨段 dtype 未对齐；③ 切点没落在潜帧边界。
  逐位不成立 ⇒ 不允许声称等价，走闸①不通过的处理（见 `SKILL.md` 的验证流程）；
- **端到端与健康**：同窗口多请求产物 md5 一致，且健康指标（闸③）无尾段塌陷；
- **必须留回退**：一行 env / 开关退回整段解码，并在结论里写明回退值。

**触发回退的条件**（出现任一条就退回整段，并在报告里记录理由）：

1. 换 CANN / 驱动版本后阈值扫描显示该算子已完整写入——此时分段只剩"省显存"一个理由，需重新评估
   是否保留，**不应继续以"绕过缺陷"为名保留**；
2. 输入形状变化使单次调用天然低于干净区上限——分段成为纯开销；
3. 改变段数后逐位前提不成立（段数必须由等价性判据决定，不能由"卡多"或"更省"决定）；
4. 新切法引入新的尾段异常（健康指标出现塌陷 / 冻结段 / 反复尖峰）。

## 5 复核触发

| 轴 | 为什么会推翻旧结论 | 重测方式 |
|---|---|---|
| CANN / 驱动 / 框架版本 | 该 kernel 可能已被修复，阈值与首坏索引都会变 | 重做 §2 的 3、4 两步 |
| 输入形状 / 潜帧数 / 分辨率 | 单次上采样 batch 直接由这些量决定，可能天然越界或天然安全 | 用真实形状重算 batch 并重扫 |
| 解码器结构（状态层位置） | 状态层的自然边界决定能不能切、切在哪里 | 重做独立性审计与逐位对拍 |
| 显存预算 | 等价重写类手段的可否用性由峰值内存决定 | 重算峰值内存 |
| 是否使用有损档（改精度 / 换权重） | 门禁口径从"逐位"变"数值门 + 质量门" | 按精度验收标准改判据 |

## 6 影响面：为什么以前没暴露

- **触发面窄**：只有"时间维解码器 + 大 batch 单次上采样"这条路径会构造这么大的调用，另一条血缘用
  逐帧小 batch 的 2-D 预览网，从不触发；
- **历史产物已受影响**：所有走这条路径生成的片子都带该缺陷。判据是"两份不同片子对应时段的桶化
  指标**逐位相同**"（同一份残留内容，故为同源证据）；
- **静默**：HTTP 200、帧数正确、同进程 md5 稳定，所以问题总是先在"画质"上被人眼发现，而不是被门禁。

## 7 给 vendor 的最小诉求（可直接引用）

1. 该算子应在任意 batch / 形状下完整写入输出；若存在受限形状，请**显式报错或断言**，不要静默返回
   未初始化的显存内容；
2. 给出该 kernel 的 batch 维上限及判定依据，并说明首坏索引这一常数是否来自核数 / UB 分块等内部分块
   参数；
3. 排查方向：分块 / tiling 的**尾块（tail block）写入路径**、`nearest` 与 `nearest-exact` 共用
   kernel 时的边界处理、规模阈值附近的核数与对齐切换点。

**上报材料**：最小复现脚本（可独立运行、无私有依赖）+ 等价写法对照表 + 规模阈值表（只写区间）+
首坏索引 + 跨运行相关性证据 + 缺陷态与正常态的对照样本。完整结构见
`accuracy-gate/references/silent-failure-localization.md` §14。
