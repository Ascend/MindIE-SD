# 解码分片「到底有没有生效」的判定（VAE / 解码器侧）

> **加载时机**：给解码器加了分片/状态携带切分（或改了片数、门控）之后
> —— **结果没变（既不更快也没变坏）、看起来生效了但收益测不出、或“看着生效了但结果不对”** 时。
> 判据顺序：**先证明分片确实发生，再谈等价与收益**。
>
> **边界（各技能对自身使能成功负责）**：本文件只管**解码器分片自身的生效判定**；
> 分片的独立性与逐位等价证明流程（四道闸）见 `../SKILL.md` 与 `verification-and-budget.md`；
> DiT 侧并行（SP/CP/Ulysses）的同类判据在
> `dit-parallel-opt/references/scope-effectiveness-check.md`；
> 测量与上报口径（三证、ABBA、噪声地板、上报模板）单点在 `perf-gate/references/`，
> 本文件不复述，只在 §6 给出指针。

---

## 1. 为什么解码分片的“没生效”同样是静默的

- **门控没生效**：片数由 env 推导，若读取点落在分支判定**之后**（或启动脚本把变量 `unset` 了），
  实跑仍是 `pieces=1` → **每个 rank 照旧完整解一遍整段**：产物完全正确（因为这是冗余计算），
  只是耗时**一点没变**。→ 最容易被读成“切分没用”，真相是“切分根本没发生”。
- **日志 ≠ 生效**：`sliced decode enabled` 这类日志常打印在**注册/切片真正发生之前**，
  按日志判定会得出完全相反的结论。
- **判定绝不能依赖 `rank`**：进入“要通信”路径（状态交换、all-gather）的条件只能由 env + shape 推出，
  否则会死锁或半张量（见 `../SKILL.md` 第 4 步）。**这条本身也是“静默失败”的一种**：
  它不会报错，只会让部分 rank 走另一条路。

---

## 2. 第一步：打印状态量，证明分片是否发生

不要从“结果对不对”开始，也不要从日志开始，**先从“这一段到底被切成几片”开始**。在解码入口与
状态携带处各打一次状态量（**不是**日志字符串）：

```python
import os, sys

pieces = int(os.environ.get("VAE_SHARD_PIECES", "1"))   # 门控的“实读值”，不是“以为的值”
world = int(os.environ.get("WORLD_SIZE", "1"))
sys.stderr.write(
    "[vae-probe] pieces=%s world=%s rank=%s x=%s state=%s\n"
    % (pieces, world, os.environ.get("RANK"),
       tuple(x.shape), None if state is None else tuple(state[0].shape))
)
sys.stderr.flush()
```

**判读规则**：

| 观测量 | 含义 |
|---|---|
| `pieces == 1` 且门控本应 >1 | **分片未生效**（门控读取点/启动脚本问题）——本次读数当基线处理，不能报收益 |
| 片内张量输出宽度 == 整段宽度 | **未切片**（仍在冗余整段解码） |
| 片内输出宽度 ≈ 整段 / `pieces`（± 边界对齐） | 已切片 ✓ |
| `state is None` 而该网络有记忆块 | 状态携带**没接上** → 这类通常**会**出错，不要当成“生效” |
| 段数与 `pieces` 不一致 | 切片数与门控不符（多一层默认值覆盖） |

**要点：门控的“实读值”必须打印出来**，不能只信导出语句与代码默认值 ——
“配错了”会伪装成“优化无效”。

## 3. 第二步：两侧对照，不要单侧下结论

同一个探针，**关（`pieces=1`）与开（2 / 4 片）两侧各跑一次，表格化对比**，再下结论：

| 观测 | 关（基线） | 开（2 片） | 结论 |
|---|---|---|---|
| `pieces` / 片内 shape | 1 / 整段 | 2 / 半段 | 切片确实发生 ✓ |
| 段边界与状态 | 无 state | 每段携带末帧 state | 状态路径已接 |
| 产物 md5 | 基线 | 与基线一致 | **还需 §4 的歧义排除** |
| 段耗时 / 峰值显存 | 基线 | 变短 / 下降 | 收益才可谈 |

只测一侧的典型代价：看到 md5 一致就宣布“分片无损”，而实际是 `pieces=1` 的静默回退
（两侧本来就是同一条路径，当然一致）。

---

## 4. 关键歧义：逐字节相同有两种解释

**“开与关的产物逐字节相同”既可以读成“切分精确无损”，也可以读成“切分根本没发生”。**
两者只能靠 §2/§3 的**状态量**分开：**先确认切片真的发生，再看逐位相等**，两条同时成立才可称
“分片无损”（顺序反了就会把静默回退误判成无损）。

同理，**“与整段逐位相等”本身不是“没生效”的证据**：本技能的分片是**精确等价变换**，
精确分片的正确结果就是逐位相等；判定是否生效只能用状态量（shape / 段数 / state）。

## 5. 第三步：沿“判别量”逐层收窄，而不是猜

当“切片确实发生了，但结果不对”时，**找一个会在正确与错误路径上取不同值的量**，一路往上追。
解码侧可用的判别量（按层级从外到内）：

1. **段边界**：每段的输入潜帧区间是否与预期一致（潜帧 j ↔ 输出帧 `time_upscale × j`）；
2. **携带状态**：每段末帧在记忆块**输入处**的激活（不是输出）是否被真正传递，
   打印其统计量（mean / std / md5）而不是只看 shape；
3. **单次调用规模**：该算子单次调用的 batch / 帧数（阈值类缺陷的判别量，见
   `../SKILL.md` 第 6 步与 `troubleshooting-cann-upsample` 一类的对象化记录）；
4. **片数本身**：同一实现仅改片数就不再逐位精确 ⇒ **片数必须由等价性判据决定，不能由“卡多”决定**。

**每一步都产出一个可打印的判别量**，而不是“我觉得应该是状态没传”。猜错的假设会互相叠加。

## 6. 收益与上报：口径单点（本节不重复定义）

- **收益必须按同窗 A/B 验收**（同环境帧轴切分用漂移受控 A/B/A 观测到亚秒级收益，作用域：Ascend 950PR
  8 卡 · CANN 25.7.rc1.6 · 容器内 vLLM-Omni 0.28 + MindIE-SD；**绝对值换环境即失效**），
  不要用跨窗口数字宣称收益；
- **失败运行的“漂亮数字”**：三项证据的定义与判据单点在
  `../../perf-gate/references/evidence-toolbox.md` §1；
  **交错对照（ABBA）与哨兵翻转**（门控可逐请求翻转是前提）单点在
  `../../perf-gate/references/measurement-discipline.md` §2；
- **判定“差异很大算不算 bug”**前先做数值敏感度校准，SOP 单点在
  `../../perf-gate/references/measurement-discipline.md` §3。
