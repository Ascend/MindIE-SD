# 独立性证明：哪些算子会把切片绑在一起

本文件回答一个问题：**给定解码器网络与候选切分轴，能不能精确切？** 结论必须由逐算子审计得出，不能由“代码里有 chunk”或“8 卡结果一样”推断。

> **作用域（强制）**：文中实测数字的**来源环境坐标（机型 / 卡数 / 软件栈版本与输入档）见会话产物归档**，口径 15 s / 768P（USP8）。判定表可迁移，**数字换环境即重测**。

## 1. 判定原则

> **输出元素是否依赖切片边界之外的输入？** 依赖 ⇒ 该轴不可直接切（要么带 halo，要么带状态，要么不切）。

按轴分类的常见算子：

| 算子类型 | 是否跨 T（帧/时间） | 是否跨 H/W（空间） | 切分含义 |
|---|---|---|---|
| 逐元素（`clamp`/`relu`/`mul`/`add`/`cast`） | 否 | 否 | 任意轴可切 |
| 逐帧归一化（逐帧 `quantile`/`mean`/`std`） | **否**（只要统计量按帧独立算） | 否 | T 轴可切；**注意别写成整批统计** |
| `Conv2d` 3×3（无 dilation） | 否 | **是**（halo = 1 像素/层） | T 轴可切；H/W 需 halo |
| 最近邻 `Upsample` / `pixel_shuffle` | 否 | 否（逐点复制/重排） | 任意轴可切 |
| 时间上采样（`TGrow` / 1×1 conv 展开到时间轴） | **否**（逐帧映射，只改变帧数） | 否 | T 轴可切，但**切分点须落在该级帧边界** |
| 因果记忆块 `MemBlock(x, past)`，`past` = 上一帧在该块**输入**的激活 | **是（1 帧深度，但逐层递推 ⇒ 依赖整段前缀）** | 否（其内部仍是空间卷积） | T 轴**不可**直接切；需状态携带（见 `sliced-state-decode.md`） |
| 3D 卷积（时间核 > 1） | 是 | 是 | T 轴需 halo（halo = 时间核半径）；不可无 halo 切 |
| 时间注意力 / 因果注意力 | 是（全局或半全局） | 否 | T 轴不可切（除非重放前缀） |
| 跨帧统计（整段 percentile / 全局 mean） | **是** | 否 | T 轴不可切；改成逐帧统计才可切 |

## 2. 案例 A：逐帧 2-D 预览网（可精确帧轴切分）

网络（Kijai MiniMax-H3 TAE，`vae_approx/taeh3.safetensors`，2,446,179 参数，`layout=tae-2d`）：

```python
_Clamp (逐元素)  ->  Conv2d 3x3 堆叠（空间 halo，不跨帧）  ->  nn.Upsample(nearest)（逐点复制）
  ->  _to_unit_range: torch.quantile(x.flatten(1), dim=1)   # 逐帧一对分位数 ⇒ 不跨帧
  ->  repeat_interleave(time_upscale, dim=1)                # 逐帧复制
```

逐算子结论：**没有任何算子跨帧** ⇒ 按 `chunk_latents` 对齐切时间轴，**精确且无需 halo**（每个 chunk 的输出帧就是一段连续输出帧，拼接顺序与单卡循环一致）。

同环境实测（15 s / 768P，8 卡 USP8；**绝对值按数字纪律出库**，见 `{run_results_dir}/archive/`）：

| 项 | 结果 |
|---|---|
| 产物一致性 | **12/12 请求 md5 与基线逐字节一致** |
| `video_tae` | 耗时降到约四分之一 |
| `decode` 阶段 | 同量级下降（该阶段降幅几乎全部来自 `video_tae`，转移率约九成） |
| 代价 | 单卡额外占用数 GB 量级 HBM |

## 3. 案例 B：时间维 taehv（帧轴不可精确切分 —— 关键否证）

网络（官方 MiniMax-H3 TAE，`h3-tae-official/taeh3.safetensors`，9,868,236 参数，`layout=taehv-temporal`）：

```python
_Clamp -> conv(latent,256) -> act
  -> MemBlock*3 -> Upsample(2x) -> TGrow(1 or 2) -> conv -> ...
  -> _MemBlock.forward(x, past) = act(conv(cat([x, past], 1)) + skip(x))
```

`_MemBlock` 的 `past` 是**上一帧在该块输入处的激活**（首帧为 0）。它逐层传递：块 i 在帧 t 的输入取决于块 i−1 在帧 t 的输出，而后者又用了块 i−1 在帧 t−1 的输入……**递归展开后，第 t 帧依赖整段前缀 t′ < t**。

⇒ **帧轴切分不可能精确**，除非每个 rank 重放整段前缀（等于没切）。

**必须写进结论的否证备注**：stock 实现里的

```text
chunk_latents = 5         # 每块 5 潜帧
frames_to_trim = 3        # 每块裁掉头部 3 帧
末尾丢 3 * time_upscale   # 再丢尾部 12 帧
```

是**边界伪影裁剪**（裁掉每个 chunk 边界处上下文不足的帧），**不是独立性证据**。看到 chunk 化就断言“天然可切”是本领域最常见的错。

另需澄清的一条同类误判：**“8 个 rank 各解一遍、结果指纹逐位相同”只说明当前是冗余计算，不说明可切**（不可切时你只能靠状态携带切，见下）。

## 4. 案例 C：递归网络的状态携带切分（可精确）

承接案例 B：既然只有 `MemBlock` 跨帧，就把它需要的**状态**显式搬过边界：

- `state[i]` = 上一段**末帧在 MemBlock i 输入处**的激活；
- 非递归层（conv / upsample / TGrow）逐帧独立 ⇒ 不需要状态；
- 首段用 zeros pad 复现整段语义；
- 切分点落在**潜帧边界**（`time_upscale=4` 时潜帧 j ↔ 输出帧 4j，每级时间上采样都是整数倍 ⇒ 潜帧边界在所有层都是帧边界）。

实测：CPU 上整段 vs 2 段 vs 4 段 **max|d| = 0**；NPU 上 2 段即与 CPU 逐桶一致。推导与骨架见 `sliced-state-decode.md`。

## 6. 快速自查清单

- [ ] 是否把**每个**算子都判过（含归一化、上采样、时间扩展、注意力）？
- [ ] 归一化统计量是**逐帧**还是整段？（整段 ⇒ T 轴不可切）
- [ ] 有无记忆块 / 3D 时间核 / 时间注意力？（有 ⇒ T 轴需状态或 halo）
- [ ] 切分点是否落在**最粗时间上采样级**的帧边界上？
- [ ] 结论里是否明确写了“chunk/trim 不是独立性”的否证（若适用）？
- [ ] 是否用“8 卡结果相同”**错误地**当成可切依据？

## 7. 维护与更新

- **触发（结构性，与版本无关）**：换网络就等于换判定表——§2 的 Kijai `vae_approx/taeh3.safetensors`（`layout=tae-2d`）与 §3 的官方 `h3-tae-official/taeh3.safetensors`（`layout=taehv-temporal`）结论相反；记忆块（`MemBlock(x, past)`）的位置与个数、§1 表里任一类算子（3D 卷积时间核 > 1、时间/因果注意力、整段 percentile 统计）被新增或替换时，§1 的逐算子判定必须重做。
- **触发（否证所依赖的实现）**：§3 的否证备注锚在 stock 实现的 `chunk_latents = 5 / frames_to_trim = 3 / 末尾丢 3 * time_upscale` 上；这些常数或 `_MemBlock.forward(x, past)` 的 `past` 语义一变，否证要按新实现重写（“chunk 化不是独立性证据”这条判据本身不变）。
- **触发（数字类）**：§2 的 12/12 md5 一致、§4 的 `max|d| = 0` 是来源环境（**坐标见会话产物归档**：机型 / 卡数 / 软件栈版本与输入档）下的一次观测——本文件可迁移的是 §1 判定表与 §5 的 proof 记录模板，**数字换环境即重测**。
- **复核方法**：拿目标网络的算子表重跑 §1 的逐算子判定，再用 `scripts/shard_equivalence_check.py --model-spec <module>:build --pieces 2 4` 对拍；不再得到 `max|d| = 0` ⇒ 结构或版本已变，先回 §1 重判依赖范围，再按 §5 重写 proof 记录。
