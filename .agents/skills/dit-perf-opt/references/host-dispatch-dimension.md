# DiT 步内 host / 下发维度（非融合手段）

> 归属：本文件属 `dit-perf-opt`。**DiT 步内**的 host/下发在优化域里曾是**无主之地**——
> `dit-perf-opt` 把"host 固定开销"推给 `host-opt`，而 `host-opt` 的范围只含**非 DiT、非解码段**
> （交付搬运 / 装载预热），两边都不接。本文件把这一维度收进 DiT 自己的性能优化。
>
> **与融合的分工**：把 N 个算子融成 1 个**也是**减少下发的手段，但那条路归 `fusion-scope-analyze`
> （定范围与收益）；**本文件只收非融合手段**。

---

## 0. 先出三笔账，再动手

**没有账就没有优化**——"下发慢"是一个必须被拆成三个可测量行的说法：

| 账 | 怎么量 | 为什么必须单列 |
|---|---|---|
| **发起账** | `launch` / `aclrtLaunchKernel*` 一类宿主 API 的**次数 × 每次成本** | 次数与单次成本是两个独立的杠杆（减次数 vs 减单次） |
| **阻塞账** | **host 阻塞型算子**的*同步时长*（**不是**算子自身耗时） | 它随队列深度变化，与设备工作**重叠**，把它当"host 计算量"会算错 |
| **空转账** | 步内 `Free`（设备空闲） | 下发的**真实后果**是设备停等；只看宿主时间是隔靴搔痒 |

**三笔账必须同报**，否则会得出错误优先级：宿主聚合时间是**多线程聚合口径**，其绝对值可超过步长本身
——不能当墙钟读；而同一窗口的 `Free` 明显下降，说明真正的收益是**消除设备空转**，不是"宿主变快"
（读数见会话产物归档 `{run_results_dir}/archive/`）。

## 1. 识别「host 阻塞型回读」——最隐蔽、也最容易被误读

**定义**：算子的**输出形状数据相关**时，宿主必须把结果或形状**回读**到主机才能继续 ⇒
在该算子处插入一次 `aclrtSynchronizeStream`，**把设备队列排空**。

**典型算子**：`torch.unique` / `nonzero` / 布尔掩码索引 / `.item()` / `.cpu()` / 任何"形状未知"的规约。
（注意：**同族的非动态算子不会**——`torch.sort` 形状静态，不阻塞。）

**判别法 ①（尺寸无关性）**：在**同一队列状态**下比较它对大小输入的耗时。
**队列排空是常数**，与输入规模无关：

```text
先把固定条数的异步算子（如若干 matmul）压进队列，紧接着：
  torch.unique( 大输入 ) ≈ torch.unique( 极小输入 )   <- 耗时同量级 ⇒ 尺寸无关 ⇒ 纯队列排空
  torch.sort  (同一队列之后)                         <- 明显更小   ⇒ 非动态兄弟，不阻塞
```

绝对读数与元素规模出库到 `{run_results_dir}/archive/`。

**判别法 ②（宿主切片包含 sync）**：在 profiler 的 host API 视图里，看该 API 的宿主切片是否
**完整包含**一条 `aclrtSynchronizeStream`。形态判据：该 API 的宿主切片**近乎全部**包含
`aclrtSynchronizeStream`（占比可用 profiler 现场读），且时长呈**双峰**——"队列已排空"的一峰为
**常数小值**、"队列很满"的一峰**显著更大**。

**处置顺序**（从便宜到贵）：

1. **上提**：若该量只依赖请求的静态几何（shape / span / 分块 / 块大小），把它**从每层/每 chunk 上提到每请求一次**并缓存；
2. **改静态形状**：用可静态推导的写法取代数据相关的规约；
3. **延后/异步**：把不阻塞后续工作的部分移出关键路径。

⚠️ **不得把阻塞时长计为 host 计算量**，也不得把它与设备耗时**相加**——两者重叠。
判决只认**空转账**与端到端同窗差。

## 2. 非融合的下发削减手段（本技能的正面手段）

| # | 手段 | 判据 / 实测形态 |
|---|---|---|
| **H1** | **减少算子个数**：合并多次小调用、去掉冗余 pass、把逐元素循环收进已有的核 | 报"发起次数计数下降"，不只报耗时 |
| **H2** | **减少 program 个数**（"更少更胖的 program"）：同一核改成 `grid=(1,H)`、每个 program 内部循环 | 本仓实测：**逐字节等价、耗时显著下降、有效带宽成量级级抬升**（比值与读数见 `{run_results_dir}/archive/`）。修法细节见 `../../operator-dev/`（per-program 固定成本拟合、preload vs unroll） |
| **H3** | **上提每层重复的 host 侧准备**（几何 / 掩码 / 索引 / 形状推导） | 上提每层重复的 host 侧准备 ⇒ 常可做到**逐字节**，且每步减少**三位数毫秒量级**（地板倍数见 `{run_results_dir}/archive/`）。**本组合观测，须本地重测** |
| **H4** | **用捕获 / 图机制摊掉下发固定成本** | 机制本体归 `../../aclgraph-dev/SKILL.md`，本技能只负责"该不该用它" |
| **H5** | **融合 kernel**（N 个算子 → 1 个） | **不属本技能** → `../../fusion-scope-analyze/SKILL.md` 定范围与收益 |

**选取顺序**：先 H3（最便宜、常逐字节）→ H2 → H1 → H4；H5 走另一条链。

## 3. 验收（三者同报，缺一不可）

1. **产物口径**：逐字节（或按 `../../accuracy-gate/SKILL.md` 说明为何允许变化）；
2. **发起次数计数下降**：`launch` / 目标算子的**调用次数**必须给出前后对照——**只报耗时不算证明**；
3. **设备空转下降**：按 `../../perf-gate/references/measurement-discipline.md` §10.3 的绑定性判据，
   *从某资源移走的工作必须变成该资源新增的空闲*。

> **硬规则：设备空转的减少 ≠ 设备计算的减少。**
> 本仓反例：某次改动把 `Free` 大幅压掉，而同一窗口 `Computing` 几乎不动——前者的降幅比后者
> **高一个数量级**。若只看 e2e，会误判成"计算被优化了"，进而在后续选点时高估同类手段
> （读数见会话产物归档 `{run_results_dir}/archive/`）。

---

## 4. 失效信号

- 宿主时间下降而**空转不变** ⇒ 收益是"宿主更闲"，不是请求更快，**不得入库**；
- 发起次数下降而**步长不变** ⇒ 该下发不在关键路径上（或被别的资源吸收），按 §10.3 复核；
- 把 profile 的**逐算子绝对耗时**当基线 ⇒ 见 `perf-gate` §7.4（同卡并发会整体抬高，绝对值不可跨运行引用）；
- 阻塞账与空转账**混算** ⇒ 结论作废，重做三笔账。

## 维护与更新

- **更新触发条件**：① 宿主 API / profiler 的字段名或覆盖范围变化（`launch` / `aclrtLaunchKernel*` /
  `aclrtSynchronizeStream` 一类的可观测性变化）；② 框架新增或移除"输出形状数据相关"的算子
  （判定法与 §1 的典型算子清单需同步）；③ `dit-perf-opt` 的优化维度树、或
  `../../perf-gate/references/measurement-discipline.md` §7.3/§7.4/§10.3 的口径变动；
  ④ 下发削减手段的归属变化（例如融合那条路改由别的技能承载）。
- **复核方法**：任取一个已知的 host 阻塞型算子，按 §1 的**尺寸无关性**判据各测一次
  （空队列 vs 满队列后）；若不再出现尺寸无关的常数耗时，说明该形态已改变或已被机制消除，
  本条对应内容应改写或删除。**不承载跨机预期值**：所有量级读数以当前环境实测为准。
