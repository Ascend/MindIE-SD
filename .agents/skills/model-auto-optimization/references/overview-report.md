# 模型自动优化总览报表（强制交付规范）

> 适用范围：**所有**进入 model-auto-optimization 的任务，闭环复验时必须输出本报表
> （`runs/YYYYMMDD_{model}_optimization/overview_report.md`），并连同 `evidence.json`、
> `final_report.md` 归档。目的是让一个模型的全部优化收益在**同一基线**上可比、可审、可复现。
> 配套细分报表（强制，紧随本报表，规范见 `references/detail-report.md`）：本报表=**合并口径**
> （特性行含其使能后融合收益，见 §2.4），细分报表=**构成口径**（融合算子逐项收益与剩余机会、
> 并行候选矩阵与带宽、稀疏/量化（FA=`量化(f8)`、线性层=`量化(w8a8)` 等分列）/cache 与
> 时间步优化、组合矩阵）。

## 1. 基线口径（全报表唯一基线 · 强制）

- **基线 = 目标框架「TP×N 多卡」配置、未叠加任何优化**的**单个完整推理请求**的运行：
  特性层面无 `并行调整`/`kernel融合`/`Cache`/`量化`/`稀疏`/`时间步优化`，实现层面亦无
  编译/offload/通信调度等实现方法；**并行仅保留框架默认 TP 拓扑**（TP×N；框架无 TP 能力时
  才退同拓扑——USP/SP 或单卡——并在「说明」列显式标注「基线=同拓扑未优化（无 TP）」）。
- **e2e 计时口径（主口径）= 单个完整推理请求墙钟（s/请求）**：Run DiT 全程（denoise 首步到末步，
  含 VAE/其他耗时）；**排除 model_load / compile_prime / warmup**；同窗口同卡组 ≥2 复现取中位。
  **实测 vs 估算（强制分层）**：
  - **必须实测 e2e 的行**：`基线（base）`行、**最终推荐方案行**（采纳/部署配置）与
    **三元组合行**（`Cache + 量化(修饰符) + 稀疏` 最强组合，§2.2/§2.3）——三行是报表结论的
    锚点，**不允许估算**；
  - **允许估算 e2e 的行**（中间叠加/单点筛选行，标注 `[估算]`）：估算公式见 §1.1。
- **首步耗时（辅助口径，s/step）= warmup 后第一个 step 的墙钟**：每行尽可能实测（少步即可采，
  见 §1.1）；它步数无关、跨 run 可比，两个用途——① 少步性能识别与同口径对比；② 中间行 e2e
  估算的输入（§1.1 公式）。
- 报表内**所有加速比 = `基线 e2e / 本行 e2e`**（实测行用实测 e2e，估算行用估算 e2e 并在
  说明列注明 `[估算]`），一律相对该基线，禁止混用其他分母；基线行步数 = 官方默认步数。
- 基线行本身在报表中以第一行列出（优化类型=基线，特性名=TP×N 未优化，e2e=基线完整请求墙钟
  （实测），首步耗时=基线首步，加速比=1.00×，质量数据=—，说明=官方默认步数/拓扑/可复现指针）。

### 1.1 步数口径：少步识别 / e2e 估算（性能识别用少步，锚点行实测 · 强制）

- **性能收益识别可以用很少的步数（如 1 步）**：无损优化（S1/S3 类）与「不做质量分析」的有损
  性能分析过程（性能选型扫描、kernel diff、off/on AB）在少步下识别收益——单步即代表算子形态与
  kernel 序，取 **warmup 后第一个 step 耗时**（首步耗时）做同口径对比（同为少步、同窗口同卡组），
  百分比才可比有说服力（profiling-collect「少步快速采集经验」：1 预热 + 1 采集）。
- **中间行 e2e 估算公式（[估算]，DiT 比例法 + VAE/其他）**：中间叠加/单点筛选行的完整请求墙钟
  不必全量实测，用 base 实测拆分估算：

  ```text
  行 e2e[估算] = base DiT 耗时 × (行首步耗时 / base 首步耗时) + (VAE + 其他固定耗时)
  ```

  其中：`base DiT 耗时` 与 `VAE+其他` = base 行实测 e2e 的拆分（profiling step_trace 的
  DiT/VAE 占比，或 base 少步/全量差分解出）；公式假设行与 base 的 **DiT 单步耗时同比例缩放、
  VAE/其他（编码器、VAE tile、启动/交接固定开销）基本不变**。**行步数与 base 不同时**（如
  时间步优化 24 步 vs 60 步）估算不可靠——须实测或按步数比另注明，禁止直接套公式。
- **锚点行必须实测（禁止估算）**：`基线` 行、`最终推荐方案` 行、`三元组合` 行（含中间叠加链的
  终点最强组合）与 **cache/稀疏/量化发生回退后的最终档/边界档行**（回退档是潜在采纳配置，必须
  全量步数实测 e2e 识别性能加速，禁止用少步/估算宣称回退后性能，见 combination-search「层回退
  策略」）——必须**全量步数实测 e2e**；少步只用于识别/筛选哪条路值得投全量，**不下最终结论**。
  质量列要填门禁结论的行同样必须全量实测（质量与 e2e 同次运行）。
- **步数列用法**：记录该行实际运行的 denoise step（锚点/全量行=官方默认或最终步数；识别行=
  少步数并注明「识别步数」）。完整请求墙钟随步数非线性（固定开销 + VAE tile + 热效应），
  不按步数等比例换算。

## 2.1 特性名词汇与命名规则（强制）

- **特性名只允许「固定名词」组合，禁止自定义名称**（内部代号/产品词/档位形容词/实现方法——如
  `frontier`、`hq`、`mix(EagleQBSA)`、`kernel 融合(FA/mindiesd)`、`稀疏 mix+量化(INT8)`、
  `编译`、`Offload`、`通信优化` 等一律不得作特性名；此类内容属特性下的**实现方法/选项/辅助**，
  放「说明」列或归入所属特性行说明）。
- 固定名词表（白名单；行组归属见 §3）：
  - 无损：`并行`、`kernel融合`
    （`kernel融合` 为**单一固定特性名**：其下全部融合内容（RMSNorm/RoPE/AdaLN/GELU/FFN 融合
    kernel/Copy 消减…）与实现方法（`编译` = pattern/Inductor/GraphPatternEntry；`直接算子 API
    接入` = eager 单算子/运行时注册表替换）**一律入「说明」列或细分报表 A.1，不得派生独立
    特性名**——禁止 `kernel 融合(FA/mindiesd)`、`编译`、融合算子名等作特性名；`Offload` =
    显存优化、`并行` 的辅助特性；a2a/通信调度类 = `并行` 相关的通信优化——均入「说明」列，
    不作独立特性名）
  - 免训练有损：`Cache`、`量化({修饰符})`、`稀疏`、`时间步优化`
    （`Cache` = 固定特性名：实现**优先用框架自带能力**（如 vLLM-Omni 的 cache_dit /
    DiTBlockCache），框架未接线时经 mindiesd `cache_agent` 接入；框架能力名/外部同名实现只作
    「说明」列内容，**不得作特性名**。`量化({修饰符})`：`量化` 为单一固定特性名，修饰符 =
    能力内容组合（w8a8 / f8 / w4a4 / w8a8f8 等，可多选组合），不是子特性。）
  - 训练感知：`少步蒸馏`、`可训练稀疏`、`QAT`
- 步数类名词区分（按是否换权重归组）：仅推理侧裁剪/跳步（不换权重）= `时间步优化`
  （免训练有损组）；用蒸馏/少步模型权重 = `少步蒸馏`（训练感知组）——不混用。
- 量化修饰符白名单（括号内，标准词）：
  - `w8a8` = 线性层 weight/activation 8bit（实现即 MXFP8 e4m3）；`f8` = FA/注意力侧 8bit
    （统称；实现按路径：mindiesd docs 特性 `FP8RotateQuantFA`（quantize 自动注入）/ 框架案例
    EagleQBSA（Q/K INT8 + V per-channel FP8，覆盖稀疏块路径）——报表说明列必须写明实际路径）；
    两维度同时使能写作 `量化(w8a8f8)`；`w4a4` = 线性层 w4a4；未使能维度**不写入**。
  - 该行的**实际实现/数据类型与量化范围必须在「说明」列写明**（如 线性层 MXFP8 e4m3 online
    dynamic（scheme `npu-w8a8-mxfp8`）、FA EagleQBSA 覆盖路径——全部注意力或仅稀疏块路径——
    及其余路径精度）。
- **选项/参数一律入「说明」列（不得进特性名）**：稀疏度数值与 precision（如 rf_v2
  sparsity=0.8 bf16/mix）、cache 类型/阈值档、拓扑与 rank（TP/USP/ring 数）、kernel 后端/
  算子名、offload 方式、编译范围、步数等。
- 叠加组合顺序固定：无损 = `并行 + kernel融合`；含 cache = `Cache + 量化({修饰符}) + 稀疏`
  （cache 前导）；无 cache = `量化({修饰符}) + 稀疏`；`时间步优化` 为步级横切项，与任一行
  叠加时随行注明步数档，不改变上述名词顺序。
- 同一特性名在总览表**只允许一行**：同名词存在多候选时，采纳档入主表，其余候选入 §5 子表
  并在子表注明选项差异——主表 + 子表共同呈现「候选 → 验证 → 选定」链。
- 涉及稀疏的行，说明列必须写明稀疏度（sparsity 数值/%）；涉及量化的行，说明列必须写明
  数据类型与范围（见上）；试验记录/子表分类命名一律 `算子(稀疏度xx%)` 式（如 rf_v2(80%)），
  量化行带规格标注（w8a8(mxfp8) 式）。

## 2.2 免训练有损强制对照组（强制）

- 每个任务的免训练有损组必须输出**最强组合对照行**，名词固定为 `Cache + 量化(w8a8f8) + 稀疏`
  ——语义 = Cache + 线性层 w8a8 + 注意力 f8 + 稀疏（稀疏度取本模型扫描最强档，数值入说明），
  **e2e 必须实测**（三元锚点行，禁止估算），给出 e2e（实测）/ 首步耗时 / 加速比 / 质量数据；
   并与单维度最强档行（如 `Cache + 量化(w8a8) + 稀疏`）同表对照；
  **量化参与组合一律以 w8a8f8 为代表档**（组合试验在此档与其他特性叠加，选最高性能组合）；
  **Cache 与时间步优化在组合中二选一**（对照行选其一进入，时间步不与此行并存）。
- 若某维度框架不支持（如全注意力 FA 8bit 未实现）：
  1) 该维度**不写入名词**（名词只表达实际使能维度，避免名义组合 ≠ 实测数据）；
  2) 该行说明列显式标注「f8 未使能（原因；❓/待核验，见 framework-support-matrix）」；
  3) §5 相应子表保留名义行 `Cache + 量化(w8a8f8) + 稀疏` 并标 ❓ 与原因——
     **禁止虚列未实际测量组合的数据，禁止静默替换维度**。

## 2.3 单点行、叠加行与叠加链（强制 · 主表无空缺）

- 免训练有损组的**每个特性**，总览表必须同时具备「**单点行**」（该特性最强档单独使能、其余有损
  特性关闭；名词即特性本身，如 `Cache` / `量化(w8a8)` / `稀疏`）与「**叠加行**」：单点行用于归因
  该特性的独立收益与质量，叠加行用于协同收益。**缺失单点行的组合表视为不完整**（首个案例：报表
  曾缺「单独 Cache」单点被审阅发现 → 补测；补测后与另一工作负载的单点收益交叉印证）。
- **叠加链（主表内逐行呈现，强制）**：从基线行开始，按「无损 → 免训练有损单点/时间步优化 →
  逐步叠加 → 最强组合」顺序给出一组**实测/估算叠加行**（每行 = 上一行 + 一个新特性，e2e =
  实测或 `[估算]`，加速比 = 相对 §1 基线单值；首步耗时列给该行单值）。禁止只列单点、跳过中间
  叠加、或用子表推导值充当主表叠加行；**最强组合行（最终推荐）= 实际部署/采纳配置，必须实测
  e2e 入主表**（三元组合行亦必须实测，§2.2）。
  **叠加链的锚点行（基线/最终最强组合/三元）必须全量步数实测 e2e**；中间叠加行允许用 §1.1
  公式估算 e2e 并标 `[估算]`——少步/估算只用于铺中间链，结论锚点不估算。
- **主表每一行都必须有 e2e 单值（实测或 `[估算]`）、首步耗时、步数单值与相对基线加速比单值**
  （含时间步优化、稀疏、叠加链各行）；未测/无匹配基线的档位**不进主表**，进 §5 子表并标 ❓ 与
  补测计划。
- **组合覆盖行（S4-2 必测 · 防静默缺行）**：当 `量化`/`稀疏`/`Cache` ≥2 个维度有单点 frontier
  时，主表叠加链必须覆盖全部跨 seam 两两行（量化×稀疏 / 稀疏×Cache / 量化×Cache）与
  **三元行 `Cache + 量化(修饰符) + 稀疏`（强制实测 e2e，禁止估算）**——最强组合行即由此三元
  （或层回退后的边界档，**回退档同样必须全量实测 e2e**，见 §1.1 与 combination-search「层回退
  策略」）产生；仅测两两、缺三元，或三元未测却宣称"最强组合"，视为组合覆盖缺口
  （审阅发现即打回补测/豁免登记，豁免须带原因与证据，见 combination-search.md「必测组合覆盖集」）。
- 同一特性在不同工作负载（分辨率/步数）下的单点收益应**交叉印证并记录**（如 DiT-Cache 单点在
  576p@60 与 768P@50 均 ≈ -67%），避免单点结论只依赖单一负载。

## 2.4 使能后融合的归属与展示（两级口径，强制）

- **归属**：融合本身属无损优化族；但「**由有损特性使能、仅在该特性使能后的 kernel 序列下有效/可实施**」
  的融合（最典型：量化后序列的融合——量化 GEMM 与上游 norm/SwiGlu 的 epilogue、A 侧动态量化并入
  GEMM、compile 按量化序列重测等；稀疏/缓存同理），在总览表中**归入使能特性行**：紧接该有损特性
  （如 `量化(w8a8)`）之后，作为该特性自身的组成收益，**不单列无损行**——其收益不可脱离使能序列
  独立获得，归因绑定序列。此归属**不改变特性名体系**：这类融合的**内容**仍是 `kernel融合` 特性的
  融合内容（实现方法 compile/API 接入、执行序收益判定与「识别但不执行（整 block <0.5%）」记录
  在细分 A.1.1/A.1.3 与迭代表，见 detail-report §A.1），只是**收益归因**写入使能特性行。
- **两级展示**：
  - 总览表行 = 「特性 + 其使能后融合」的**合并收益**（e2e（实测或 `[估算]`）/首步耗时/加速比/质量）；
  - 打开该特性的 §5 内部组合搜索子表时，才拆分展示「特性基准档 vs 基准档 + 使能后融合」的增量与
    证据（候选 → 验证 → 采纳/回退；融合本身属无损的标注写在该行说明）；
  - 未实施的使能后融合候选标 ❓（如 H3 w8a8 机会 O1–O7 未落地项），**不得计入当前行收益**。
- 框架原生 / 独立于有损特性的无损融合（FA、并行、DLO 解锁等）仍入无损组（§3a），不受本条影响。
- 计数/声明：行加速比分母仍为全报表基线（§1）；子表拆分须单变量证据（同窗口 特性基准 vs +融合）。

## 2.5 特性可用性标注（强制：区分「框架未提供」与「未做/未核验」）

- 行组清单 / 对照组 / 子表 / 细分报表中出现的每个特性或组合，若**目标框架未提供（不支持）**，
  必须**明确标注「框架未提供（不支持）」并给证据或引用**（support-matrix、运行期错误如
  ring 不支持 attn_mask→500、NPU FA 8bit 无实现路径等），**不得以笼统 ❓ 掩盖**——❓ 只用于
  「框架提供但本任务未核验」，两者语义不同，混用会让审阅者把「框架能力缺口」误当「待办实验」。
- 三态术语（报表内统一）：
  - `✅` = 框架提供且本任务已验证；
  - `框架未提供（不支持）` = 框架/该形态无此能力，写清证据与引用；
  - `❓` = 框架提供但本任务未核验，写清待核验点（P 级）；
  - 另有「回退」= 框架提供但实测为负（写证据），与本三态正交。
- 真源：`framework-feature-enablement/references/framework-support-matrix.md`（特性命名以
  docs/zh/features 为准）；报表标注须与矩阵一致，不一致时先改矩阵（含 last-checked）。
- 示例（H3 × vLLM-Omni 0.28）：全注意力 FA 8bit / CFG(NPU/H3 路径) / ring 形态 = **框架未提供**；
  量化后融合 O1–O4、TP4@60、稀疏 0.9+ 档 = **❓（框架提供未核验）**；few-step/Turbo/FastH3 =
  本任务未启用（决策），另列。
- **与 framework-support-matrix 图例互译（避免误读）**：报表「框架未提供（不支持）」≈ 矩阵 `❌`；
  报表「回退」（框架提供但实测为负）≈ 矩阵 `🟡` 负面档或实测为负；报表 `❓`（框架提供未核验）=
  矩阵 `❓` 同义；矩阵 `🟡` 的其余含义（可配置但有限制/默认关）在报表落入该行「说明」列标注。

## 3. 三层级加速手段清单（行组）

- **a. 无损优化**：`kernel融合`（实现方法 = pattern/编译 或 直接算子 API 接入）、`并行` 策略
  （USP/CP/TP 调整、拓扑选型；**Offload = 显存优化，属 `并行` 的辅助特性**；a2a/通信调度类
  属 `并行` 相关的通信优化——均作实现/辅助入说明列，不单列特性名）；由有损特性使能/仅在其
  序列下有效的融合 **按 §2.4 归入使能特性行**（如 `量化(w8a8)` 后的融合），不在此组单列。
- **b. 免训练有损优化**：`Cache`（DiTCache/AttentionCache…，注明类型档）、`时间步优化`
  （docs cache 章，步级，注明步数档）、`稀疏`（rf_v2/ada_bsa 等，注明 sparsity
  档）、`量化`——**区分 FA 量化与线性层量化**：FA = `量化(f8)`（实现选 EagleQBSA：Q/K INT8 +
  V per-channel FP8）；线性层 = `量化(w8a8)`（实现即 MXFP8 e4m3）或 `量化(w4a4)` 等（修饰符按
  §2.1 白名单）。
- **c. 训练感知优化（可选，S5 预留）**：少步蒸馏（4/8 步蒸馏权重：框架支持则下载尝试，
  推荐 modelscope；框架不支持则略），可进一步叠加**可训练稀疏**与 **QAT**；
  未做该层时整组可省略或标「本任务未启用」。
- **其他**：预期之外的手段/组合（如非上述层级的实验性收益、多卡资源相关说明）列此，写明原因。

## 4. 质量数据列口径

- 无损行：输出一致性口径（逐字节一致 / 与 baseline 数值差异），写「输出一致（逐字节）」或按
  S1–S3 验收口径。
- 免训练有损 / 训练感知行：用质量门禁结论与数值——PSNR/SSIM（或 LPIPS）对比基线帧 +
  视觉判卷（pass/fail/inconclusive）+ off-identity 结论；指标与阈值引用 `runs/{task_id}/profiles/{model}.toml`（gen_profile.py 生成不入库）
  与 `quality-gate.md`（未校准/无 VLM 的按该文件规则写 inconclusive + 并排存证）。
- 训练感知行额外给「相对全步数/原始模型」的质量基线说明（少步蒸馏本身即质量-速度权衡）。
- 所有有损/组合行的质量列一律 = **vs 同构 lossless 基线的绝对口径**（PSNR/SSIM 等）；「有损 × 并行」
  等两有损档间的交叉对比（如同档 USP2 vs USP4）只作次级参考注释放「说明」列，**不得替代绝对口径**
  作对外数值（首个案例：曾以 vs USP2-int8 交叉 20.8/0.750 展示 USP4 档，已改为 vs lossless 绝对值 19.43/0.692）。
- 补测/回填优先盘点存量产物：已跑档的远端 mp4/帧仍在时，可抽帧（select every Nth 帧）+ quality_compare
  后处理补算质量，不必重跑占卡；确需新跑才占用卡资源。
- **每运行标杆质量信息（强制，随报表逐行登记）**：主表每个有损/叠加行的质量列 = 与
  `runs/{task_id}/profiles/{model}.toml`（gen_profile.py 生成）冻结 baseline 的**同 seed 标杆对照**（按 profile `[domain]`
  套取样协议：视频 21 采样帧 / 图像 21-seed 像素对）；数值由 `evals/scripts/quality_compare.py`
  对 `runs/` 冻结产物**现算**（不入 git），报表与细分 detail-report §E **逐行登记证据引用**
  （runs/{id}/quality.json + 帧或 profile 指针 + visual/off-identity 结论）；缺对照基线或未跑
  门禁的行只登记不得写 pass——质量证据缺失视为交付缺失（细则见 detail-report §E 与
  仓库 `evals/profiles/README.md`「数值不入库」约定）。

## 5. 分特性内部组合搜索数据（总览表下方）

每个「特性名」行下方，附该特性**内部组合搜索**数据子表（消费既有单点产物的结论，不重复维护细节；
主表行名遵守 §2.1，子表「子组合/参数档」列承载选项差异）：

```text
## {特性名} 内部组合搜索
| # | 子组合/参数档 | 步数 | e2e(实测或[估算]) | 首步耗时 | 加速比(相对基线) | 质量 | 证据与采纳/回退 |
```

- 子表每行登记**实测步数**与 **e2e（实测或 `[估算]`）**：性能选型扫描行可为少步（如 `1`，
  注明「识别步数」），质量/采纳候选行为全量步数（如 `60`）；中间行 e2e 可 `[估算]`（§1.1），
  最终采纳候选行 e2e 必须实测；同列对比限同步数档。

- **无损**：kernel 融合按候选逐项（pattern 名/eager 接入项）；并行策略按候选矩阵
  （含 offload 解锁前后、few-step + 多 rank 证据，固定 rank 口径）。
- **免训练有损**：cache 阈值扫描档、稀疏度-性能曲线档（引用 mindie_bench 扫描）、量化档
  （FA 量化 vs 线性层 PTQ 分开列）；多特性组合的 seam 判定与叠加顺序引用
  `combination-search.md` 的候选登记表与层回退名单；**特性使能后融合的拆分**（特性基准档 vs
  基准档 + 使能后融合）按 §2.4 在此子表展示（如 `量化(w8a8)` 子表含「量化基准 → +量化后融合」行）。
- **训练感知**：少步档位、QAT/可训练稀疏的试验记录（若做）。
- 每个子表须带：三层证据/计数契约结论、采纳或回退原因、回退名单链接；❓/未做明确标注。

## 7. 单元格纪律（表格内容确定性 · 强制）

总览表每一列都必须是**确定类型**的内容，禁止在单元格内夹带未定义的词或注释；口径/说明只允许
出现在固定的「说明」列与表外章节（§1/§4 口径与声明）：

- **「优化类型」列**：只允许枚举值之一——`基线`（仅首行基线行可用）、`无损优化`、
  `免训练有损优化`、`训练感知优化`、`其他`。禁止出现「…（参考行）」「…（名义对照）」「未纳入…
  」等附加词；行的参考/名义/未纳入等状态一律写进该行「说明」列。
- **「特性名」列**：只允许 §2.1 固定名词白名单（及组合「+」串联），如 `时间步优化`
  （docs cache 章）。**禁止括号、配置值、状态词、引用**（如
  `(infer_steps 30→24)`、`（参考行）`、`（未纳入部署）`）——参数/档位/状态一律移入「说明」列。
  组合行名词相同者只保留一行（选项进 §5 子表）。
- **「e2e 耗时」「首步耗时」「步数」「加速比」「质量数据」列**：e2e 单位 s/完整请求（实测或 `[估算]`）、
  首步耗时单位 s/step（warmup 后第 1 步）、加速比 × 数值、步数 = 该行实测 denoise step 整数——
  **均只填数值**或按 §2.3/§1 规定的占位。**主表特性行（含时间步优化、稀疏、叠加行）的 e2e、
  首步耗时、步数与加速比必须给单值**——`—` 只允许出现在：基线行质量数据列、质量数据列（无门禁
  时写「—」+说明）、以及 §2.2 未使能声明表/§5 子表（未测档）；**禁止把「参考行」「未测」当主表
  占位**。禁止任何注释/括号/区间文本（如 `（~135s 热尾）`、`3.354 / 3.131`、`Run DiT 参考`）；
  区间/参考/分母不同等全部进「说明」列。
- **实测 / 估算分层（§1/§1.1）**：e2e 单元格只允许两种——实测数值，或估算数值带 `[估算]` 标注
  （中间叠加/单点行；锚点行=基线/最终推荐/三元组合**禁止估算**，必须实测）。估算行的加速比基于
  估算 e2e 计算，说明列写明公式输入（base DiT/VAE 拆分 + 行首步耗时）。
- **跨步数/分母不同的行**：主口径 e2e 随步数非线性（固定开销 + VAE tile + 热效应），**不同步数
  行不按 e2e 等比例换算/直接互比**——同口径对比用「首步耗时」（辅助列，步数无关）；完整请求 e2e
  只与同 base 步数的行直接比，或经 §1.1 估算（同步数前提）。分母不同的跨窗口/构成口径只在
  「说明」列写明，加速比列仍给相对 §1 基线的单值（见 §4 声明，禁止混用多分母数值直接入列）。
- **质量数据列**：无损行填 `输出一致`（可加 `（逐字节/数值一致，见细分）`）→ 仅状态词+可选括注；
  有损行填质量门禁数值（如 `SSIM 0.972`），结论/锚点（vs 谁、帧数、视觉 inconclusive）进「说明」。
  质量行必须实测 e2e（质量与 e2e 同次运行），禁止估算。
- **口径行首**：允许在表上方以独立图例行/脚注声明列口径与单位（不属于单元格内容）。

### 7.1 字段取值类型（枚举 vs 任意写 · 强制）

总览主表与 §5 子表的每个字段都属以下三种之一——**枚举**（值域固定，只能取列出的值）、
**数值**（任意写数字，受单位/精度约束）、**自由文本**（任意写，受"必须含哪些"约束）：

| 字段（位置） | 类型 | 值域 / 约束 |
|---|---|---|
| 优化类型（主表列 1） | **枚举** | `基线` / `无损优化` / `免训练有损优化` / `训练感知优化` / `其他` |
| 特性名（主表列 2） | **枚举（白名单组合）** | §2.1 固定名词表 + `+` 串联；量化修饰符白名单；禁止自定义名/实现名/括号/状态词 |
| e2e 耗时（主表列 3） | **数值（实测）或数值+`[估算]`** | s/完整请求；锚点行（基线/最终推荐/三元组合）必须实测，中间行可 `[估算]`（§1.1） |
| 首步耗时（主表列 4） | **数值** | s/step（warmup 后第 1 步），2–3 位小数，单值；无法实测标 ❓ |
| 步数（主表列 5） | **数值** | 正整数，该行实测 denoise step |
| 加速比（主表列 6） | **数值** | `基线 e2e/本行 e2e`（估算行基于估算 e2e），2–3 位 + `×` |
| 质量数据（主表列 7） | 无损：**枚举**；有损：**数值** | 无损=`输出一致`（+可选 `（逐字节/数值一致，见细分）`）；有损=门禁数值（如 `SSIM 0.972`），pass/fail 结论进说明 |
| 说明（主表列 8） | **自由文本** | 必含：使能子特性/开关（量化规格、稀疏度、cache 档、拓扑 rank、offload/compile 方式）、e2e 实测或 `[估算]`（估算行注明公式输入）、可复现命令/配置指针；可含：eager/compile 形态、分母说明、状态（参考/未纳入） |
| 子组合/参数档（§5 子表） | **自由文本** | 档位差异（稀疏度、cache 阈值、量化档链…），遵守 §2.1 命名 |
| 步数（§5 子表） | **数值** | 正整数；识别行注 `1（识别步数）`，质量/采纳行全量 |
| e2e / 首步耗时 / 加速比（§5 子表） | **数值** | e2e 同上实测/`[估算]` 分层；首步耗时 s/step；加速比相对 §1 基线 |
| 质量（§5 子表） | **枚举/数值** | 同主表质量列；未测标 `❓` |
| 证据与采纳/回退（§5 子表） | **自由文本** | 三层证据/计数契约结论、采纳或回退原因、回退名单链接 |

> 判别口诀：**枚举**=选一个值（错了可校验）；**数值**=填数字（有单位/范围约束，估算值带
> `[估算]`）；**自由文本**=说明性内容（必含项固定，其余任意但不得夹带枚举/数值列的语义）。

审阅示例（禁止——估算/实测不分、多分母、区间塞数值列）：
`| 免训练有损优化（参考行…） | 稀疏（rf_v3，eager） | sp0.5 bf16 3.354 / mix 3.131（eager-dense 4.074） | 60 | … | SSIM 0.960 | … |`
应写为（锚点行 e2e 实测单值；中间行估算标 `[估算]`；首步耗时辅助；口径入说明）：
`| 免训练有损优化 | 稀疏 | 89.4（实测） | 1.49 | 60 | 1.47× | SSIM 0.960 | 档位 sp0.5/bf16，eager 形态；e2e=60 步完整请求墙钟（实测），首步=warmup 后第 1 步（1.49 s/step），分母=§1 基线（60 步，e2e 实测 131.2s）；compile×rf3 待解（未纳入部署）；见细分 B.1/§4 |`
`| 免训练有损优化 | Cache | 36.4[估算] | 0.62 | 60 | 3.6×[估算] | SSIM 0.72 | 单点档；e2e[估算]=base DiT(125.4s)×(0.62/2.19)+VAE+其他(5.8s)；最终三元组合行实测，见下 |`

时间步优化行合规示例（锚点/推荐行必须实测 e2e）：

```text
| 免训练有损优化 | 时间步优化 | 93.2（实测） | 1.55 | 24 | 1.41× | SSIM 0.937 | docs cache 章「时间步优化」；步级 infer_steps 30→24（官方默认 30 → 采纳 24）；e2e=24 步完整请求墙钟（实测），首步=warmup 后第 1 步（1.55 s/step），分母=§1 基线（官方默认 30 步，e2e 实测 131.2s）；20 步激进备选见细分 B.3 |
```
