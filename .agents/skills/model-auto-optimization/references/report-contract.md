# 报表契约与数字复核（编排层 L1 单点）

本文件回答：**性能结论怎么写进总览表，以及怎么机械地复核别人写的数字。**

> **归属**：报表**列契约**的单点在编排层（本目录，与 `scripts/report_lint.py`、

## 1. 主表：8 列固定契约

```text
优化类型 | 特性名 | e2e 耗时 | 首步耗时 | 步数 | 加速比 | 质量数据 | 说明
```

- **列顺序不可换**（渲染与 lint 都依赖它）；列名可用"（s）"等括注，但语义不变。
- **优化类型**取枚举：基线 / 无损优化 / 免训练有损优化 / 训练感知优化 / 其他。
  基线行是唯一分母锚点；`其他` 用于不可归类的参考项。
- **每行必填单值**：e2e、首步、步数、加速比都要给单值（不允许 `—` 或区间；
  区间只能写在"说明"里）。锚点行（基线、三元组合、最终推荐）的 e2e 必须实测，禁止估算；
  中间行可估算但必须标 `[估算]`；**只有性能验收标准的验收态结果才可入主表**
  （探索态/少步识别读数标 `[探索]`，留在过程材料里，不进主表）。
- **加速比 = 基线 e2e ÷ 本行 e2e**，分母只允许是同一张表的基线行。若表里混了两个世代的
  血缘，加速比列必须用统一分母，并在说明里注明该行属于哪个世代——同一物理配置在两个血缘表里
  会得到两个都"对"但**不可混读**的加速比（踩过：同一配置在两个世代里一个看着是两位数倍、
  另一个看着是 1.00×，差别全在分母）；跨世代混读必错。

## 2. 可选 `序号` 列（用户常要求加）

在第一列前插入 `序号`（1,2,3…）。两个必须注意的点：

1. **分隔行列数必须与表头一致**。插入列时要同步重算分隔行；用 `str.replace` 拼接时极易漏掉一个竖线，
   结果是"表头 9 列、分隔行 10 列"——严格 Markdown 渲染器会判定"这不是表格"，
   **整张表变成纯文本**（实测中真实事故）。
2. 校验工具如果按"固定 8 列"写死，需要让它**容忍一个可选的前置 `序号` 列**（其余 8 列顺序不变），
   否则 lint 会误报。

## 3. 质量列语义

| 优化类型 | 质量列应写 | 禁止 |
|---|---|---|
| 无损优化 | `输出一致`（可加括注：逐字节 / md5 前缀 / 张量 dump 一致） | 只写"看起来一样" |
| 免训练有损 / 训练感知 | 数值（相对基线的质量变化度，如 `SSIM 降约 0.2` / `PSNR 降约 4 dB`；或门禁数值指针）+ 结论 | 留空、只写"有损" |
| 基线 | 允许 `—` 或"基准锚点（自身即参照）" | 编一个比值 |
| 参考/未采纳 | 可写"未验证""未测得（原因）" | 与主表收益混淆 |

**一致性要求**：同表内同类行的质量列格式要一致（实测中把主表所有无损行统一为
`输出一致（逐字节：md5 前缀…）`，基线行统一为"基准锚点：md5 …、字节数…（自身即参照）"）。
用户明确要求过"与上面各行保持一致"——这是可执行的规则，不是风格偏好。

## 4. 主表 vs 参考表

- **主表只收"已验证有效"的收益**（即性能验收标准的**验收态**结果；探索态/少步识别读数一律不进主表）。
  未验证项、否决项、跨口径参考行**不进主表**——承载位置由编排层报表规范定义
  （`overview-report.md` §2.2 的未使能声明表 / §5 子表，以及细分报表的已否决假设表），
  并在该处写明"本小节不进入总览报表主表"。
- 参考项里若某行与主表行是同一次测量，**数值必须逐字段一致**（用脚本核对 e2e/首步/步数/加速比
  四列，避免"两处数字不同"）。
- 否决项也要写清楚"为什么否决 + 证据"，不要静默删除（后人会重复踩坑）。

## 5. 跨血缘 / 跨窗口标注

- 混世代的表要在表头下方写 **注**：哪些行来自哪个世代、哪些量不可直接互比。
- 同一行的"无损声明"若只对某个世代成立，要在该行说明里限定（例如"仅当某条件满足时逐字节精确"）。
- 跨窗口数字必须标"量级参考"；只在同窗口内比差值（口径见
  `../../perf-gate/references/window-ab-protocol.md`）。

## 6. 格式事故清单（都真实发生过）

| 事故 | 症状 | 处理 |
|---|---|---|
| 分隔行列数 ≠ 表头列数 | 整表在渲染器里"消失"，变成纯文本 | 重算分隔行；用脚本核对每张表的列数 |
| 行被插到空行之后 | 该行不属于任何表，渲染成孤立片段 | 用"表头 → 数据行连续"的规则校验 |
| 单元格里含未转义竖线 | 列数错乱（但转义竖线 `\|` 合法） | 审计脚本按**未转义**竖线切分 |
| 嵌套加粗（外层 `**` 对内嵌内层） | 渲染错乱 | 拆开写；**跨行成对是合法的**——判定要按段落/表行分块配对，勿逐行数 `**` 个数 |
| 表里混入百分比与倍数 | 审计工具误判 | 统一列语义；百分比与倍数分列或写明 |

## 7. lint 与审计脚本

- **lint**：`../scripts/report_lint.py`（编排层门禁工具，close 阶段由 `stage_gate.py` 强制调用）——
  主表必须 `error=0` 才算交付；它检查表头列序（含可选前置 `序号` 列）、必填单值、
  锚点行禁 `[估算]`、质量列语义等。**不要在文档里另写一份列规则**：改列/改语义时同步
  `overview-report.md` §2 与本文件。
- **结构与数值审计** = `../scripts/audit_report.py`（一次调用同时跑两类；`--only structure|numeric`
  可单跑；`--selftest` 跑负样本自测）。**close 阶段由 `stage_gate.py` 强制调用**（与 `report_lint.py`
  同级：非 0 ⇒ 不得宣称闭环，见 §8 步骤 6）；改表后也应即时跑一遍，`error=0` 才算完：
  - **结构**：逐表核对"表头列数 = 分隔行列数 = 每个数据行列数"，切分只用**未转义**竖线
    `(?<!\\)\|`；"表头 → 数据行连续"（空行之后的孤立表行报错）；加粗成对性——**跨行成对是合法的**
    （按段落 / 表行分块配对，逐行数 `**` 个数会把合法跨行加粗误报成"未闭合"）。
  - **数值**：有 e2e + 加速比 ⇒ 校验 `分母 ÷ e2e ≈ 加速比`（排除 `[估算]`/区间/`—`/`?` 行，并**逐条
    列出跳过原因**，避免审计覆盖面被误读）；有 diffuse + 每步 ⇒ `diffuse ÷ 每步` 是合理整数
    （只看是否整数，跨世代不误判）；有"实测 / 单点连乘 / 比值" ⇒ `实测 ÷ 连乘 ≈ 比值`；
    有"相对上一行"⇒ 先判百分比还是倍数，再校验参照行是"上一行"还是"第 0 行"（踩过：某行用错了
    参照行）；同一次测量出现在两张表且两表分母相同 ⇒ e2e/首步/步数/加速比须逐字段一致（§4）。
  - **分母判定（决定审计是真阳性还是假警报）**：加速比的分母是**报告级基线**（主表第一行「基线」
    的 e2e），**不是"表内那条叫基线的参考行"**——参考行自身也相对报告基线（例如 CP2USP4 参考行
    在同表内是 0.90×，不是 1.00×，把它当分母会把整表判成全错）。脚本按 `--baseline` > 报告基线 >
    本表基线行 的顺序拟合，并**始终打印所用分母**；表内基线行不是分母时会单独说明。
  - **单元格数值判读**：剥掉加粗 / 反引号 / `≈` 前缀后必须以数字开头。`**34.32**（实测）` 这类
    加粗单元格若不剥标记会被判成"无数值"而**静默排除**在检查之外（真实盲区，由 `--selftest`
    抓到）；反之"见 §6"这类文字单元格必须排除，否则会被抽出 `6` 造成假阳性。
- 审计脚本要**幂等**、锚点缺失时**显式报错**（而不是静默跳过），否则改表后无法复现；
  `--selftest` 在真实报表上注入已知事故（分隔行列数错、孤立表行、加粗未闭合、加速比与分母不符、
  比值不符、相对上一行参照错、锚点被删）并断言"全部被抓到且逐次结论一致"，是"审计器本身有效"的复验手段。

## 8. 复核流程（拿到别人的加速比时）

1. 找分母：这张表的基线是哪一行、e2e 是多少？
2. 逐行重算 `基线 ÷ e2e`，与标注对比（容差按四舍五入）；
3. 检查质量列语义与一致性；
4. 检查跨世代/跨窗口标注是否存在；
5. 用同一套审计脚本跑一遍，把发现的问题列成"位置 / 原值 / 应为 / 依据"四列，逐条修正；
6. 修完跑 lint（`report_lint.py`）+ 结构审计 + 数值审计（两者都在 `audit_report.py`），
   三者都干净才算完。

## 维护与更新

- **单点纪律**：列定义在 `overview-report.md` §2（模板与示例行）与本文件（契约 + lint + 审计）
  **成对维护**；任何增删列/改列语义/改枚举/改占位符的改动必须同时改两处，并同步
  `detail-report.md` 与 `scripts/report_lint.py`。
- **本文件不做测量判定**：同窗 A/B、噪声地板、三证、双态（探索/验收）与"什么数字能入库"的判据在
  `../../perf-gate/SKILL.md`（性能验收标准）；本文件只规定"数字怎么写、怎么机械复核"。
- **失效信号**：报表模板、`report_lint.py` 的列校验规则、`stage_gate.py` 的 close 门禁三者任一变化 ⇒
  本文件相关条目必须同步复核（否则复核流程会对着旧规则给出假通过）。
