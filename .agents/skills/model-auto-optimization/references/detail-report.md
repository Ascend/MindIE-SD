# 模型优化细分报表（detail_report.md · 强制，紧随总览报表）

> 适用范围：所有进入 model-auto-optimization 的任务，闭环复验时必须随 `overview_report.md` 输出
> `runs/YYYYMMDD_{model}_optimization/detail_report.md`（总览给**合并口径**，细分给**构成口径**）。
> 沿用同一基线/命名/质量纪律（见 `overview-report.md` §1 / §2.1–§2.4 / §4）与声明纪律；
> 细分（构成口径）沿用 overview 的**同一唯一基线（TP×N 未优化的 e2e 完整请求墙钟，实测）**：
> 细分各子表允许按构成口径报 per-step avg / 首步耗时（辅助）/ 相对自身 dense 的 delta 等诊断值，
> 但**凡是进入 overview 主表的行，其 e2e/加速比一律用完整请求墙钟主口径**——锚点行（基线/最终
> 推荐/三元组合）必须实测，中间行可 `[估算]`（§1.1 公式），首步耗时作辅助口径
> （见 overview §1/§2.3/§7）——不得把构成口径数值直接当作主表单值；细分结论用于主表行归因与
> 证据，不替代主表数值。
> 本报表所有表格同样受 `overview-report.md` **§7 单元格纪律**约束：类型列只放枚举、特性/子项
> 名只放固定名词或档位名词、耗时/加速比/质量列只放数值（或规定占位 `—`），注释一律进「说明/
> 结论」列；不得把分母说明、区间、参考行状态塞进数值单元格。
> 本章节结构为**强制契约**：无数据章节**保留目录**并标「❓ / 未启用 / 初始即融合良好」，禁止静默删除章节。

## A. 无损细分

### A.1 融合算子（对应「a. 融合算子部分」）

- 归属口径：`kernel融合` 是**一个固定特性名**，其下所有融合内容（RMSNorm/RoPE/AdaLN/GELU/
  FFN 融合 kernel（operator-dev 开发）/Copy 消减等）都是子项——子项与方法**不得派生独立特性名**，
  一律以本节约定的表/说明记录。
- **A.1.1 每个融合内容（子项）的收益**：逐已使能/已识别融合子项给记录——表
  `[融合内容 | 实现方法(compile / API 接入) | 覆盖链(原算子序列→融合算子) | 证据(kernel diff) |
  收益(整 block 或单步,含 0.5% 阈值判定) | 步数 | 状态]`；
  状态枚举：`采纳` / `既有`（初始覆盖，无独立增量，**不省略**）/ `识别但不执行`（执行序对比后
  整 block 耗时影响 <0.5%，收益小；附证据与签名）/ `回退`；单变量证据。
  **步数**：性能识别/收益评估可为少步（如 1 步，同口径少步对比，见 overview §1.1），最终采纳行
  全量步数实测。
- **A.1.2 当前融合后的算子序列**：必须**按 Attn 路径 与 FFN(MoE) 路径两部分**给出当前序列
  （构成、kernel 计数、类别耗时占比；拆分为计数级即可，耗时级如未按路径采样标 ❓ 与补测方法）。
  本节与目录**必须保留**——即使融合已很好，也展示「融合后序列现状」。
- **A.1.3 识别到但未落地/未执行的融合机会**：表 `[融合内容 | 开发链(识别→operator-dev 开发/未开发) |
  执行序对比证据 | 整 block 耗时影响(<0.5% 判定) | 决策 | 状态]`；
  识别到融合机会（含需 operator-dev 开发新算子者）必须记录决策：收益小（整 block <0.5%）→
  「识别但不执行」；候选未实施标 ❓ 不计入收益；初始融合良好时此节写「无/少量」但目录保留；
  **量化使能后融合的收益归属**按 `overview-report.md` §2.4（并入使能特性行，拆分在此节/
  特性子表），归属不影响本节目录保留。

### A.2 并行（对应「b. 并行部分」）

- **A.2.1 候选策略验证矩阵**：框架支持的并行策略中**优选子集**逐项验证比较
  （USP / CFG / CP / TP 及组合）：表 `[策略 | 首步耗时(同窗) | 显存 | 使能/解锁条件 | 说明]`；
  框架支持但未测者标 ❓ 并注明为何跳过（如 ring 不支持 attn_mask）。
- **A.2.2 内存不足 → CPU Offload 联合审视**：因显存不可行的更优策略（如 TP1×USP4）→ 列 offload 类
  解锁（DLO/CPU offload/FSDP 语义）结果；**量化等降显存后复查**并行×新余量矩阵。
- **A.2.3 通算掩盖效果**：step_trace 的 compute / comm(未重叠) / free 拆分、Overlapped 是否可用、
  掩盖空间量级；随特性（量化等）使能后重采（见 `post-enable-review.md` 面②）。
- **A.2.4 通信带宽合理性**：hccl test 或其替代（实测 all_reduce/集合通信带宽 vs 理论带宽、跨拓扑/
  跨环差异）——用于验证并行策略的通信已内部优化；无数据标 ❓ 并写明方法与引用
  （parallelism-strategy `ascend-topology-bandwidth-diag`）。
- **纪律（方法要点，写进正文）**：**并行策略比较必须在「各自通信已内部优化（带宽利用/掩盖到位）」
  的前提下进行**——否则好策略因优化没做好而被低估（测得差），导致该策略后续优化潜力被误判丢弃；
  用 hccl 带宽基线 + step_trace comm 时间交叉核验「策略差因通信未调优」而非策略本身差。

## B. 有损细分

> **步数口径（同 overview-report §1/§1.1）**：e2e 完整请求墙钟 = **主口径**（锚点行实测；
> 中间行可 `[估算]`，公式见 overview §1.1）；**首步耗时（warmup 后第 1 个 step, s/step）=
> 辅助口径**——完整请求墙钟随步数非线性变化，跨步数不直接比 e2e，用首步耗时做同口径对比。
> B.1–B.4 的性能扫描/选型过程可在少步下进行（如 1 步识别收益）；**凡质量列要填门禁结论的
> 行与组合行必须全量步数实测**（最终采纳行 e2e 实测）；各表行登记实测步数与 e2e（实测或
> `[估算]`，识别行注明「识别步数」）。

- **B.1 稀疏**：不同稀疏度下**单个特性**的质量与耗时——表
  `[算子(稀疏度xx%)（如 rf_v2(80%) / EagleQBSA(80%)）| 后端/precision/mask 算法 | 步数 | e2e(实测或[估算]) | 首步耗时 | 质量(psnr/ssim) | 结论]`
  （逐档端到端 gate；非线性档（如 0.6 < 0.8）显式标注；档位尽量同窗对比，跨窗注明；
  行/记录命名一律 `算子(稀疏度xx%)` 式；稀疏×FA 量化(f8) 产生的新算子须标注 mask 算法与
  量化规格）。
- **B.2 量化**：**FA 量化 与 线性层量化分开**——表
  `[档位与规格（w8a8(mxfp8) 式，链：w8a8 → w8a8f8 → w4a4f8 →(可选)w4a4f4）| 实现(类型/覆盖范围) | 耗时 | 加速比 | 质量 | 进一步融合(量化后融合)性能]`；
  进一步融合未实施标 ❓（如 H3 w8a8 O1/O6）；档位链上框架未实现档标注不使能；组合代表档 = w8a8f8；
  量化算法类型须写明 w/a 位宽与激活方案、覆盖路径。
- **B.3 cache 与采样步数优化（同一章，分别给单独效果）**：cache 表
  `[类型/档位(按框架推荐) | 首步耗时 | 收益 | 质量]`；采样步数表 `[步数档 | 首步耗时 | 质量 | 是否启用]`；
  两表分开，不混；**Cache 与时间步优化在同一任务组合中二选一**（不同时入同一对比行/组合）；
  两者均按框架能力/推荐使用（mindiesd 不做额外适配）；未启用步数优化标「未启用（决策记录）」。
- **B.4 组合（对应「组合」）**：组合矩阵表 `[实现(命名按 §2.1，量化以 w8a8f8 为代表档) | 耗时 | 相对收益(vs 基线 & vs 无损) | 质量 | 结论(frontier/回退)]`。
  结论=回退的行（cache/稀疏/量化层回退后的最终档）**必须全量步数实测 e2e**——回退档是潜在采纳
  配置，性能加速效果须实测识别，禁止少步/估算（见 combination-search「层回退策略」）。

## C. 候选治理（过程交付 · 强制：已否决与未尝试）

> 探索过程本身的交付（借鉴 bounded search 的 rejected-with-signature 与 remaining-untried）：
> 采纳项的「候选 → 验证 → 选定」链已在 §5 子表/细分 A/B 呈现，本节**只收否决与预算外**，不重复。
> 过程证据单一来源 = run-state「候选与迭代表」（references/run-state.md），本节做报表级汇总。

- **C.1 已否决假设表**（表 `[round | 特性/实现 id | 假说(一行) | 阶段 | 否决签名(crash/implementation-wrong/degenerate/dominated/out-of-scope/no-gain) | 证据 | 是否派生新候选]`）：
  凡在迭代表判 `reject` 的候选/档位/组合必须入表——禁止只报采纳项、把否决静默吞掉；
  `dominated` 须写被谁替代；`no-gain` 含口径说明（融合类按整 block <0.5% 收益小阈值判定，
  见 A.1.3 与 optimization-flow S1）。
- **C.2 未尝试候选清单**（表 `[候选 | 预期价值(一句) | 未试原因(预算耗尽/依赖缺失/框架不支持) | 建议]`）：
  预算到点收尾时把迭代表中未尝试假说与探索中浮现的新方向登记为清单（terminal_pending_review
  交用户选档），不静默丢弃；预算记录（max_rounds/已用）随附。
- **C.2 禁区（组合覆盖 [MUST] 行不得入表）**：S4-2 必测组合（量化×稀疏 / 稀疏×Cache /
  量化×Cache / 三元 `Cache+量化+稀疏`）不因"预算耗尽/排序靠后"进 C.2——每行必须已测
  （C.1 带签名）或登记豁免（原因 + 证据，见 combination-search.md「必测组合覆盖集」）；
  否则视为组合覆盖缺口，先补测或补豁免再闭环。
- 边界：C.1/C.2 只做治理汇总，收益数值不进 overview 主表；C.2 中「框架不支持」类须按
  `overview-report.md` §2.5 三态标注并与 support-matrix 一致。

## D. 证据与声明

- 与总览同一纪律（基线唯一 / 命名 / 绝对质量口径 / 同窗同卡组 / 计数契约 / off-identity / 视觉门
  inconclusive 不宣称通过）；❓ / 未启用 / 跨窗口清单集中列；产物落点 ↔ overview §5 子表 / evidence.json。
- 特性覆盖清单（run-state「任务级触发判定」）：闭环前复核无未裁决项；每特性 做/不做 结论在
  A.1–B.4 各表与 §C 可回溯（触发判定登记见 optimization-flow「特性覆盖清单」）。
- 细分章节内容与 overview_report 主表/子表同源，只拆不矛盾；若冲突以同窗实测为准并登记。

## E. 质量证据（每运行标杆对照 · 强制）

> 每次有损/组合运行（含单档、叠加链每一行）的**标杆质量对照信息**必须在本节逐行登记，
> 随报表归档（不可推导的判定结论入库；可推导数值由 `evals/scripts/quality_compare.py` 对
> `runs/` 冻结产物现算，不入 git——见仓库 `evals/profiles/README.md`「数值不入库」约定）。

- **E.1 质量证据表（强制；每档/组合一行，禁止只记性能不记质量）**：
  表 `[档/组合(命名按 §2.1) | 对照标杆(profile 冻结 baseline) | 质量数值(psnr/ssim 或 视觉域-仅登记) |
  visual_artifact(pass/fail/inconclusive+存证) | off_identity(逐字节/数值差/md5) | 证据引用
  (runs/{id}/quality.json + 帧或 profile 指针)]`；
  数值口径 = 与 `evals/profiles/{model}.toml` 冻结 baseline 的**同 seed 对照**（视频 21 采样帧 /
  图像 21-seed 像素对，按 profile `[domain]` 套用协议）；
  弱视觉域（video_chaos）数值只登记回归、主判据 visual+off-identity；强视觉域（图像）可设
  绝对门槛——域规则来自 profile `[domain]`，报表不另起。
- **E.2 强制关联**：overview 质量数据列每行数值/结论 ↔ 本表对应行（profile + run 引用）；
  缺对照基线或未跑质量门禁的档位 → 只登记不得写 pass；质量证据缺失视为交付缺失（close
  门禁复核项）。
