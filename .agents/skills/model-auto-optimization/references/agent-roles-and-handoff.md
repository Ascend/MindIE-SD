# 多 agent 角色分工与交付/交接契约（编排层 L1 机制）

> 定位：**角色、交付件、交接与并行控制的单一真源**——回答「谁做 / 交什么 / 存在哪 / 换 session 怎么接 /
> 并行怎么控」。与 `run-state.md`（进行中状态）、`artifact-layout.md`（终态产物）、
> `report-contract.md`（报表列）配套：**本文件只管协议（角色与交付），状态内容仍写 run-state，不在此重复**。
> 适用范围：**自动优化任务默认扇出**（见 §0，用户裁决）；**不开的理由必须落 run-state**，
> 而不是"默认单 agent"。

内容索引：§0 **扇出与进度汇报（强约束）** → §1 扇出分类与资源检查（§1.1 **工作性质**同类共用 /
异类拆 · §1.2 **并行验证**）→ §2 四角色 → §3 交付件契约 → §4 交接单与 session 接力 →
§5 并行特性验证控制 → §6 拒收与失败模式 → 维护与更新。

## 0. 扇出与汇报（强约束 · 用户裁决，覆盖此前的"默认单 agent"）

> **来源**：用户对自动优化交付件的裁决（2026-09-20）。该裁决**改写了本文件的默认值**：此前默认
> 单 agent 自执行，现在**默认扇出**。§1 的原"四条判据"降级为**资源/预算检查与例外清单**，
> 不再是"要不要开子 agent"的前置否决。

**0.1 默认扇出**：一次自动优化任务里，**具体优化工作默认扇出给子 agent 执行**——
按「**特性 × 卡组**」切分执行单元（一个执行单元 = 一个自洽的可验证特性 + 独占的一批卡/窗口），
主控只做定序、派发、裁决与总览收口（§2 四角色）。
**仍然不扇出**（保留 §1 例外清单，硬禁）：同 seam 双 writer、同一次实验窗口内的对照臂、
需共享演化上下文的连续单链探索、口径未冻结（manifest/基线未定）、协调开销大于收益的小任务。

**0.2 主控定期汇报（强约束）**：主控**至少每 20 分钟**向用户汇报一次进展（可按会话约定调整周期，
但**必须显式约定并在 run-state 记录**），汇报字段固定：

| 字段 | 内容 |
|---|---|
| 窗口 | 本轮时间范围 + 同时占用/释放的卡组与实验窗口 |
| 已完成 | 已验证并落盘的项（带**口径与单位**，单位按 §`report-contract.md` 与 `overview-report.md` §2 契约） |
| 进行中 | 在跑的臂/实验，预计产出时间 |
| 阻塞 | 具体阻塞条件 + 已尝试的绕行（没有就写"无"） |
| 裁决请求 | 需要用户决策的点（没有就写"无"） |
| 下一步 | 下一轮计划 |

汇报本身**进 run-state 的轮次记录**（不是只在对话里说），保证换 session 可回溯。

**0.3 特性合入后必须给"整体效果 + 来源拆分"（强约束）**：一个特性合入最好档时，交付件里必须同时给
①**整体优化效果**——同窗 A/B，**两条并列**：相对**基线**、相对**合入前的最好档**；
②**收益来源拆分**——把该特性的收益按来源拆开（设备内算子级 / 主机与下发 / 阶段级 / 精度档位变化…），
并显式标注**哪些项不可相加**（争夺同一处收益的候选）。
拆分表的列契约见 `overview-report.md` §2 与 `report-contract.md`；**断链（无同窗 A/B 或无来源拆分）
的行不得进主表**。

## 1. 扇出分类与资源检查（先分类，再判并行）

**两轴判据**：① **工作性质**——同类工作**共用 agent**，异类工作**拆**（§1.1）；② **是否并行验证**——
同一（类）工作的多个单元要不要并行，按 §1.2 与下列四条**资源检查**逐单元判。

**四条资源/预算检查**（任一不满足 → **该单元**改回串行执行并把理由记入 run-state「决策与轮次」；
注意：这不再是否决"整个任务扇出"的理由）：

1. **可独立完成**：子任务不依赖主线正在演化的上下文——依赖方**读文件**即可补齐，不需要主线脑内状态；
2. **有独立验证价值**：产物能被**未参与实施的另一个实例**独立复核（性能/精度/生效判定类天然满足）；
3. **资源可互斥**：卡组 / 容器 / 实验窗口 / 可写文件能划开（见 §5）；
4. **预算允许**：扇出的成本是**数倍 token 与上下文**；并行的墙钟收益必须大于协调开销。
   本仓特有约束：并行度通常受**空闲卡组数**限制，而不是受 token 限制——先看卡，再看钱。

**不扇出清单（硬禁）**：

- 同一 seam 的双 writer 组合（`seam_check.py` 判定的互斥组合）；
- 需要**共享演化上下文**才能决策的连续单链探索（假说 A 的结论决定假说 B 的设计）；
- 同一次实验窗口内的对照臂（同窗对照必须由同一口径、同一流程产出）；
- 口径未定（manifest / 基线未冻结）时——**先定口径，再并行**；
- 只是"想快一点"而子任务本身几分钟能做完（协调开销 > 收益）。

### 1.1 第一轴：工作性质（同类共用 / 异类拆分）

不同业务类型的**技能面、验证口径与产物形态**不同——混进同一个 agent 会**串用判据**
（拿算子对拍口径判"使能是否生效"、拿计数契约判"算子精度"）。三类典型工作 + 优化验证：

| 工作类型 | 典型 skill | 交付物形态 | 验证口径（判据来源） | 典型失败模式 |
|----------|------------|------------|----------------------|--------------|
| **纯算子开发**（DSL / 内核） | `operator-dev`（+ `benchmark-dev`） | 内核实现 + 数值对拍 + 算子级微基准 | 逐位 / 数值门 + 算子性能（`../../accuracy-gate/SKILL.md`、`../../benchmark-dev/SKILL.md`） | 编译过但结果错；换写法更快但不等价（per-shape 条件等价） |
| **框架接入**（注入点 / 图适配） | `framework-integration`、`pattern-dev`、`aclgraph-dev` | 注入点或注册机制 + 图命中证据 | 图**真实命中** + kernel diff + 数值核验（禁前端绕开） | 假命中 / 注册未生效；算子在但没进图 |
| **特性使能**（开关 / 计数） | `framework-integration`（分支 A）、`dit-perf-opt` | 开关配置 + 生效计数契约 | 计数契约 + 同窗 A/B + off-identity（`../../perf-gate/SKILL.md`） | no-op 假加速；门控没生效却"跑通了" |
| **优化验证**（多维度档位） | `model-auto-optimization` + 域模块 | 特性档 + 证据 + 报表行 | 同窗 A/B（验收态）+ 质量门 | 口径漂移、对照臂被污染、未裁决结论被当既定事实 |

**切分规则**：

- **同类**（同一行）→ **默认共用一个 agent**：技能面、口径、产物形态都相同，拆开只会重复加载知识、
  多一次口径转述；
- **异类**（不同行）→ **拆**：各自带自己的 skill 白名单与验证口径（派发单必须写「必须使用 skill」）；
- 同一任务含异类工作时（如"新算子 → 接入框架 → 开量化档"）→ **按类型分段**，上一段的产物
  （内核 + 对拍证据）是下一段的输入，**交接靠回执与交接单（§3/§4），不靠对话**；
- **反例（硬禁）**：把"纯算子开发"和"特性使能"塞进同一个 agent——它一定会拿对拍口径去判"使能生效"。

### 1.2 第二轴：优化类默认共用，仅并行验证时拆

**优化维度本身（Cache / 量化 / 稀疏 / 并行 / 时间步…）不构成拆分理由**——它们共用同一技能面、
同一基线口径与同一产物形态，**默认由同一个执行 agent 顺序推进**（省上下文、少一次口径转述）。
拆成多 agent 只服务一件事：**多单元并行验证**。

- 拆的粒度 = **并行单元**（`特性 × 阶段 × 卡组`，§5），**不是**"每个维度一个 agent"；
- 拆的前提 = §1 四条判据全过 + §5 的资源租约与并发上限（**没有空闲卡组就不要拆**）；
- 拆的收益是**墙钟**，代价是协调与上下文成本；
- **共用时的上下文卫生**：单元之间用交接单切段（§4）——当当前上下文已被上一单元的证据/日志占满时
  换新实例，而不是继续硬塞（换实例的成本 ≪ 带着污染上下文继续决策的成本）。

## 2. 四角色（职责 / 必需 skill / 写权限 / 交付件）

| 角色 | 职责 | 必须使用的 skill | 写权限（只写这些） | 交付件 |
|------|------|------------------|--------------------|--------|
| **主控 orchestrator** | 定序、派发、裁决、跨阶段调度、总览收口、对用户汇报 | `model-auto-optimization`（模型优化）/ `dev-workflow`（仓内开发） | run-state 推进表/迭代表/覆盖清单、双报表与总览表 | 派发单 + 裁决签名（表内） |
| **代码开发 developer** | 实现与代码改动（pattern / 算子 / 图下发 / 框架侧使能与接线） | `dev-workflow`、`pattern-dev`、`operator-dev`、`aclgraph-dev`、`framework-integration` | 代码仓（按归属）+ `evidence/{task_id}/{stage}/{feature}/dev.md` | 改动清单 + 自验证回执 |
| **结果分析 analyst** | 采集数据的分析与判定；**复核（含独立复核）** | `profiling-collect`、`profiling-analyze`、`perf-gate`、`accuracy-gate` | `.../analysis.md`、`review-{feature}.md` | 分析结论 + 复核单 |
| **部署与资源分配 deployer** | 环境 / 容器 / 权重就绪，**卡组与实验窗口的分配与登记** | `env-install`、`remote-access` | `evidence/{task_id}/{stage}/lease-*.md`、环境指纹 | 资源租约 + 环境清单 |

- **角色是职责划分，不是人数约束**：同一角色可由不同实例承担；**复核必须由未参与该特性实施的实例**承担
  （§6「复核独立性」），不得由实施者自证充当复核。
- **边界纪律**：主控不写代码、不亲自采集；developer 不自行定口径；analyst 不改代码
  （发现问题回报，不静默修）；deployer 只分配资源，不裁决收益。

## 3. 交付件契约（agent 间只传文件指针，不传上下文）

**唯一交付通道 = 落盘文件。** 硬规则：

1. 派发 prompt **只填模板字段与文件指针**，不转述上下文：执行者进场自读（§4 读取序）；
2. 回执**只回**三样：结论摘要 + 证据文件路径 + 需主控决策的问题——长日志/原始数据留 evidence/，不回传主上下文；
3. 一切"已完成"必须**可指针化**：一条结论进总览表，必须能顺指针链回溯——
   `总览表行 → 回执 → 证据文件/日志 → 资源租约（证明窗口互斥）→ manifest/基线（证明同口径）`，
   断链的行**不得进主表**（列契约见 `report-contract.md`；多 agent 模式下断链由
   `scripts/stage_gate.py` 机械校验，见 §4）；
   **路径基准（强制 · 演练实测两类断链）**：指针一律**相对 run-state 所在目录（`agentic/`）解析**，
   即回执/派发单里写 `evidence/{task_id}/…`——**既不写工作目录前缀、也不写 `agentic/` 前缀**；
   产物在别处（报表 / `runs/…`）写相对 `agentic/` 的 `../runs/…`。
   **实测两类断链**：① 把 `evidence/` 放在 `agentic/` 之外（指针解析不到）；② 多写 `agentic/` 前缀
   （门禁按 `run_dir/token` 解析 ⇒ 实际找 `agentic/agentic/…`）。派发单必须写明基准，
   交接单「产物指针」同此基准。
4. **只追加不覆盖**（先读后追加）；**禁止两个 agent 写同一文件**；
5. **禁止**：只回自然语言结论；把状态写在对话里；引用**未裁决**结果作为前提。

| 交付件 | 谁写 → 谁读 | 路径 | 最小字段 |
|--------|-------------|------|----------|
| 派发单 `dispatch-{feature}.md` | 主控 → 角色 | `agentic/dispatch/`（模板见 `workflows/references/dispatch-templates.md`） | task_id / 阶段 / 特性 / 角色 / 必须用 skill / 任务 / 口径指针 / 产物路径 / 禁区 |
| 回执 `receipt-{feature}.md` | 角色 → 主控 | `evidence/{task_id}/{stage}/{feature}/` | 结论 / 生效计数或证据 / 命令+退出码 / 证据路径 / 异常 / 需决策项（四行自验证格式见 dispatch-templates） |
| 复核单 `review-{feature}.md` | analyst（未参与实施）→ 主控 | 同上 | 复核对象与被复核回执指针 / 检查项 / 结论（通过·FAIL·无法判定）/ 差异与诊断 / 未覆盖项与原因 |
| 资源租约 `lease-{group}.md` | deployer → 全体 | `evidence/{task_id}/{stage}/` | 卡组 id / 容器或远端 / 起止时间 / 占用者（特性·实例）/ 释放确认 / 冲突排队规则 |
| 交接单 `handoff.md` | 每个角色收尾 → 下一位/下一个 session | `agentic/handoff.md` | 见 §4 |
| 运行状态（推进表/迭代表/覆盖清单） | 主控单写 | `agentic/run-state.md` | 见 `run-state.md`（本文件不重复） |

## 4. 交接单与 session 接力（换 session 能继续）

**纪律一句话：状态在文件里，不在对话里。**

**进场读取序（任何角色、任何新 session 的最小重建路径）**：

1. `agentic/run-state.md` —— 推进表（到哪一步）/ 迭代表（试过什么、裁决与签名）/ 覆盖清单（哪些特性未裁决）；
2. `agentic/handoff.md` —— 最新交接单（上一位做到哪、卡在哪、下一步）；
3. `evidence/{task_id}/` 索引 → 该阶段/特性的回执与复核单；
4. `runs/{task_id}_.../`（manifest / 双报表 / evidence.json）—— 口径与基线。

> 读完这四处再动手。**不得**要求用户复述上下文，也不得凭对话印象继续；四处信息冲突时以
> run-state + manifest 为准，并先**修正文件**再推进。

**交接单模板（每次收尾必写；追加不覆盖，最新在末尾）**：

```markdown
## {YYYY-MM-DD HH:MM} {阶段} · {角色} · {agent/session 标识}
- 状态: in_progress / done / blocked
- 最后完成动作: <一句 + 证据指针>
- 未决问题: <问题 + 需要谁决策>
- 下一步: <下一位要做的第一件事>
- 产物指针: <文件路径（+ 计数 / md5 等可比对标识）>
- 口径指纹: <基线 / manifest 指针 + 生效开关 + 步数档>
- 资源占用: <卡组 id / 容器 / 窗口；是否已释放>
- 预算余量: <max_rounds 剩余 / 时间盒剩余>
```

- **交接判据（可机器核，已机械化）**：交接单存在 + 字段齐全（缺项即视为"未交接"）+ 与推进表状态一致
  —— `scripts/stage_gate.py` 的**多 agent 契约校验**（`--run-dir` 下存在 `dispatch/` 即触发，每阶段都跑）
  实际校验：交接单八字段（**最新一条**）/ 回执四要素 / 指针链可达 / 多单元租约；
  `--selftest` 用 8 个用例做负样本回归（pre-commit 钩子 `stage-gate-selftest`）。
- **校验边界（强制 · 防把叙述性文件做成硬门禁）**：门禁**只校齐备性**——交接单「存在 + 最新条八字段标签」
  与回执「四要素 + 指针可达」；**不校**交接单自身的指针可达（其「产物指针」允许是**"下一步要交的"**、
  此刻尚未生成）与任何内容正确性。**「已完成必须指针可达」只归回执**——回执声明的是"已完成"，
  交接单允许声明"将要做/进行中"。
- **命名映射**：本文件的交接单即 `.agents/README.md` §7 所称的 **`HANDOFF_*.md`（交接文档）**，
  运行态落点 `{工作目录}/agentic/handoff.md`（与 run-state 同目录、同不入 git）。
- **写时机**：阶段收尾、裁决后、阻塞时、session 结束前——**即时写，不延后到收尾**
  （与 run-state「即时回写」同纪律）。
- **不入 git**：交接单属运行态（与 run-state / evidence 同侧，见 `artifact-layout.md`「仓库零数据」）。

## 5. 并行特性验证控制（主控的控制面）

- **并行单元** = `特性 × 阶段 × 卡组`：一个单元 = 一个 feature 证据目录 + 一名 developer/analyst 实例 + 一份租约。
- **可并行判据**：证据目录互不覆盖 + 卡组与窗口互斥 + 不共享可写配置 + 不引用彼此未裁决结果。
- **互斥判据**：`scripts/seam_check.py` 判定同 seam 双 writer（同 attention_backend、双缓存等）→
  **不并行**，取最强档后顺序化；同代码 / 同环境改动 → 串行（避免互相污染构建与镜像）。
- **资源租约（deployer 唯一签发）**：**一次一实验（NPU 单飞）**；不同单元分配**互斥卡组**；
  租约写明起止时间与占用者，超时回收；冲突**排队不抢占**（禁止打断他人对照臂）。
  **≥2 并行单元而无租约 → `scripts/stage_gate.py` 报 error**（发卡即登记，别只留在对话里）。
- **并发上限**：由**空闲卡组数**与时间盒决定，不是"想开几个开几个"；每单元设 max_iters + watchdog +
  预算，失败记为 proposal 不静默终止（护栏细则见 `search-orchestration.md`）。
- **收口（主控）**：dedupe → 冲突消解 → frontier 合并 → 在**同一基线**下逐行录入总览表
  （`overview-report.md` §2 固定 8 列）；每行须能追到该行的回执与租约（§3 指针链），
  否则不得进主表；并行中**禁止互相引用未裁决结果**（防"未裁决结论被当既定事实"）。
- **波次**：单特性并行 → 单特性收敛后再进组合（含 [MUST] 必测集），见
  `workflows/optimization-flow.md`「执行波次与并发」。

### 5.1 任务卡与结论验收

- **切分准则**：按**"可独立证伪的问题"**切，**不按文件 / 模块切** —— 按模块切出来的两个 agent
  会产出互不可比的读数，主控最后无法合并。
- **每张任务卡必须写全五项**（缺项退回）：① **判定**（要回答"是/不是/哪个"，不是一个主题）；
  ② **证据坐标** `file:line`（或产物路径，不接受"我读过代码"）；③ **计数**（报计数 / 比值，
  **不接受形容词**）；④ **负对照**（该判定在什么情况下**会失败**，证明探针不是瞎的）；
  ⑤ **反证条件**（出现什么结果就**推翻**它；预登记，事后不改口径）。
- **回报只带关键信息**：过程与中间日志留在各自报告里，主控只收"判定 + 上面五项"。
- **资源授权要显式**：写明**唯一**可碰加速器的 agent + **设备号** + **禁项清单**（不推送 / 不 pkill /
  不改共享树），其余 agent **只读**；机器占用判据见 `../../remote-access/references/arm-driver-traps.md` §5。
- **分支一旦变得无关就立刻回收资源**——宁可早停，不要留着占卡。
- **子 agent 的结论必须被测量否证或确认**，不能只做汇总——汇总视角看不出矛盾，只有实测能。

## 6. 拒收与失败模式（多 agent 特有）

| 失败模式 | 症状 | 拦截 |
|----------|------|------|
| 回执失真 | 自报成功，但产物不存在 / 计数不符 | 回执必带命令+退出码+证据路径；主控核验指针可达 + 计数契约（见 SKILL「声明纪律」4） |
| 错误复合 | 上游错误前提被下游当事实继续放大 | 派发单写死口径指针；只接受**裁决后**结果作为前提 |
| 口径漂移 | 各 agent 各自起口径 / 基线 | 口径只在 manifest + run-state；派发单注明"从 run-state 读取，不另起口径" |
| 重复劳动 | 两个单元做同一候选 | 迭代表 round 全局唯一；派发前先查迭代表与覆盖清单 |
| 上下文碎片 | 子任务靠对话猜上下文 | §4 进场读取序 + 派发单只给指针 |
| 假并行 | 名义并行实为串行 / 名为两特性实为同 seam | 租约与卡组登记可核；seam_check 静态过滤 |
| **汇总代替验证** | 主控把子 agent 结论聚合成"既定事实"，未用测量复核 | 每条结论必须由**测量**否证或确认；缺负对照的回执按未验证处理（§5.1） |

- **拒收语义**：回执缺自验证节、或记录与 evidence 矛盾 → 拒收并列出缺失项，要求补齐后重交；
  主控**不得**用自行审查替代验证（同 `workflows/optimization-flow.md`「阶段推进规则」3）。
- **复核独立性**：性能 / 精度类结论的复核者必须**未参与该特性实施**——同一实例自证只算"自验证"，
  证据强度低于独立复核（证据阶梯见 `../../perf-gate/SKILL.md` 与 `../../accuracy-gate/SKILL.md`）。
