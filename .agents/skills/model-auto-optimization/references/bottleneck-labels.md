# 瓶颈点标签表（MAO 产出 · 优化域入口的唯一输入）

> **归属**：本表由编排层（`model-auto-optimization`）产出与维护；**消费方**为优化域入口
> `performance-optimization`（其按标签分发到各优化模块）。标签是**域间接口**，不是实现细节。
> **单一真源**：标签枚举与门限口径只在本文件定义，其它技能只引用。

## 1. 标签枚举（5 类，禁止自定义）

| 标签 | 含义 | 判据源 | 备注 |
|---|---|---|---|
| `DiT-计算受限` | DiT 主体（MatMul / Attention / Norm-launch 等）占比领先 | `profiling-analyze`（kernel 占比 + 阶段账） | 细分类（MatMul / Attn / Norm）留优化域内部映射，不上升为标签 |
| `DiT-通信受限` | 未重叠通信占比显著 / 掩盖空间大 | `profiling-analyze` + 并行模块的可比口径 | 注意两种分母语义不同：Exposed Ratio（未重叠 ÷ 通信总量）与"掩盖空间上限"（未重叠秒数 ÷ 未开 profiler 单步耗时），报数时须写明用的是哪一个 |
| `非DiT-解码段` | VAE / TAE 解码段耗时占比达门限 | 阶段账（本文件 §2） | 触发 S6 |
| `非DiT-host段` | 交付/搬运（编解码、worker→API、落盘）与装载/预热的固定开销占比达门限 | 阶段账（本文件 §2） | 触发 S6 |
| `一致性不达标` | 结构性改动后输出与基线不一致 | 精度验收标准的判据 | 不达标 → 转对应对象的 `troubleshooting-{对象}.md` 排障流程 |

## 2. 非 DiT 段的 10% 门限（S6 进入条件）

- **分母**：该段耗时 ÷ **同一口径**的端到端请求墙钟（e2e 主口径）。
- **测点**：S0 冻结基线时产出**阶段账**（每阶段墙钟 + 占 e2e 比 + 峰值显存），此后每轮迭代沿用同一测点口径。
- **必须带步数档**（强制）：同一模型在不同步数下固定开销占比差异极大 ——
  **本仓已有证据**：4 步交付档实测 非 DiT 段**已达 10% 门限**（交付 + 视频 TAE + 音频 VAE 三段分解值
  见归档 `{run_results_dir}/archive/` 与 `vae-opt/SKILL.md:18-23`），而 50 步档必然远低于 10%。
  故门限的写法是「在 {步数档 / 分辨率 / 卡数} 口径下，该段占比 ≥10%」，**不是**无条件 ≥10%。
- **未达门限**：在推进表把 S6 登记为 `skipped` 并写理由（**登记 ≠ 缺失**，闭环时"无未裁决项"要求覆盖到它）。

## 3. 瓶颈点的确认权（防"优化错对象"）

- 用户可直接给出瓶颈点，但**须带一句实测锚点**（阶段账某行、或某 kernel 占比）——
  理由：声明与实际常不符（例：用户认为"解码慢"，实测 DiT 占 89%）。
- **无锚点 → 退回 MAO 做定位**，不由优化域入口自己猜。
- MAO 分析产出的标签同样要附锚点（阶段账或 kernel 占比行），便于复核与回溯。

## 4. 与优化域的接口

优化域入口（`performance-optimization`）**只消费标签**，不再做占比分析；其分发路由表按标签指向：

| 标签 | 分发目标 |
|---|---|
| `DiT-计算受限` | DiT 计算模块（`dit-perf-opt`）+ 需要新能力时 `pattern-dev` / `operator-dev` |
| `DiT-通信受限` | DiT 通信模块（`dit-parallel-opt`） |
| `非DiT-解码段` | VAE 模块（`vae-opt`） |
| `非DiT-host段` | host 模块（`host-opt`） |
| `一致性不达标` | 精度验收标准（`accuracy-gate`）→ 排障 |

## 5. 维护与更新

- 触发：新增/合并优化模块、阶段清单变化（如 S6 的进入条件调整）、或报表口径变化时同步本表。
- 校验：标签枚举凡被引用处必须是本表原文（`report_lint`/人工评审可查）；新增标签须同时落到优化域
  分发路由表与相关技能 description，否则视为孤儿标签。
- **如何判定记录仍成立**：跑一次 S0 阶段账，核对"步数档 + 占比 + 门限"三者是否仍能复现；
  换模型/换步数档/换硬件后必须重测，不得沿用旧占比。
