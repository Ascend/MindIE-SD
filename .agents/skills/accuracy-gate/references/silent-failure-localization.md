# 静默错误定位（silent failure localization）

**一句话**：当"结果不对但一切正常"——进程不崩、日志无异常、无 NaN/Inf、形状与帧数正确、同进程内
结果甚至可复现——靠"读代码找 bug"几乎不可能收敛，只能靠 **造参照、切维度、做对照** 把"哪里错了"
逼出来。本文件给出可迁移的**判据与流程**；对象特有的案例与规避手段不在这里（见 §16 索引）。

**先确认走对入口**：

| 你在回答的问题 | 去哪 |
|---|---|
| 结果**为什么是错的**（无报错、无 NaN、md5 稳定但内容错） | 本文件 |
| 这个替换**是不是无损**（等价分层 / 逐位断言 / 三层验收） | 本技能 `SKILL.md` 与 `references/bit-exact-harness.md` |
| 这个优化**有没有效、有多少效** | `perf-gate`（同窗 A/B、漂移校正、报表口径） |
| 解码**能不能切到多卡、怎么切才逐位精确** | `vae-opt`（独立性证明、状态携带切片、交换预算） |
| 某个**已知设备算子缺陷**的判定实验与规避 | 对象技能自己的 `troubleshooting-{对象}.md`（首批见 §16） |

如果错误是在你改动**之后**才出现的，先用测量口径确认"改动到底改了什么"（产物 md5 / 张量 dump
是否变化），再回到本流程定位——**先确认"变了"，再查"为什么错"**。

---

## 1 为什么常规检查抓不到（先讲清楚，它决定方法）

- **所有健康检查都会通过**：md5 门禁、形状断言、数值范围断言、甚至"跑两遍结果一样"的可复现性
  检查都不报错——缺陷产物在**同一进程内**可以是完全确定的。
- **它常被误判成"模型 / 量化 / 稀疏的问题"**：客观表现是"画面变差 / 尾部退化 / 颜色漂移"，
  最自然的猜测是模型质量，而不是某个算子在特定形状下少写了一部分输出。

**复核**：拿缺陷产物与**已知良好参照**各跑一遍常规门禁；若两者门禁结果相同而内容明显不同，
说明门禁对本类缺陷仍然盲，需要走本流程。

## 2 铁律

1. **先建真值，再谈对齐**：没有真值只能描述现象，无法判断"错了多少、从哪开始错"。
2. **一次只动一个维度**：设备（CPU↔NPU）、精度（fp32↔bf16/fp16）、形状（batch / 长度）、
   实现（等价 API 写法）分开测；混在一起测等于没测。
3. **"从第几个单位开始错"是最有价值的一个数**：它把问题从"整条链"缩到"某个算子的某个位置"。
4. **假设必须先被证伪才允许写进结论**：每条"看起来很像"的解释都要有实测数据，不能靠推理。
5. **任何修复都要有三层回归**（见 §10），缺一层都不算修好。

## 3 S0 建立真值参照

目标是拿到"同一份权重 + 同一份输入"在**可信环境**下的输出，作为后续一切对照的参照。

- 优先 **CPU fp32**：慢，但语义最直白，且在设备出问题时通常仍给出正确结果；
- 保存**真实输入样本**（真实数据 dump，而不是随机张量）：随机输入往往触发不到与真实数据
  分布相关的路径，也可能触发不到同一批 kernel 配置；
- 若被查对象是"解码 / 后处理"这类可换实现的部分，**再准备一条独立实现的对照**：两条独立路径
  互相印证，比单条路径的"看起来正常"可靠得多；
- 记下参照的用途边界：CPU 真值用来判"设备算错没"，独立实现用来判"这段本来就该长这样吗"。

**复核**：换了权重 / 解码器 / 预处理约定后，参照必须重建——旧参照与新链路不再是同一口径。

## 4 S1 把现象量化

主观描述无法收敛，必须先有指标。视频 / 图像类输出可用的组合（工具见 §16）：

| 指标 | 抓什么 | 异常形态 |
|---|---|---|
| 桶化高频能量（相邻像素差） | 结构是否还在 | 后半段断崖式下降 |
| 16×16 块均值方差 | 纹理与结构强度 | 骤降 = 糊成一片 |
| 逐通道均值（R/G/B 分开看） | 通道是否被写坏 | 某一通道显著偏离另两路 |
| 帧间差 + 近重复段计数 | 冻结 / 重复 / 频闪 | 长串近零段、反复孤立尖峰 |
| 单帧 PNG 体积（或张量压缩体积） | 极低成本的"信息量"代理 | 接近全平图时体积骤降 |
| 按固定帧数分桶统计 | 从第几秒开始坏 | 某个桶起持续异常 |

张量类输出用同样思路：分桶统计 + 逐帧 / 逐 token 的 L2 与最大绝对差 + 与真值的相关性。

**判据要点（同时也是复核方式）**：必须先测**正常样本**的指标量级，否则不知道某个数算正常还是坏。
量化脚本自带合格判据（末桶不低于首桶的 50%、冻结段应为 0、允许少量孤立尖峰），
**换机器 / 版本后重跑一次健康样本**确认判据量级未漂移。

## 5 S2 逐层打点，找首个分叉点

在**同一份输入、同一份权重、同一段代码**下，把 CPU 与 NPU 的每一层（或每个 block）输出逐个比对。
判据用两个**相对量**，比绝对差更稳：

- `rel = mean|NPU − CPU| / mean|CPU|`——层开始分叉时会增长；
- `amax = max|NPU| / max|CPU|`，约等于 1.000 表示量级一致；远离 1 说明该层写的是"另一份东西"，
  而不是精度不够。

**分段式分叉**（头段一致、尾段坏）几乎必然指向"**某次调用只有一部分被写入**"，而不是"整个算子
精度不够"。骨架见 §16 的 `scripts/layer_bisect.py`。

**复核**：打点只有在两端同 dtype（fp32）时归属才成立；只要这一步引入了 dtype 变量，
分叉点的归属即失效，必须重做。

## 6 S3 算子隔离 + 等价写法对照

找到可疑 block 后，把上一层输出单独喂给这个算子（CPU 与 NPU 各一份），把它从网络里摘出来：

- 隔离后**错误依然复现** ⇒ 缺陷在这个算子本身，与上下游无关；
- 再测**同一语义的其他写法**（如 `nn.Upsample` / `F.interpolate(mode=...)` / `size=` 形式）：
  若多种写法**错得一模一样**，说明是**同一个底层 kernel** 的问题，而不是"某个 Python API 用法
  不对"。这条判断决定你是改调用方式，还是必须绕开这个 kernel / 这个形状。

**复核**：换 CANN / 驱动 / 框架版本后，"多种写法是否仍共享同一 kernel"会变，需重跑一次写法交叉
对照。

## 7 S4 规模阈值扫描：是"固定索引"还是"规模阈值"

固定输入内容，只改**单次调用的规模**（batch / 序列长度），观察坏区起点是否随之改变：

| 观察到的规律 | 结论 | 处置方向 |
|---|---|---|
| 坏区起点随规模变、与内容无关（"最后 N 个"或"某比例之后"） | **规模阈值**：kernel 在大规模下尾部处理有缺陷 | 把调用拆到阈值以下，或分段 |
| 坏区起点固定在某个绝对索引，与总量无关 | **固定索引 / 分块边界**缺陷 | 定位该索引对应的分块参数，改分块或换实现 |
| 只在特定形状 / 特定对齐下坏 | 形状约束 / 对齐缺陷 | 规整形状或走等价实现 |
| 每次运行坏区内容都不同 | **陈旧内存**（缓冲区没被写） | 见 §8 |

骨架见 §16 的 `scripts/op_threshold_sweep.py`。**阈值只写到区间**（未继续二分就如实标注区间），
不要写成确定值。

**复核**：阈值与首坏索引通常是**形状的函数**，换版本 / 换形状后必须重扫，不能按比例外推。

## 8 S5 判定性质：陈旧内存，还是数值漂移

这一步决定你能不能自信地说"这是设备缺陷"。

- **陈旧内存（缓冲区未写入）的指纹**：同一进程内可复现、但**跨运行内容不同**（两次独立运行的
  坏区相关性显著低于 1，而不是接近 1）；同时无 NaN、无异常、形状正确；
- **数值漂移 / 精度不足的指纹**：跨运行高度一致（相关性接近 1），误差随链长 / token 位置平滑
  增长，降精度或改累加顺序会明显改变结果。

**复核**：跨运行相关性必须在**同一环境**下重测；换驱动 / 换 CANN 后该指纹可能消失（缺陷已修）
或变成数值漂移型，两者的处置完全不同。

## 9 S6 规避与修复（三种手法，按代价排序）

1. **等价重写**：用数学等价的另一种写法绕开坏 kernel。**但必须先算内存**——逐轴复制类写法会
   新建整张张量，在显存本就紧张的服务里直接 OOM ⇒ **等价 ≠ 可用**。手段本体归该对象技能的
   优化 / 替换条目，本流程只给判据：先算峰值内存，再决定能不能用。
2. **降到阈值以下**：把单次调用拆成多次（每次规模 ≤ 干净区上限）。简单有效，但要保持语义：
   逐帧 / 逐 token 独立的算子随便拆；有跨帧状态的网络不能乱拆（见下一条）。
3. **状态携带式切片（递归 / 有状态网络专用）**：按**状态更新的自然边界**切段，并把上段末状态传给
   下段；切分点必须落在该网络的合法边界上（例如潜帧边界），且以 CPU 上"整段 vs 分段逐位相等"
   为前提。完整方法、代码模式与前置 / 回退条件见 `vae-opt`
   （`vae-opt/references/sliced-state-decode.md`、`vae-opt/scripts/sliced_state_decode.py`），本流程只引用不复制。

**逐位等价是选段数的前提，不是结果**：段数以现场阈值扫描与 CPU 逐位对拍为准，不要照搬任何历史值。

## 10 S7 修复后的三层回归

- **CPU 逐位**：分段 / 重写与整段参照 `max|d| = 0`；
- **端到端产物**：同窗口多请求 md5 一致（同窗口口径见 `perf-gate`）；
- **健康指标**：坏区消失（§4 的指标恢复到与健康参照同量级）。

## 11 失败模式清单（现象 → 判据 → 复核 → 处置）

**排查时先拿现象对形态，再用该条判据确认，不要凭形态下结论。**

### 11.1 设备 kernel 尾部未写入（陈旧内存）

- **现象**：输出后半段 / 某个索引之后内容错误，形态是"结构消失 + 通道漂移"；无报错、形状正确、
  同进程内可复现。
- **判据**（三条同时成立即可定案）：① 固定输入扫规模，坏区起点**与总量无关、固定在某个绝对索引**；
  ② 存在清晰的规模阈值（干净区与坏区的分界）；③ **跨运行坏区内容不一致**（相关性显著低于 1）
  ⇒ 读到的是残留显存。
- **复核（判定它仍存在）**：换 CANN / 驱动 / kernel 版本或换形状后重跑一次阈值扫描——若首坏索引
  随之移动或坏区消失，旧结论过期；若首坏索引随总量等比移动，则不是本条（转 11.2）。
- **处置**：§9 的三种手法。对象实例（CANN 最近邻上采样大 batch 少写尾部）见
  `vae-opt/references/troubleshooting-cann-upsample.md`。

### 11.2 规模阈值型缺陷

- **现象**：只有"单次调用规模超过某个量"时才坏，坏区总在尾部或某个比例之后。
- **判据**：坏区起点随规模变化且与内容无关；把规模降到阈值以下即恢复干净。
- **复核**：阈值是形状 / 版本的函数，换形状必须重扫。
- **处置**：拆调用（保持语义）或走等价重写；有状态网络走状态携带切片。

### 11.3 递归 / 状态链在设备上的偏差累积

- **现象**：序列越长越差（前段正常、后段退化）；或者**切分方式一变结果就变**。
- **判据**：改变"一次处理多长 / 从哪里切开"会改变结果形态，而在 **CPU 上同样切法却逐位一致**
  ⇒ 是设备执行问题，不是切法本身不合法。
- **复核**：在 CPU 上重做"整段 vs 分段"逐位对拍；相等才说明切分不引入差异。
- **处置**：状态携带式切片（§9 第 3 条）；不要用"重置状态"充当修复——它会改变语义，
  属于另一条假设（见 §12）。

### 11.4 dtype / autocast 假设不成立

- **现象**：想用"精度不够"解释误差，但误差是结构性的（整段塌陷 / 通道翻倍），不像精度损失。
- **判据**：**直接对比开启 / 关闭 autocast 的输出**（逐位比对）；若逐位相同，说明该组合下
  autocast 标注了低精度却没有真正下转，精度假设当场被否。
- **复核**：换版本 / 换 dtype 组合后重跑一次开关对照——"autocast 是否真的下转"是版本相关的。
- **处置**：先证伪精度假设，再查算子 / 形状；确需改精度时改成显式 cast 并重做逐位与质量回归。

### 11.5 门禁盲区：门禁全过，内容仍与真值不符

- **现象**：产物 md5 与基线一致（门禁"通过"），但画质 / 语义与真值明显不符。
- **判据**：当基线与各配置臂用了**同一份**可疑权重 / 解码器时，md5 一致只证明"优化没改变本链
  产物"，**不证明链路忠实**。必须**另设一条独立实现的忠实度对照**（与真值的分块指标 / 相关性 /
  MAE 一类），并逐项核对配置里"看起来一样"的路径参数（权重路径、layout 判定、normalize/scale、
  分块参数）。
- **复核**：换权重 / 解码器 / layout 后重做忠实度对照——旧对照不再代表新链路。
- **处置**：把"解码器 / 权重口径"写进基线口径说明；日志里"不保证复现 stock 解码"一类 WARNING
  要当**强证据**，而不是噪音。

### 11.6 元数据 / 补帧 / 裁剪算术错位（最常被证伪的假设）

- **现象**：怀疑"补帧 / 裁剪 / 分块参数的算术"导致尾段错位。
- **判据（否证方式）**：把该参数显式改成另一种合法取值，看**产物是否变化**；产物不变 ⇒ 该假设
  被证伪，别把它当主因。
- **复核**：先改参数看产物，再读代码——"手算出来的参数值"本身可能就是错的，要以实现实际选中的
  值为准。
- **处置**：证伪后回到 §5 重新找分叉点。

**已由对象技能覆盖、本文件不重写**（避免同一判据两处维护）：

- 集合通信把结果写进副本（`all_gather_into_tensor` 的 `out` 传了栈视图）⇒
  `vae-opt/SKILL.md` 的「已知陷阱清单」；
- 分片参与方式导致的静默错 / 死锁（参与判定必须与 rank 无关、rank 选举式参与的适用边界）⇒ 同上；
- 分片精确性的前置条件与自动修复（`MINLEN` 一类补零阈值）⇒ `vae-opt` 的
  「有损 / 条件性分片」节。

## 12 排除清单（每条假设配一次性排除实验）

写结论时必须逐条给出**实测证据**，而不是"我认为"：

| 假设 | 一次性排除它的实验 |
|---|---|
| 我新加的代码（切片 / 门控 / 并行） | 让所有配置臂的产物 md5 全部一致 |
| 精度（fp16/bf16/autocast） | 开关 autocast 的输出逐帧逐位比对 |
| 输入尾部本身坏 | 用独立实现解码同一输入，看尾部指标是否平滑、有无重复帧 |
| 移植 / 实现细节不同 | 与上游权威实现逐项对拍（算子定义、索引顺序、前处理约定） |
| 状态传递语义（全局 vs 每段重置） | 实现两个变体比对：差异小且**两者都不塌陷** ⇒ 该假设不是主因 |
| 元数据 / 补帧算术 | 改参数看产物是否变化（不变 ⇒ 否） |
| 是不是"内容本来就这样" | 与另一条路径 / 真值的分桶指标对照 |

## 13 反模式（出现任何一条，结论都不成立）

- 只测端到端、不测层内：你会得到一堆相关性，却永远不知道是哪个算子；
- 用"看起来更好 / 更像"下结论：静默错误必须用参照与数字说话；
- 改动一次同时动多个维度（设备 + 精度 + 形状），事后无法归因；
- 把"CPU 也这样"当借口：先确认 CPU 是真值（同权重同输入），再谈"这是模型特性"；
- 修复后不回做逐位回归：绕过坏 kernel 的写法很可能引入数值差异，且会在下游放大；
- 把缺陷写成"偶发 / 玄学"：本类缺陷几乎都能被"**固定索引 + 规模阈值 + 跨运行相关性**"三件套钉死。

## 14 输出与缺陷上报

排查结论按这个结构写（同时也是给 vendor 提缺陷时的最小素材）：

1. 现象与量化指标（含**正常样本的量级**作为对照）；
2. 参照怎么来的（CPU / 独立实现 / 真实输入样本）；
3. 首个分叉点（层 / 块索引 + 相对偏差 + absmax 比）；
4. 隔离后的单算子证据（形状、dtype、阈值表、首个坏索引）；
5. 性质判定（陈旧内存 vs 数值漂移，附跨运行相关性）；
6. 已排除的假设及各自的实测证据；
7. 规避 / 修复方案与三层回归结果；
8. 影响面（哪些历史产物 / 哪条路径受影响，为什么以前没暴露）。

**上报给 vendor 前的三条硬判据**：① 最小复现（同输入、同形状、可比对参照，脚本可独立运行、
无私有依赖）；② 规模阈值表（**只写区间**，未二分就如实标注）；③ 首个坏索引 + 跨运行相关性
（区分陈旧内存与数值漂移）。诉求写"完整写入或显式报错"，不要接受"静默返回未初始化内容"。

**证据卡三件套**（缺一件别人无法复核、也无法判断何时过期）：

1. **口径**：哪台机器、什么形状 / 步数、哪个时间窗口、哪份权重与解码器；
2. **判据**：多大差异算成立、噪声地板是多少、阈值二分到哪个区间；
3. **失效信号**：出现什么现象就说明这条结论不再适用。

## 15 复核触发：什么变了就必须重跑

判据是稳定的，**观测值不是**。下表任一条改变，旧结论即过期：

| 会变的轴 | 为什么会推翻旧结论 | 重测方式 |
|---|---|---|
| 硬件 / 驱动 / CANN 或框架版本 / kernel 实现 | 阈值、首坏索引、数值路径都可能随实现改变 | 重跑阈值扫描 + 逐层打点 |
| 模型 / 形状 / 序列长度 / 分块参数 | 阈值与首坏索引通常是形状的函数，不能按比例外推 | 用真实形状重扫 |
| 布局 / dtype / 自动混合精度是否真的生效 | "autocast 没下转"这类观察是版本相关的 | 开关对照一次（逐位比对） |
| 并行拓扑与卡数 | 参与方式、交换量、状态边界都会变 | 重做独立性审计与预算核算 |
| 窗口 / 邻居负载 / 共享机器 | 绝对值漂移可能大于收益本身 | 同窗 A/B（必要时 A/B/A 校正） |
| 权重 / 解码器 / 预处理约定 | 同一道门禁下语义可能完全不同 | 与独立真值做忠实度对照 |
| 用户裁决（某参数冻结、某档不采用） | 这是**决策**，不是技术结论 | 记录裁决与出处，不写成"更快 / 更好" |
