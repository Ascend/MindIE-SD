# 方法：融合候选的识别与误判排除

> **位置**：在**开始找融合点之前**、以及 **profile 归因出现「看不到的成本」时**用本文件，把候选清单先过一遍
> 「真假筛」，再交给 `fusion-unit-method.md`（边界怎么画）与 `fusion-benefit-method.md`（值不值得做）。
> 本文件只写**识别与排除的判据 + 现场取数方式**，不复制上述两文件的规则；三者冲突时以它们为准，
> 阈值与噪声地板只引 `../../perf-gate/SKILL.md`，等价性分层只引 `../../accuracy-gate/SKILL.md`。
> **数字纪律**：正文只写量级、比例与排序，不写绝对耗时/计数/质量分值；任何"本组合观测"结论都必须**本地重测**后沿用。

| 阶段 | 文件 |

## 1. 候选来源与「同一 seam 竞争」

**候选清单的四个来源**（少一个就会漏掉一整类机会）：

1. **profile 热算子 / 搬运链**：`kernel_details.csv` 里成规模的 copy / cast / 布局算子链；
2. **上游候选**：`profiling-analyze` 的融合机会候选（本技能接它做结构侧与收益判定）；
3. **代码结构**：定义在同一函数 / 同一模块 / 同一子图内的算子组（`fusion-unit-method.md` 规则 1）；
4. **非算子视图的成本**：launch 计数、设备流同步、host 侧下发 —— **这类成本在逐算子视图里可能为零**（§2.1）。

**seam（接缝）定义**：候选要消除的**那一处**边界 —— 一次中间态 GM 往返、一次设备流同步、一次额外下发。
**两个候选「争同一处」 ⟺ 它们消除的是同一个 seam（或 A 的产/消对象正是 B 的目标算子）。**

- **判据（事前 · 站点重叠分析）**：把每个候选的目标站点（被删掉的算子实例：名字 + 形状 + 次数）列成集合，
  交集非空即视为**竞争**；若 A 删掉了 B 的绝大多数目标站点，B 只剩**残余价值**，必须按组合测而不是并列各测。
- **判据（事后 · 唯一能作数的）**：**关掉 A，看 B 的收益是否变化** —— 逐臂 + 组合臂，同窗、同脚本、唯一变量 = 是否开该候选；
  若 `(A+B) − A` 明显小于 `B 单独`，竞争成立；两者接近则两候选**独立可连乘**。
- **单卡复算**：单卡 ABBA（分区、每臂多轮、先量 A/A 地板，负样本须被检出）给出**每站点**收益与**站点数**，
  再用"该候选删掉了多少个站点"复算组合收益。单卡数字只作**站点级投影**，
  **不得直接当模型级收益**（口径不可换算是 `fusion-benefit-method.md` §6 的硬纪律）。
- **纪律**：**竞争者的收益不可相加** —— 交付表里并列各自独立值就是高估。
  规则本体与不可相加的实测记录单点在 `../SKILL.md`「候选争用同一站点：禁止把单项收益相加」节；
  本文件只补"如何提前判定两个候选争同一处"，不重复其数据。
- **陷阱（须复核）**：继承来的对拍脚本常把**不同 pipeline stage 的张量**当同一对象比
  （一侧取融合前的输入侧、另一侧取融合后的输出侧），于是报出"逐位不等 / 大比例差异"的**假阴性**，
  把逐位精确的候选挡在门外。
  **如何判定它仍存在**：对拍两侧各打印被比张量的**语义位置**（由谁产生、位于哪一步的边界），两者必须同 stage；
  再把其中一侧换成**同 stage 的等价量**，若差异归零 ⇒ 原判为假阴性，必须作废。

## 2. profile 找 copy/cast 的三类误判

> 前提：**逐算子 profile 是「被调度的设备工作量」的视图，不是「这次调用花了多少墙钟」的视图。**

### 2.1 设备流同步在 profile 里看不到（成本真实存在，逐算子视图为零）

- **机理**：数据相关的**强制写入 / 索引赋值 / 设备取值**会在调用内插入**整流通（stream synchronisation）**；
  整流通**不占任何算子的耗时**，也不计入算子实例，因此在逐算子视图里"不存在"。
- **后果（两条，方向相反）**：① **高估**这类 site 的成本（你以为算子贵，其实贵的是同步）；
  ② **错认已不存在的算子**（按 profile 逐算子找 copy/cast，会把已被消掉的算子、或已被别处吸收的成本继续当成优化对象）。
- **判定方法（现场取数）**：
  1. **单卡 microbench 复算该 site 的真实 wall**：把**同一个调用**分别在 (a) wall 口径（含同步）与
     (b) 纯 device 事件口径下测，差值即同步/整流通成本；再把该调用重复多次，看 wall 是否随**调用次数**线性增长
     而 device 时间不动；
  2. **对照写法**：把该处的数据相关强写改成**预计算向量 + 广播 OR**一类无数据相关索引的写法，重测同一 wall 口径；
     若 wall 显著下降而 device 视图几乎不动 ⇒ 确认成本在同步侧；
  3. 同步成本**不进** `fusion-benefit-method.md` 的 L1 理论列（该列只有访存/计算两侧）⇒ 这类 site 的收益必须用
     **wall 口径单独量**，不要指望理论列覆盖它。
- **复核**：换版本 / 换算子实现后重跑第 1 步（该实现可能已不再插入整流通）；wall 与 device 的差值落到噪声内 ⇒ 本条作废。

### 2.2 算子已被融合后，名字仍留在旧路径

- **机理**：profile 里的算子签名由**当前实际走的路径**产生；旧路径的实现（旧 kernel 家族、被回退的入口、
  默认关闭的开关分支）仍留在代码里 ⇒ **"名字在" ≠ "被调用"**。反方向同样成立：
  **看起来已启用的开关也可能在编译后被消除（inert）**，于是"改了配置但结果不变"。
- **判定方法**：
  1. **两臂 op census 差**：把相关门控 **OFF / ON 各采一次单步 profile**，按 `(算子名, 输入形状)` 对账 ——
     融合体签名应在 ON 臂出现、在 OFF 臂**成规模**出现；若只在一边出现一次、或只降几个百分点，说明被别处吸收或根本没命中，
     **归属判错**（生效观测量的完整判读顺序见 `../../profiling-analyze/references/performance-analysis-methodology.md` §3.3）；
  2. **按当前树核事实，不按记忆**：`grep` 该算子名 / 开关名在**当前树**的引用，确认它是否仍在生效路径上；
     对"看起来已启用却无效果"的开关，用**编译后中间产物或最小 probe**确认它是否被消除
     （lowering 侧的 inert 形态与判定法见 `../../operator-dev/references/triton-ascend-lowering-pitfalls.md`）；
  3. **复核**：每次换版本 / 换树后重跑第 1 步；当 OFF 臂已不再出现该签名，则"某算子已被融合"这一前提过期，须重判其收益。

### 2.3 惰性 cast / round-trip 可能是语义所在（位置即语义）

- **机理**：`x.to(dtype)` 这类往返 cast **不一定只是布局或精度转换** —— 当它决定"**在何处做一次舍入**"时，
  **它就是语义的一部分**：把它与相邻算子融掉、或把舍入从"存储侧"挪到"权重/计算侧"，结果会**静默改变**
  （差异可达整张量的一大部分），且不报任何错。**同一个开关名在两个算子里也可能意味着不同的数学**
  （一个在存储侧舍入、一个在加权侧舍入）⇒ 照抄兄弟算子的写法同样会静默改结果。
- **判定方法**：
  1. **关掉 / 改写该融合，做 L1 逐位对比**（判据是 `torch.equal` / 逐字节，不是看指标）；
  2. **必须在最终 dtype 上比**：中间量的位级差异可能被**末级舍入吸收**（量化链路尤其如此，见
     `../quantization-dev/SKILL.md` §四·B.1 结论 3）⇒ 在中间 dtype 上判"有差异"会得出假阳，
     在**最终 dtype** 上判"无差异"才是可用依据；反之若最终 dtype 上仍有差异，则不得声称无损；
  3. **对照写法**：把 cast 放回**同族兄弟算子**的位置再比一次；若差异从"大面积"缩到"个位数百分比 / 单 ulp 量级"，
     即证明"位置即语义"在本处成立（bf16 舍入在 lowering 侧被静默消除的形态见 `../quantization-dev/SKILL.md` §3.2）；
  4. **复核**：换版本后重跑第 1/2 步；若新版本编译器已能正确保留该 cast，则相关绕行作废、**整条删除**。

## 3. 闸门旁路会静默丢功能

- **机理**：门控快路径（early-return 到融合实现）绕过的不只是耗时，**还可能绕过适配器 / hook / 包装层**：
  前向直接驱动底层算子，被包装模块的 `apply()` / hook 根本不执行，而**权重早已绑定成功** ⇒
  校验器与日志都不报错，只是结果少了一部分功能。
- **判定法（强制）**：**开闸门与关闸门做 L1 逐位对比**（同窗、同脚本、同请求），**不是只看加速比**：
  - 逐位不同 ⇒ 该闸门改变了语义，必须先回答"少了什么"——用**可观测副作用**当探针：被包装链的算子签名是否出现、
    该模块的参数是否真被消费、checkpoint 里对应 key 是否被读取；
  - 逐位相同 ⇒ 旁路无副作用，可放心启用。
- **本组合观测（比例，须本地重测）**：这类旁路把**同一根开关**下的收益与丢失的功能绑在一起 ——
  融合本身的收益是**个位数百分点**量级，而被旁路吞掉的功能代价**高一个数量级** ⇒
  "用功能换速度"必须显式计入收益账并写进交付表，不得静默。
- **复核**：换版本后重跑"OFF vs ON 逐位对比 + 两侧 op census"；若包装层已改为在融合路径内也生效，则该陷阱作废
  ——但**逐位对比本身保留为常设检查**（它是唯一能发现"静默丢功能"的仪器）。

## 4. 候选的预注册与分级

**动手前先写四件事**（未写不得开工；写完再改就是事后调参）：

| 项 | 内容 |
|---|---|
| 预期收益 | 量级/约数 **+ 口径**（站点级 / 块级 / 模型级，三者互不可换算） |
| 判定方法 | 用哪个口径量、哪一臂做对照、A/A 地板怎么取、负样本是什么 |
| 等价性等级 | **L1 逐位**（`torch.equal` / 逐字节 100%）或 **L2 数值门**（差异占比 + 相对张量峰值的量级 + 最坏 ulp 及其尾部） |
| 控制臂与负样本 | 至少一条**已知会失败**的对照；负样本被检出，才证明仪器有效 |

- 分层定义、`"极小"仍不是逐位` 的铁律与阈值判读见 `../../accuracy-gate/references/equivalence-criteria.md`（本文件不复述）。
- **L2 必须报三元组**：差异**占比**、差异**相对张量峰值的量级**、**最坏 ulp 及其尾部**；
  只报"1 ulp"、或以均值代表整体，都属不合格表述（尾部与绝对最坏元素常**不是同一个**）。
- **排序固定**：先证**等价性 / 正确性**（不达标的候选无论多快一律淘汰），再比收益；
  收益比较按 `../../perf-gate/SKILL.md` 的同窗 A/B 与噪声地板，跨窗绝对值不可比。

## 5. 一次性缺陷不得固化成结构

- **规则**：为绕过一次性缺陷（编译器行为、版本缺陷、未合入的补丁）而引入的绕行，必须**可一键关闭、可整块删除**：
  走**一个开关**（默认关）、单一回退路径；**不长期分裂代码路径、不写兼容 shim**。
- **每条记录必须带「如何判定它仍存在」**：一条探针 / 一条 `grep` / 一个最小复现；**先复核、再套用绕行**；
  升级软件栈或硬件后逐条复核，**不再复现的整块删除**（留着已修复的条目会制造假结论与无谓绕行）。
- **复核方法（通用形态）**：① 读该绕行的默认值与环境变量读取点，确认当前默认是否仍为关；
  ② 关掉它跑一次同窗 A/B 与 L1 逐位对比，确认关掉后行为**回退到基线**（说明它仍在生效路径上）；
  ③ 若"关掉"与"开着"逐位相同且耗时无差 ⇒ 它已无用，删除。
- **判定"仍在生效路径上"的探针要为它单独留一条**（不要依赖"我觉得还开着"）；
  一次性实验的**结果**（负收益、被证伪）应记录，但**载体**（临时补丁、探针脚本、分块实现）不得留在交付结构里。

## 维护与更新

- **更新触发**：出现新的锚点或新的候选来源；profile 归因工具/口径变化（逐算子视图的定义变化）；
  引入新的门控快路径（新的 early-return 分支）；`fusion-unit-method.md` 的规则变化（冲突以它为准）。
- **必做复核（本文件的结论有寿命）**：§2.1「逐算子视图看不到同步」、§2.2 的 inert 形态、
  §2.3「位置即语义」、§3「闸门旁路丢功能」—— 每条都要用文件内给出的判定法在**当前版本**复跑一次；
  不再复现的条目**删除**，不留"以防万一"。
- 本文件只写判据与辨识方法；实测读数、设备/模型/版本取值、产物坐标与个案细节留会话产物与对应 case 记录，不进本文件。
