# 方法：融合收益前置评估

> 目的：**写 kernel 之前**判定"值不值得做"，避免把机时投进注定不可达的单元。
> 输入同上（执行序 + 计算单元利用率）。阈值与噪声地板**只引用** `perf-gate`，本文件不另立一套；
> 数字纪律：不写绝对耗时与绝对质量分值，只写量级/约数与比值判据。

## 1. 判型：先看"收益来自哪一类"，再看总时间

主指标用官方字段 **`memory_bound = mte2_ratio / max(mac_ratio, vec_ratio)`**（PipeUtilization 档）：

| 判型 | 观测量 | 结论与唯一有效方向 |
|---|---|---|
| **MTE 饱和** | `memory_bound > 1`，`*_mte2_ratio` / `*_mte3_ratio` 高，`*_vec_ratio ≈ 0` | **值得建单元**——收益来自**减少/合并搬运**（含尾块处理） |
| **向量饱和** | `*_vec_ratio` 高，`*_mte2_ratio ≈ 0`，`memory_bound < 1` | **不值得**——"喂更少数据 / 融更多东西"**不会移动它** |
| **向量约束的单 pass** | `*_vec_ratio` 高但内存余量充足 | 值得，但收益上限在**向量侧** |
| **标量 / 延迟串行受限**（第三类，**判型公式看不到**） | **检测器见下**；`memory_bound ≈ 0` 且 `aiv_scalar_ratio` 高 | **值得**——收益既不来自搬运也不来自向量数学，而是**去掉每 program 的固定/标量成本与串行等待**。**"向量饱和"会把它误判成不值得** |

### 1.1 第三类「标量 / per-program 固定成本受限」的**检测器**（辨识侧必做）

判型公式只看 `mte2 / max(mac, vec)`，**标量工作与 per-program 固定成本不在其中**。所以**在这四步走完之前，
不得因为判成"向量饱和"就否决一个核**：

| 步 | 看什么 | 判据 |
|---|---|---|
| **D1** | `aiv_scalar_ratio` vs `aiv_vec_ratio` | 标量占比**可与向量相比**（相对量，具体阈值随算子而定）⇒ 可疑。**`aiv_vec_time` 占 `Duration` <2% 时必须报 `n/a`**——纯拷贝/聚集类核 `aiv_vec_time = 0`，比值无意义，放一个天文数字进表只会误导 |
| **D2** | **`Block Num`（program 数）** vs 设备计算单元数 | program 数**远超**计算单元数 ⇒ 每个 program 的固定成本被放大。**本类最可靠的单一指标；D2 ≈ 1（每核一个 program）即无空间** |
| **D3** | `duration` 与「各管线忙时间之和」之差 | 差为**正且显著**（>0，未重叠）⇒ 存在串行/等待结构。⚠️ **对本类常常失效**：在**已确认为 program 数受限**的核上 `aiv_time ≈ Duration`（缺口在噪声内）⇒ **D3 会漏报** |
| **D4** | **判别实验**：把同一个核改成"**更少更胖的 program**"（`grid=(1,H)` + 每 program 内循环）重测 | **变快** ⇒ 确认为 program 数受限（本类）。**这是唯一的确证手段，D1–D3 只是筛选。** |

> **指标可靠性（实测口径：ABBA + 逐字节对照 + 负控）**：
> **D2 是决定性指标**；**D3 对本类会漏**（见上表）；**D1 单独用会误报**——
> 一个已经每核只跑 1 个 program 的核（`SwiGlu`）同样能让 D1 落在可疑区。
> ⇒ 用法固定为 **D2 先筛 + D1 作旁证 + D4 定论**，**禁止拿 D1 单独下结论**。
>
> **确证后的机理签名**（用来判断"真的修对了"，而不只看耗时）——**先分清是哪一种**：
>
> - **A 重叠型**：`aiv_scalar` **显著塌陷**、`aiv_vec` **基本不变**、
>   **各管线忙时间之和 `Σpipes` 保持常量**、而 `Duration` 下降 ⇒ 管线从**串行**变成**重叠**
>   （读数见 `{run_results_dir}/archive/`）。
>   **这类核是「被每 program 的标量/启动开销串行化」，不是"向量算力不够"**；
>   profile 里的 `aiv_vec_ratio` 读出来像余量，**但那个余量不可用**。
> - **B 算量下降型**：**`Σpipes` 本身显著下降**（各核降幅可达**数十个百分点**），
>   且 `aiv_vec` 同步下降 ⇒ 胖 program 让**每个元素少做了事**，不只是少付启动费。
>   **恢复率可显著超过固定占比**（倍数见 `{run_results_dir}/archive/`）。
>
> **⇒ 判别方法**：两臂各取一次 profile，比较 **`Σpipes`** 与 **`Duration`**。
> `Σpipes` 不变 ⇒ A 型（可用"恢复率 ≈ 固定占比"预测）；`Σpipes` 下降 ⇒ B 型（**只能实测**，
> 不要用固定占比外推）。**两种都真，但别把 A 型的预测公式套到 B 型上**（本仓把 A 型公式套到 B 型，
> 一个投影高估了 2.3×）。
>
> **恢复率 ≈ 该核的固定成本占比**这句话**只对 A 型成立**（作用域见上一条；B 型不适用）：
> 因此**必须逐核实测固定占比，不能套用统一百分比**。本仓实测：恢复率与固定成本占比在**同量级**
> 且高度接近（±1pp 内）⇒ 公式可用，但**必须逐核实测**。
>
> **口径换算警告**：把"恢复**百分比**"乘到**另一套仪器的耗时份额**上会系统性偏大——
> 本仓曾因此把一个投影明显高估（profile 的逐算子绝对值会被同卡并发系统性抬高，量级为
> **百分之十几到二十**；**本组合观测，须本地重测**）。
> 正确换算是 **绝对恢复量 × 每步调用次数**。
>
> **实测反例（本仓）**：一个 `aiv_vec_ratio` 看起来余量充足、`memory_bound` 为 0 的量化核，按前两类
> 判型会得到"向量饱和 ⇒ 不值得"；D1–D3 显示标量占比与 per-program 固定成本各占该核的**两位数百分点**；
> D4 确认后改写（更少更胖的 program + **并发在飞装载**）⇒ **耗时显著下降、有效带宽成量级级抬升、
> 逐字节等价**（读数见 `{run_results_dir}/archive/`）。
> 修法本身（per-program 成本拟合、preload vs unroll 的分辨）见 `../../operator-dev/`。
>
> **另一个反直觉点**：本类里**软件流水常常无效** —— 实测 `num_stages` 1/2/3 给出完全相同的耗时，
> 而把同一段 unroll 改成**先把多个 load 发满在飞、再统一计算**（preload）才有收益。
> ⇒ **"流水/多缓冲没效果"不能推出"这个核没有空间"**，要换 preload 形式再试。

辅助量：`cube_utilization(%)`（是否已到屋顶线）、`*_time(us)`（与 ratio 互校）。
**否决规则**：判为**向量饱和**且不变更向量侧工作量 ⇒ 直接否决，不再进入收益估算；
**但该否决必须先过 §1.1 的 D1–D4**——第三类被误判成"向量饱和"是本技能已知的假阴性来源。
（判型的实测对照与硬件常量留在实现侧笔记，本文件只写判据。）

## 2. 三条收益前置判据

1. **带宽下限**：`(读字节 + 写字节) / 实测有效带宽` = 该段的**理论最小耗时**。
   若目标区当前耗时已接近该下限 ⇒ 上限本身已越天花板，判**不可达**。
2. **区域占比**：目标区在阶段/端到端里的占比决定**收益上限**（占比是个位数百分点量级时，
   再怎么做也只是这个量级）。
3. **天花板法**：设问"若目标区耗时降到 0 会怎样"——上限若只有很小一档，**直接判不可达**，
   省掉整轮实现与验证。

## 3. 传导判据：什么能传导到阶段级

- **移除 DRAM 流量 / matmul 结构开销的改动可以 1:1 传导**；
- **纯 kernel 延迟改进可能被流水线吸收**（站点级读数明显改善而阶段级不动）；
- 因此"站点约 2 倍"之类只是**必要不充分**证据，不能作为交付依据；
- 分类动作在**写内核之前**完成：先判"这条改动属于哪一类"，**纯延迟型要格外警惕**。

## 4. 地板先行：上限低于地板就关项

顺序固定为：**估效应上限 → 与本地板比 → 上限低于地板 ⇒ 直接关项（不投入）**。

- 措辞纪律：预测效应落在噪声地板量级（约 1.5σ 内）⇒ 报**"不可分辨"**，**不得**报"没帮助"；
- 地板随环境漂移，换拓扑 / 形状 / 窗口必须**重测地板**后再下结论（同窗内自带基线）。

## 5. Amdahl 不变性：用它校验测量本身

只移除**与序列长度成正比的流量**、且主导核耗时也成正比的改动，在不同时长档上的**百分比应当相同**。

- 百分比一致 ⇒ 因果成立；
- 百分比随规模衰减 ⇒ 必须给出**非比例机制**（如结构开销在大规模下摊销更好），否则视为测量或归因有问题。

## 6. 口径纪律

- **per-site / per-block / 模型级三种口径严格不可比**（旧链按 profile 多 kernel 求和 vs 新核
  standalone 计时含 launch），不得互相换算；
- **共享算子的份额必须"按形状"取，不得按平均**：同一个算子名下不同 shape 变体的单位成本可以差**数倍**
  （本仓实测：同一个 `GatherV2` 的 `13640,56,128` 形态为 **272 µs/次**，是全部同类调用平均 **39.3 µs 的 6.9 倍**）
  ⇒ 把共享 op 当作某个区域的一部分时，**先按 shape 过滤出属于该区域的行再求和**，用平均值会同时高估别处、低估此处；
- 事前评估用区域/site 口径即可，**最终结论以模型级 A/B 为准**，判据与噪声门引 `../../perf-gate/SKILL.md`；
- 跨配置比较前先确认分母定义一致（分母不同则结论作废，见报表口径）；
- **不要从跨零的点估计里挑有利符号**：同一组读数下 median 与 mean 可能**符号相反**，按有利符号取结论
  等于自欺——先看符号稳定性，再谈幅度。

## 7. 输出格式（交给上游调度）

| 列 | 内容 |
|---|---|
| 融合机会点 | 区域坐标（起止算子）+ 建议单元构成（首算子、包裹范围） |
| 判型 | MTE 饱和 / 向量饱和 / 单 pass（含 `memory_bound` 读数与来源文件列） |
| 收益量级 | 大致加速比或降幅（约数/量级），**不写绝对耗时**；并注明口径 |
| 结论 | 建议做 / 不建议做（**含否决理由**，如"向量饱和""上限越天花板""Σvec ≥ Cube"） |

## 8. 失效信号

- 判型读数缺失或为 `N/A` ⇒ **不得**用其他字段臆测：先用采集完成检查门禁
  `python ../../profiling-collect/scripts/check_output.py --dir {ASCEND_PROFILER_OUTPUT}` 判该次采集
  **不合格**，再按其提示带 `--task-time=l1 --aic-mode=task-based --aic-metrics=PipeUtilization` 重采；
  **把 `N/A` 当 0、或凭执行序臆测判型，都属静默失败**（补采通过前不得给收益结论）；
- 换设备代际 / 换形状 / 换窗口 ⇒ 地板与带宽下限必须重测；
- 有损档叠加后复核：被吸收的向量工作量可能已被量化改写（序列变化即重判）；
- **片上资源预算（硬容量）没算过就下了"值得做"的结论** ⇒ 该收益结论作废，先补算再重判。
  判据与两行算术单点在 `../../operator-dev/references/catlass-ffn-fusion-guide.md` §2.1：
  融合常要求"两份中间结果同时留片上"（两个累加器）或"某操作数常驻"（A 留 L1）⇒ 受**片上硬容量**
  约束，须按**目标代际的容量现场取值**先算再判；本仓实测两例都是**方案在容量上就不存在**
  （两份 fp32 累加器把片上容量占满、无余量；操作数足迹超过 L1 容量）。
  ⇒ 收益与边界判定必须先过这一关：**"值得做"不等于"做得出来"**，容量不过的方案不进交付表。

## 9. 两级收益口径：L0 快速上界 → L1 理论锚定

**L0（默认，用于排序取舍）**：搬运消除上界——Σ(种子的写回 `mte3` + 其消费方读入 `mte2`)，上界以该段自身
耗时为封顶，区间取下界 = 0.5×、上界 = 1.0×。它是**乐观估计**，未扣融合核自身开销，也不含物理下限，
**只能用于初筛**。

**L1（要下结论时，用理论列锚定）**：把 `duration − theoretical` 当作**该算子的可回收量**，而不是"搬运算子的耗时"。
理论列由本技能自产：`scripts/theory_columns.py` 逐算子按「字节 ÷ 实测有效带宽、FLOPs ÷ 实测峰值算力」计算，
**峰值口径（带宽 / 算力）必须由使用者给出，缺参数即拒算——不得编造默认值**。字段契约：

| 字段 | 用途 |
|---|---|
| `theoretical_memory_time_us` / `theoretical_compute_time_us` | 访存 / 计算两侧理论耗时 → 与第 1 节 `memory_bound` 判型**交叉校验**（不一致先查理论列是否 supported） |
| `theoretical_operator_time_us` | 该算子理论最小耗时（取两侧较大者量级） |
| `fixed_overhead_us` | **固定开销**（launch / 调度一类）→ 用于**对抵**：融合核自身新增的固定开销从这里减 |
| `bound_type` | 受限类型（算力 / 访存）→ 决定"该不该融"的方向 |
| `duration_over_theoretical` | 实测 ÷ 理论。**≈1 ⇒ 该算子无空间**（此时即便 `vec < mte` 也判无收益）；差值部分才是可回收量 |
| `theory_supported` | `false` ⇒ **不得编造理论值**，退化回 L0 并在交付表说明列标注 |

**L1 的收益式**：

```text
单元可回收量 ≈ Σ(成员 duration − theoretical_operator_time)  −  Σ(新增 fixed_overhead)
收益预期   = 可回收量 / denom（denom 同第 1 节：块内计算主流耗时和）
```

**关键纪律**：

1. **只在关键流（critical stream）上核算**：多流时按"观测时间线并集最大"的流取值，其余流视为被覆盖 /
   旁路（与规则 2b 的通信判据一致）；若第二大流的并集 ≥ 最大流的 80%，标 `review` 并复核选流；
2. **`duration_over_theoretical ≈ 1` 的成员不计入可回收量**（已在物理下限上，融合不会更快）；
3. L1 与 L0 的差异必须可见：交付表说明列注明口径（`L0` / `L1`），两者混用即视为不合格；
4. **覆盖有限，须报未锚定占比**：理论列只对有静态 shape 且 shape / dtype 列完整的算子产出；动态或符号
   shape、缺列、以及 `duration < theoretical`（估算不成立）的算子一律 `theory_supported=false`。
   未锚定的那部分常包含耗时最大的一批（集合通信、注意力类）⇒ 交付表说明列须写明未锚定占比，
   不得用被锚定的少数行代表整段收益；
5. L1 仍不是验收：采纳前按 `perf-gate` 同窗 A/B（[探索] → 验收态）。

**失效信号（判档复用纪律）**：kernel 集合变化 / anchor 数偏差 / shape 分布漂移 ⇒ 分别对应小改 / 中改 / 大改，
决定理论列与单元结论要**全量重算还是增量复核**。

## 10. 事后复核：实测收益不及预期时的归因与升级

> §1–§9 回答"**值不值得做**"（事前）；本节回答"**已经做了、实测收益却不及预期**时，
> 那个不及预期能不能作为结论"。适用范围以「matmul + 激活 epilogue + 输出量化」型融合
> （`mm_swiglu_mxquant` / `mm_gelu_mxquant` 族）为代表，判据本身与具体算子无关。
>
> **总纪律：收益打平或为负不是一个结论，而是一个待归因的观测。** 未完成 §10.1 的**等功对照**之前，
> 不得把"该融合无收益"写成结构性结论，也不得据此关闭该项。

### 10.1 四步归因（顺序固定，不可跳步）

0. **先排除"是测量在骗你"**：**整模 profile 的逐算子绝对耗时会被同卡并发系统性地抬高**
   （本仓实测：幅度可达**百分之十几**，且是**整步性**的——同一 profile 里共跑的其他算子会按各自
   比例一起抬高）。
   所以"实测收益不及预期"的**第一步**不是怀疑核，而是：**把被测核放回隔离/单卡测量，
   与 profile 值做比值**。比值≈1 ⇒ profile 值可信，继续第 1 步；比值明显 >1 ⇒
   **先按并发抬高扣除**，否则会把测量误差当成 kernel 缺陷去修（或反过来把真缺陷解释成测量误差）。
   判据与口径引 `../../perf-gate/references/measurement-discipline.md` §7.4。

1. **关键流核对（先排除"根本不在关键路径上"）**：融合成员与被它替换的算子是否都在**关键流**上？
   判据：该流 `Σ(duration)` 与流并集之比 ≈ 1，且成员的**跨流重叠比 ≈ 0**（判据同 §9 关键纪律 1 与
   构造规则 2b 的通信重叠判据）。
   - 成员本就被隐藏（重叠比显著 > 0）⇒ **收益上界本来就是 0**，这是**解释**，不是缺陷，到此为止；
   - 成员确实暴露 ⇒ 进第 2 步。
2. **等功对照（核心判据）**：把**融合核自身**与被它替换的算子放在**同一工作量**下比较。
   工作量必须显式给出并核对：乘加类按 `M×N×K` 的 MAC 数；纯搬运类按读写字节数。
   **比较对象是"忙计数"，不是墙钟**：
   - 核芯忙计数（MAC 流水线忙时间，如 `aic_mac_time`；及 `cube_utilization(%)` 互校）；
   - 搬运忙计数（L1 装载，如 `aic_mte2_time` / `*_mte2_ratio`）；
   - **epilogue 增量 = `duration − 核芯忙计数`**，即融合核自身**非核芯**的那部分。
3. **判决**：

| 观测（等功下） | 判决 | 动作 |
|---|---|---|
| 核芯忙计数 ≈ 被替换算子（噪声内），且 epilogue 增量 ≈ Σ(被吸收的独立 epilogue 核) | **结构性受限**：收益上界本来就这么小 | 记录上界后关闭该项；**措辞不得**写成"融合无效" |
| **核芯忙计数 > 被替换算子** | **缺陷在融合核自身** —— 是**实现问题，不是结构问题** | **升级 `operator-dev` 深入分析** |
| epilogue 增量 > Σ(被吸收的独立 epilogue 核) | epilogue 写法是缺陷 | **升级 `operator-dev`** |

**升级时必须一并给出"可操作上界"**（先算再决定投不投入）：

```text
可操作上界 = Σ(被吸收成员各自的忙计数 + 各自独立 epilogue) − (被替换核芯忙计数 + 融合核实测 epilogue 增量)
```

即"若融合核的核芯效率达到被替换算子的水平、同时保留其**实测** epilogue 增量"能拿回多少。
**这个数才是该项的真实目标**，而不是"被吸收成员的墙钟之和"。

### 10.2 必带的对照（缺一即结论作废）

- **未触碰算子的同窗负对照**：取一个本次改动**不涉及**的邻近算子，确认它同窗为平。
  它若随之变慢 ⇒ 变因不是融合本身，按下一行走。
- **频率 vs 停顿判别**：邻近算子**在管道占比不变的前提下**变慢 ⇒ **时钟/频率效应**（功耗/温度）。
  这部分**不可由算子侧修掉**，必须单独报账，**不得计入融合的收益/亏损**。
- **等功算术必须写进结论**：调用次数 × 形状与被替换侧闭合才成立；不闭合即该对照无效，重做。

### 10.3 融合 GEMM + epilogue 核的头号嫌疑类（源码可查，可迁移）

- **输出被拆半、归约轴跑两遍**：把输出沿 N 拆成两半（如 act 半 / gate 半）各自发起一次核芯循环
  ⇒ 同一归约轴被走两遍、操作数装载重复 ⇒ **搬运忙计数与核芯占用双双上升**。**先查这一条。**
- **tile 形状被累加器共存挤小**：两个累加器要同时在累加存储（L0C 一类）里共存 ⇒ tile 被迫取小。
  这是**资源约束**；必须区分"资源约束"与"调度选择"，两者修法完全不同。
- **操作数复用未跨拆半共享**：拆半之后 A 操作数是否仍只装载一次。

### 10.4 升级契约（交给 `operator-dev` 的最小集）

等功算术 · 核芯/搬运忙计数对照表 · epilogue 增量 · 同窗负对照与频率判定 · 关键流与重叠结论 ·
源码侧嫌疑类与定位 · **重算后的可操作上界**。缺任一项，`operator-dev` 只能重新采集，等于返工。
