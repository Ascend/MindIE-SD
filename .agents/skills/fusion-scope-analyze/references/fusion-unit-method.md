# 方法：融合单元构造与边界判定

> 输入 = 模型**代码** + profiling **算子执行序**（`kernel_details.csv`：`Name` / `Start Time(us)` /
> `Duration(us)` / `Task Type`）。本文件只给**结构性判据**（能不能成一个单元、边界画在哪）；
> 值不值得做见 `fusion-benefit-method.md`。
> **本文件是通用方法：不写模型名 / 框架名 / 具体算子名**——判据只依赖三类可观测量
> （代码结构、执行序、计算单元利用率），模型与框架专有的事实一律放在文末「案例指针」。

## 1. 术语与记号

| 记号 | 含义 |
|---|---|
| **种子** | 满足 `vec < mte`（搬运受限、有搬运可省）的算子 ⇒ 融合入口 |
| **成员** | 与种子融合的算子集合（按逻辑相邻，见规则 0） |
| **单元** | 一个候选融合体（对应一个融合 kernel / pattern 替换体） |
| **区域** | 执行序中按锚点切出的一段连续算子序列（**仅作分析视角**） |
| **锚点** | 不可被吸收、也不可被跨越的算子族（规则 2） |
| **Cube / Vec 算子** | `Task Type` 呈 `AI_CORE`（含 `MIX_AIC`）/ `AI_VECTOR_CORE` 的算子 |
| **规范族** | 语义上有标准形态、常被拆成多个小算子的算子族（归一化、位置编码、激活…） |

## 2. 规则（按顺序应用）

### 规则 0：种子（入口）与配对（逻辑相邻）

- **入口判据**：任一 kernel 满足 `aiv_vec_ratio < max(aic_mte2_ratio, aiv_mte2_ratio)`（**`vec < mte`**）
  ⇒ **它本身就需要融合**（种子）。**只要有 1 个有收益成员，即可判定该融合有收益**，不要求整段都满足判据。
- **配对判据**：与种子融合的是**逻辑上相邻**的算子（数据流 / 语义依赖），**不是执行序上相邻**的算子。
  执行序只用于分区与收益核算；逻辑邻接必须按**模型代码 / 图**确认。推论：成员可能连到执行序中
  **更前方**的算子，边界不是"上下相邻"。
- **范围判据**：优先按**实现边界**（同一函数 / 同一模块 / 同一子图）收敛，避免跨模块拼装（见规则 1）。
- **规范族强制项**：被拆散的**规范族**子算子**必须融回该族的一个算子**（如归一化族→一个归一化 kernel、
  位置编码族→一个位置编码 kernel）；在此之上**可进一步尝试跨族合并**（迭代，见规则 5）。

### 规则 1：实现边界优先

代码里**定义在同一函数 / 同一模块 / 同一子图内**的算子，默认属于同一候选组。

- 读法：以 forward / 子模块 / 子图的边界作为单元的**天然范围**；
- 跨边界默认不同组，除非图依赖证明二者相连（此时仍要过规则 2–6）。

### 规则 2：注意力算子族是硬锚点

**注意力算子族**（含其稀疏 / 量化 / 分块等全部变体）**既不能被吸收进单元，也不能被单元跨越**。

- 识别：算子名族 + `Task Type` + 该算子在实现中被当作不透明调用的位置；
- 机制原因：注意力本身的耗时不由"相邻小算子融合"决定（其优化手段在别的维度）。

### 规则 2b：通信**不是**硬锚点——按"是否真把计算序切断"判

**先按 `Task Type == COMMUNICATION` 认出通信算子**（算子名匹配只作辅助：实测按名匹配会把通信计次翻倍、
并把重叠率从 0.0% 虚高到 2.7%）。`Stream ID` **不能**单独当判据——实测真实产物里通信算子的
`Stream ID` 常为 `N/A`，此时既读不成"与计算流不同"也读不成"同流"，必须走重叠率。

1. **看重叠（主判据）**：用**通信占用与计算占用的重叠率**——重叠高 ⇒ 并发、不阻塞；
   重叠≈0 且计算在其后启动 ⇒ **串行依赖，才是边界**；
2. **看 stream（仅 `Stream ID` 有值时可用）**：与主体计算流不同 ⇒ 它不在计算流的算子序里，**不构成边界**；
   `Stream ID` 缺失 / 为 `N/A` ⇒ 该判据**不适用**，不得据此下结论；
3. **看 launch 依赖**：通信 launch 算子与相邻计算的先后、有无显式同步 / wait——有依赖才是边界。

**失效信号**：通信由并发变为串行时，结论立即失效、须重判。（通信暴露与掩盖属并行模块，本技能只判边界。）

### 规则 3：分区（**仅作分析视角**）

以**锚点族**为界把执行序切成区域，便于逐区核算与呈现。**这只是切区视角**：真正决定配对的是规则 0 的
逻辑相邻与规则 1 的实现边界——**不要把规范族（归一化 / 位置编码）当成不可触及的分界**，规则 0 要求它们
反向聚合。

### 规则 4：Cube 与 Vec 的两种单元形态（按**收益来源**分流）

- **4a 隐藏型**：Vec 总量**小于** Cube 时，Cube 作单元首算子向后包裹尽量多的 Vec；终止：`Σvec ≥ Cube`
  或遇到下一个 Cube。
- **4b 搬运消除型**：小 Cube + 大 Vec（`Σvec ≥ Cube`）**仍可融合**——只要代码或 profiling 证明**输入输出
  关联**，收益来源就变成**减少中间态 GM 往返**；**不得用"cube 小"一票否决**。
- **4c 结构复杂度判据**：`cube + vec + vec + cube` 且中间 Vec 段**小于**两侧 Cube 时，**不做跨两个 Cube 的
  复杂融合**；按 4a/4b 分别处理两侧，或不动。

### 规则 5：迭代再融

一轮之后，把**已融合单元视为新的算子**再走规则 3/4（含规范族之间、单元之间的跨族合并）；收敛接收益侧
（地板先行 / 阈值 / 与图开销对抵）。

### 规则 6：已有载体优先（防重复建单元）

若某段计算已由**单个融合算子**（框架内建融合 op、自定义融合 op、已有 pattern 替换体）承载，
**不再为它建单元**——只做"是否生效"的判定（见 `fusion-benefit-method.md` 与生效观测量）。

### 分组视角：按结构段分工

- **矩阵乘族**（`MatMul` / `BatchMatMul` / `GroupedMatmul` 一类）作为**分区与首算子**；
- **纯向量段**：按规则 0 的种子 + 逻辑相邻组单元，规范族按规则 0 的强制项聚合。

## 3. 候选族与识别规则（族级，不写具体算子名）

| 候选族 | 识别规则（执行序 / 代码） |
|---|---|
| 归一化族 | 归一化算子 + 其前后的调制 / 缩放 / 平移链（scale / shift / 门控） |
| 位置编码族 | 位置编码算子 + 其周边的切片 / 拼接 / 重排（布局）子算子 |
| 激活 / 门控族 | 拆分的激活链（split + 激活 + 乘）+ 门控链 |
| 布局 / 搬运族 | 连续 ≥2 个纯搬运算子（切片 / 转置 / 拼接 / 填充 / 广播 / 拷贝） |
| 量化族 | 量化 / 反量化算子 + 其相邻的缩放、归约、类型转换 |
| 索引 / 归约族 | 索引、掩码、排序、归约类算子的链（常属实现方式问题，先判是否值得） |

- 编译侧**开关名与启用方式**见产品特性真源（本文件不复制）；
- 「预期收益量级」类启发式只用于排序取舍，不得当作某组合的预期收益引用。

## 4. 生效观测量（单元是否真的生效）

- **新增融合 kernel 的调用次数应与站点数对齐**（对不上 = 覆盖不全或误命中；计数契约真源见
  `../../pattern-dev/references/fusion-graph-forms-and-semantics.md` §3）；
- **被替代的分解链要成规模消失**才算真融合；只降几个百分点 = 被别处吸收或根本没命中；
- 完整判读顺序见 `../profiling-analyze/references/performance-analysis-methodology.md` §3.3。

## 5. 失效信号（出现即重判，不得沿用旧结论）

- **dtype / 量化路径变化**：量化点位置或出现 fp32 中间岛时，原单元的收益前提失效；
- **执行序变化**：量化、并行、缓存等使能后算子序列被重排 ⇒ 邻接关系与 `Σvec/Cube` 比都要重算；
- **图形态变化**：同一语义换了写法（多分支、view/split 形态变化）⇒ 规则 1 的边界与规则 3 的分区要重切；
- **算子在单元内被替换为现成载体** ⇒ 转规则 6；
- **代码侧实现变化**（如某个融合算子被移除 / 回退路径被引入）⇒ 该单元的收益前提要重新核算。

## 6. 案例指针（**非判据**；模型 / 框架专有事实集中在此，便于方法文件保持通用）

- 归一化族的**已融合载体**示例（某 DiT 模型中：归一化 + 调制 + 门控 + 残差已被单个融合算子吸收）
  ⇒ 属规则 6，不再建单元；其"未融合的裸归一化"才是机会。
- 位置编码族的**布局链来源**示例（某框架的 NPU 侧旋转位置编码在有形状回退分支时会引入
  切片 / 转置 / 重排 ⇒ 该单元收益主要来自**消掉回退布局链**）。
- 具体模型 / 框架 / 版本的实测读数与案例细节 → 会话产物目录与对应 case 记录，**不进本文件**。

## 7. 维护与更新

- 新增算子族 / 新框架结构出现**新锚点**时，补规则 2/2b 与第 3 节族表；新增或修改锚点须有实测证据，
  无证据不得写死判据（通信侧已复核到「如何识别」这一层：`Task Type` 为 `COMMUNICATION`、
  `Stream ID` 常为 `N/A` ⇒ 判边界只能走重叠率，不能走 stream 差异）；
- **并行形态是否改变锚点**属并行域问题（见 `../../dit-parallel-opt/SKILL.md`），本文件只写与并行形态
  无关的结构判据，不为某一种并行形态单列锚点；
- 本文件只写判据；实测数值（容量、wave、绝对耗时）留在实现侧笔记与会话产物归档。
