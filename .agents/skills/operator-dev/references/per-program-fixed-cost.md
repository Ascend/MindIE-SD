# per-program 固定成本：识别与修法

> 归属：`operator-dev`。**识别**（判型第三类 + D1–D4 检测器）在
> `../../fusion-scope-analyze/references/fusion-benefit-method.md` §1.1；本文件只写**修法**。
> 本文的读数为本仓实测，用作**量级与形态**说明，不作为跨机预期值。

## 1. 形态：耗时与工作量不成比例，却与 program 个数成比例

**朴素两参数模型**（用于把两者分离）：

```text
T(K) = (N / K) · c  +  N · p
        └ 固定成本 ┘    └ 工作量 ┘
N = 总块数，K = 每 program 处理的块数
c = per-program 固定成本（启动/标量/同步）
p = 每块成本（算术或访存）
```

**本仓一例**（某量化核 `_qk_norm_rope`，生产几何）：按上式做两参数拟合可把 per-program
固定成本与每块成本分离，该核的**固定成本占其耗时的量级为几十个百分点（约三成）**，
且这部分工作**在 AIV 管线之外**——
所以管线占比（`aiv_vec_ratio` 等）读不出来，**"向量饱和"的判型会漏掉它**。
（该例属 §1.1 的 **A 重叠型**：固定占比与实测恢复率同量级、两者接近是机理决定的，
不是普适关系——**判别与适用范围见下节**。读数见会话产物归档 `{run_results_dir}/archive/`。）

### 1.1 收益有**两种机理**，先分清是哪一种（2026-09-20 实测，两组各三核）

"更少更胖的 program"能省的不止一项，实测存在**两种机理**，**判别量 = 各管线忙时间之和 `Σpipes` 在两臂间变不变**：

| 机理 | `Σpipes` | `Duration` | 恢复率与固定占比的关系 | 形态示例（核名） |
|---|---|---|---|---|
| **A 重叠型**（管线原先被串行化） | **基本不变** | 下降 | **恢复率 ≈ 固定占比**（±1pp） | `_qk_norm_rope`、`_gate_then_norm1`、`_indexed_gate_...`（仅作形态示例，读数见会话产物归档 `{run_results_dir}/archive/`） |
| **B 算量下降型**（每 program 的重复/冗余工作被摊掉） | **显著下降** | 下降 | **恢复率 > 固定占比，可达数倍** | `_quantize`、`_pool`、`_boundary_amax`（仅作形态示例，读数见会话产物归档 `{run_results_dir}/archive/`） |

**⇒ 纪律**：

1. **必须先算 `Σpipes` 两臂之差**，据此判断是 A 还是 B；两者都真、但**解释与预测方式不同**。
2. **只有 A 型**才可以用"恢复率 ≈ 固定占比"预测（这也是 D4 拟合的适用面）——**该式的作用域是
   A 型，不是"per-program 固定成本"这一类**。**B 型不能用它**——省的还有向量/搬运侧的重复工作
   （本仓 `_quantize` 的 `aiv_vec` 同时降了 **35.6%**，
   说明胖 program 让每个元素少做了事，不只是少付启动费）。**B 型只能实测**。
3. 无论 A/B：**"program 数（`Block Num`）在 ON 臂塌下来"是操纵变量本身的自证**，必须一起报
   （本仓的核上该数在 ON 臂塌下来——具体倍数见会话产物归档 `{run_results_dir}/archive/`）。
4. **不要用一个统一的降幅套所有核**：历史上如此外推会显著高估；按 §1.1 先判 A/B 型再选预测式。

### 1.2 grid 量化（波）效应：`K` 不是越大越好，**也不是 `W` 越小越好**

program 数只有取整后才落到核上，**最忙的那个核**拿到的是

```text
W = ceil( ceil(N / K) / 计算单元数 )      # 波数
T(K) = W · c + (W · K) · p                # 波量化模型（比朴素的 N/K 形式更准）
```

**关键量是最忙核的工作量 `W·K`，不是 `W`**：`W` 只数「波数」，而每一波要干 `K` 块活。
两条都能被实验证伪：`W` 变小但 `W·K` 变大的 K 会更慢（下表 `K = 40`）。
**为什么朴素模型不够用**：朴素的 `T(K) = (N/K)·c + N·p` 假设负载均分（`N/核数` 块/核），
而取整后最忙核实际背 `W·K` 块；本仓实测朴素模型在 `K` 极小与 `K` 接近波宽处残差最大
（读数见会话产物归档 `{run_results_dir}/archive/`），波量化模型才对。

**选 K 的规则**：**最小化最忙核的代价 `W·c + (W·K)·p`** ——
等价说法是「**把最忙核的工作量 `W·K` 压到最接近 `N / 核数`，同时让 `W` 尽量小**」。
**不要只最小化 `W`**：`W` 小而 `W·K` 大的 K 会更慢（见下面的反例）。

**反例（本仓一例，`N` 与核数现场取；下表即该例读数，另见会话产物归档 `{run_results_dir}/archive/`）**：

| K | grid=⌈N/K⌉ | W=⌈grid/核数⌉ | **W·K（最忙核工作量）** | 实测相对 K=1 |
|---:|---:|---:|---:|---:|
| 31 | 440 | 8 | **248** | −9.5 % |
| **40** | 341 | **7** | **280** | **−0.34 %（哑弹）** |
| 62 | 220 | 4 | **248** | −10.1 % |
| 124 | 110 | 2 | **248** | −10.3 % |
| 248 | 55 | 1 | **248** | −10.2 % |

`K = 40` 的 `W` 比 `K = 31` **更小**（7 < 8），但最忙核要做 `7 × 40 = 280` 块，而 `K = 31` 只做
`8 × 31 = 248` 块 ——**多背 12.9 % 的活**，而省下的 per-program 固定成本本来只占这个小核的 ~10 %，
于是净亏。**只按 `W` 选 K 就会挑中它**。

**⇒ 落地做法**：把候选 K 各算一遍 `(W, W·K)`，按 `W·c + (W·K)·p` 排名取最优，
**并用实测复核**（本仓最优出现在 `W = 1` 的那一档，最贴近 `N/核数`）。
K 超过阈值后收益**很平**（本仓 B/C 核 `K ≥ 62` 后都在 −10 % 附近），但 **K 过大时尾部守卫的代价会回来**
（见 §2.1 的整除性注意）。

**为什么必须用 D4 判别实验确证**：`c` 与 `p` 只在"改变 K"时才分离；
只调 `num_warps` / 只改块大小/只改 tile，都动不了 `c`。

### 1.3 预测收益用**朴素固定占比式**，波次式只用来**选/限 K**（第三个核的实测，2026-09-20）

同一规律在另一个核（`_qk_norm_rope_kernel`，生产几何与核数现场取）上被独立复核，得到一条**使用分工**：

| 模型 | 形式 | 预测值与实测的关系 |
|---|---|---|
| 朴素固定占比 | `recovery ≈ c/(c+p·(N/核数))` 的等价拟合 | 与实测差 <1 pp（拟合误差小） |
| 波量化（§1.2） | `T(K)=W·c+(W·K)·p` | 整体压低预测值（低几个百分点） |

**实测**：最优档 **降约三成**、跨多轮**符号一致**，且**效应远超 A/A 地板**；
`K=40`（`W=7`）**复现 §1.2 的哑弹**；`K≥620`（`grid < 核数`，核都填不满）**反而显著上升（每轮同向）**。
（读数与地板见会话产物归档 `{run_results_dir}/archive/`。）

**⇒ 分工**：**报收益**时用**朴素固定占比式**（对它做拟合，误差 <1 pp）；
**选 K / 给 K 定上界**时用**波次式**（`W·c+(W·K)·p`，见 §1.2）。
原因是两式只在 `W` 变化处分离：当候选 K 的 `W` 都相同时，波次式的 `W` 项是**公共因子**，
不改变排序，只会**整体压低预测值**（本例低几个百分点）。**不要把波次式的绝对值当作收益预测。**

**尾守卫（`K` 不整除 `N` 时）**：守卫**只 AND 进 STORE 掩码**，**绝不进 load 与算术**；
代价实测（同一编译产物、同 K 下比带/不带守卫）：两臂差**全部落在 A/A 地板内** ⇒
只能报"**有界（亚百分点量级）**"，**不能报"零代价"**（读数见会话产物归档 `{run_results_dir}/archive/`）。
可证伪条件：**陈旧行负控**（把行索引写成 `row = pid*K`）的差异数必须**精确等于**
`rows·H·D·(K−1)/K`——对不上说明守卫没真正生效。

## 2. 修法（按收益排序）

### 2.1 减少 program 数（首选）

把 `grid=(nb, H)` 改成 `grid=(1, H)`，每个 program 内部循环 `nb` 块。**语义与逐块算术不变。**

- 本仓实测：**耗时显著下降（数成量级）、有效带宽成倍上升、逐字节等价**（读数见会话产物归档 `{run_results_dir}/archive/`）；
- **端口注意**：`K = nb` 一定合法（每 rank 的 `nb` 不同也没关系）；
  但**不要假设整除**——尾部用显式 `TAIL = nb % P` 或守卫处理；
- 同一手法对池化类核也成立（每 program 处理多个 cell），但**尾部守卫必须逐 cell 判**
  （本仓某 rank 的 `nc ∈ 108..112`，**不存在 >1 的 CG 能整除全部五个**）。

### 2.2 并发在飞装载（preload）—— 与 unroll 是两件事

**先发满多个 load，再统一计算**：

```text
preload：  ld0, ld1, ld2, ld3, st0, st1, st2, st3   <- 有收益
interleaved：ld0, st0, ld1, st1                     <- 没有收益
```

- 本仓实测：preload **有可测收益**；**同一段 unroll 的交错写法落在噪声地板内**（读数见会话产物归档 `{run_results_dir}/archive/`）；
- ⇒ **收益来自"并发在飞的装载"，不是展开本身**。做实验时必须两种写法都测，
  否则会把"展开"当成杠杆，或反过来错误地否决整条路。

### 2.3 `num_stages` 可能完全无效——不要据此判死

本仓实测同一循环 `num_stages` 1/2/3 给出**相同**耗时。
⇒ **"软件流水/多缓冲没效果"不能推出"这个核没有空间"**；换 preload 形式再试。
流水无效通常意味着瓶颈不在"计算与装载的重叠"，而在**每 program 的固定成本**（见 §1）。

## 3. 反直觉的负结果（不要凭直觉删东西）

本仓同一核上实测、均为 22/22 同号：

- **去掉一个看似冗余的 2.25× 装载** ⇒ **更慢**（读数见会话产物归档 `{run_results_dir}/archive/`）；
- **去掉一段看似直通的四分之一** ⇒ **更慢**（同上）。

⇒ **"这段看起来多余"不是证据**。任何"删除"类改动都要按 perf-gate 的地板与同窗配对判定，
并给出负结果记录（否则下一个人会再试一遍）。

## 4. 验收（缺一不可）

1. **逐字节**：`torch.equal` + md5 + **差异元素计数**（不是只看 True）；
2. **有效带宽**前后对照（不是只看耗时）；
3. **program 数**前后对照（证明你确实动的是 `c` 那一项）；
4. 单卡地板：先测 A/A 地板；跨运行绝对值不可比（见 `../../perf-gate` §7.3/§7.4）。

**另加两条（缺一即该结论不可用）**：

1. **负控必须咬得住**：构造一个**故意错**的 fat 版（例如把行索引写成 `pid * K` 造成陈旧行），
  断言它的字节门**报错**——该负控的差异量级见会话产物归档 `{run_results_dir}/archive/`，
  `BYTE_GATE_CAN_FAIL: BITES`。**只有先证明门能失败，逐字节结果才算证据**（见 `perf-gate` §8.6）。
2. **报告单位要写清"per call"还是"per block"**：K 扫描的 `dep` 是**一个测量块**的耗时
  （含多轮多调用），直接当"每调用耗时"会比 profile 的 µs/call 大三个数量级。
  本仓 harness 曾把 `ms` 标签下的读数按 µs 打印，并把它标成 `ms/call`——
  **换算成 ms/step 时一律用"恢复的绝对时间 × 每步调用次数"**，不要用标签。

3. **尾块安全：守卫必须同时覆盖 LOAD，不只是 STORE**（设备侧陷阱）。
   当 `K` 不整除 `rows` 时最后一个 program 是**部分块**；只把 `row < rows` AND 进 STORE 掩码，
   而让 LOAD 照常发出，就是**越界读**——本仓实测该写法下
   `x` 的读**越过张量末址一段可观距离**（用 kernel 自己的地址公式算出来的，非估；读数见会话产物归档 `{run_results_dir}/archive/`）。
   是否真的报错**取决于分配器把什么放在那里** ⇒ 同一份代码、同一个 K，
   一个臂干净通过、另一个臂报 `aivec error exception / vector core exception`。
   ⇒ **"隔离逐字节通过"不能证明没有越界**（越界读常常读到无害内容）；要么把
   `row < rows` 同时 AND 进**所有** mask（本仓 6 个 load + 7 个 store），要么用
   **clamped row**（`t_safe = min(row, rows-1)`）让**形成的地址集合**成为已部署 kernel 地址集合的子集
   —— 最好两者都做（前者防越界、后者防"地址形成"本身越界）。
4. **K 扫描必须包含"出厂默认实际算出来的那个 K"**。本仓 v1 的扫描覆盖了一组按倍数递增的取值，
   而代码的 fallback 算出的是 `ceil(rows/核数)` —— **恰好是被漏掉的那个点**，
   也是唯一会走进尾块的常见取值（具体取值见会话产物归档 `{run_results_dir}/archive/`）。
   ⇒ 默认值应当**取能整除 `rows` 的 K**，并把"该规则复现出 `_K_DEFAULT`"写成断言。
   读参与度日志时也要认指纹：**修好的默认是「无部分块」的那个 K/grid**，带尾路径是另一个 grid。

## 维护与更新

- **更新触发条件**：① 后端对"每 program 固定成本"的摊薄方式变化（编译器/运行时开始自动合并 program
  或分摊启动成本）⇒ §2.1 的收益量级需重测；② `num_stages` / 多缓冲语义在本后端被修复或改写
  ⇒ §2.3 的处置需同步；③ `../../fusion-scope-analyze/references/fusion-benefit-method.md` §1.1
  的检测器（D1–D4）字段或判据变动；④ `../../perf-gate` 的 §7.3/§7.4 口径变动；
  ⑤ **计算单元数（波宽）或 grid 量化方式变化** ⇒ §1.2 的 `W` 公式与"选 K 规则"必须重算；
  ⑥ **§1.1 的 A 型预测式（"恢复率 ≈ 固定占比"）若在某个核上偏离超过几个百分点** ⇒ 先算两臂
  `Σpipes`：**降了就是 B 型**（该式本就不适用，改用实测），**没降才是 A 型偏离**，此时说明该核
  另有机制（如固定成本可被重叠、或尾部守卫成了新瓶颈），应把该核作为**反例**记录而不是改比例。
- **复核方法**：取一个已知 program 数远超计算单元数的核，按 §1 的两参数拟合重新分离 `c` 与 `p`，
  **先用 §1.1 的 `Σpipes` 判 A/B；A 型再用规律预测恢复率、B 型直接用实测验证**；
  两者差超过几个百分点即说明模型在该核上不成立。
  若 `c` 已接近 0（或改 K 不再影响耗时），说明该类已被机制消除，**本条应删除而不是保留**。
- **删除纪律**：本文件只承载**修法与判据**；具体某核的读数属会话产物，不进本文件
  （§1.1 的三核表是**形态示例**，不是跨机预期值）。
