# triton-ascend 的 lowering 陷阱（数值与性能都会被悄悄改变）

**加载时机**：在 Ascend 上用 Triton 写 / 调内核时 —— 尤其当内核**编译通过、结果"接近但不相等"**，
或**同一个语义换个写法性能差数倍**时。本文件只记**backend 侧的 lowering 事实**（可迁移到别的内核），
具体量化契约不在这里（契约见 `../../quantization-dev/SKILL.md`；内核级 UB/wave 约束见
`vertical-fusion-notes.md`；计时口径见 `../../benchmark-dev/references/benchmark-guide.md`）。

**一句话**：在 triton-ascend 上，**"写出来的语义"与"发射出去的语义"可能不同**，
而且**不报错、不告警** —— 只有逐字节对拍或同口径计时才看得见。

## 一、三个 lowering 陷阱

| 陷阱 | 现象（怎么发现它） | 处置 |
|---|---|---|
| **bf16 往返被静默消除**：`x.to(tl.bfloat16).to(tl.float32)` 在本后端上是 **no-op** —— 判据不是"值是不是标量"，而是**这个值是否紧接着被存成 bf16**。**标量**（含掩码加载出来的标量）与**参与后续算术的张量**都命中 | 与 torch 的同语义写法在**大量元素上不相符**，且**原样返回输入**；后果是**舍入根本没发生**（实测**全部元素不符**）；**另一条证据**：一个**存 fp32** 的探针内核上**全部取值原样返回** —— 连 constexpr 都通了、开关 True/False 却是 **0 差异**，看起来"实现无效" | 改用**整数 RNE 位技巧**：bitcast `int32` → `b = b + 0x7FFF + ((b >> 16) & 1)` → 取高 16 位 → bitcast 回 fp32（与 torch 的 bf16 cast 在**含 ties 的大批取值上逐位一致**）；**标量路径要单独套一遍**。⚠️ **还有一条同样致命的语义陷阱**：舍入必须放在**参考实现真正落盘的那一步**——rms_norm 的例子：**post-weight**（`bf16(x*inv*w)`）与 `npu_rms_norm` 只差**百万分之几量级的元素**，而照抄邻近算子 `rms_norm_strided` 的 **pre-weight** 写法差到**四分之一量级**（读数见会话产物归档 `{run_results_dir}/archive/`）⇒ **抄名字会抄错语义**，必须对着参考实现的存储点定位置 |
| **gather 式加载会改变 `x / scale` 的 lower**：把"按索引取数"写成数据相关的 gather 载入后，除法的发射形态随之改变 | **原始观测（二维块 tile + bf16 混合的真实量化核）**：同一算法、同一输入，**只有载入写法不同**，输出出现成片字节差（相对全体元素只占极小比例，看起来"几乎全对"；读数与规模见会话产物归档 `{run_results_dir}/archive/`）。⚠️ **未独立验证**：两条**一维隔离复现路线**（值走 gather / scale 走 gather）都给出 **0 差异**，**原始观测的二维块 tile 条件未复现** ⇒ 引用必须带"未独立验证"标注（升级 / 删除条件见维护节） | **作为稳健写法**：**先用一次 `index_select` 把 token 拷进块序**，再在**规整的跨步 tile** 上做算术 —— 把"数据相关的载入"与"数值算子"**分开**。⚠️ 这是**可读性 / 稳健性**建议，**"必须如此才正确"尚未被验证**（同上标注） |
| **`tl.sum(axis=0)` 在本后端是顺序求和**：不是树形归约 | 与 numpy 的**顺序折叠**逐元素一致、与**树形**在大量元素上不一致（原始观测：前者 0 差异、后者成片不符；**设备侧最小复现见下方注②**：顺序 **0 差异**，树形与 `torch.sum(0)` 都成片不符，且**对照**顺序 vs 树形本身也成片不符 ⇒ 探针有能力失败 ✓） | **需要特定结合顺序时不要在 Triton 里凑** —— 树形归约**发射不出来**。要么把该归约留在库算子侧，要么接受"结合顺序不可控"（此时不能声明 L1 逐字节，见 `../../accuracy-gate/SKILL.md` 的分层铁律） |

> 三者的共同点：**编译通过、无告警、结果"几乎对"**。所以判定它们的唯一手段是
> **位级对拍**（口径 `../../quantization-dev/SKILL.md` §五）与**同口径计时**，而不是读生成代码。
>
> **陷阱①的修法已在设备侧复跑验证**（单卡 / 双卡、无模型）：朴素写法与整数 RNE 写法在**边界采样**上
> 不一致样本（≠0 ⇒ 陷阱存在 ✓）；改用整数 RNE 之后，融合内核的 scales 与 eager
> **逐元素、逐块均为 0 差异**（⇒ 修法有效 ✓）。两者都**报计数**，不报"看起来一致"。
>
> **注②｜陷阱③ 已复现，且带"能失败"的对照**（单卡、`R=512 × C=64`、fp32、无模型）：
> 内核 vs **显式顺序折叠 = 0 / 256**、vs **显式树形折叠 = 60 / 256**、vs `torch.sum(0) = 58 / 256`；
> 关键在**最后那条对照** —— **顺序与树形本身相差 60 / 256** ⇒ 该对拍**有能力失败**，
> 于是"0 / 256"才是证据（没有对照的 0 差异不算验证）。
>
> **顺带被独立验证的一条（可直接引用）**：**同一数学表达式上，本后端 triton 内核的 fp32 除法与库算子
> 可差约 1% 的元素**（两种载入写法**各自**对精确参照都有同量级的不符元素）。
> 这就是"**先跟库算子比正确性、再比性能**"（§二 结论）的实证理由。
>
> **注③｜本树里两处"看起来开了、其实没生效"的舍入开关：**
> 凡是把舍入写成 `(expr).to(tl.bfloat16).to(tl.float32)` 的地方，在本后端**都是 no-op**：
>
> * `qk_norm_rope.py`（`layers/`）的 `rms_norm_strided(..., round_mid=True)` —— **惰性**；
> * 同文件的 RoPE 算术变体 `ropevar=1/2`（按变体做乘后舍入）—— **惰性**，这解释了早先"三个 ropevar
>   变体结果逐位相同"的困惑：编译出来的**永远只有 v0**。
> 走显式整数 RNE 的路径不受这两处影响；但**任何引用
> `round_mid=True` / `ropevar=1/2` 的结论都必须先按本文陷阱①重测**（这就是这两处的复核触发）。
> 同族的另一个副作用：`qk_norm_rope.py` 的整数 RNE 写法（`_round_mid_bf16`）能让该模块自带测试里
> 原本失败的 one-ulp 用例通过——即"测试通过"本身也可能是这类 silent lowering 的受害者。

## 二、Triton vs torch：按"算子形态"选，不按"看起来该用 Triton"选

本后端的实测形态（环境见各技能的 §0/适用范围声明，**换版本必须重测**）：

* **bulk（大块、规则、逐元素）拷贝 / 搬运：慢于库算子（⚠️ 本环境尚未独立验证）** —— 会话内观测称
  中等规模的整块拷贝用 triton 内核会比 torch `copy_` 慢数倍，但**设备侧隔离探针本轮没有直接测这一项**
  ⇒ 该子命题降级为"**待验证**"：只当**选型提示**用，不要当结论引用。这类活**没有融合语义可省**，
  因此**先跟库算子比**再决定（比完再选，别默认"用 triton 就更快"）。
* **折叠大量小算子：Triton 赢** —— 把几十次小算子下发折成少数几个内核，收益主要来自
  **省掉主机侧的下发**（本仓实测：同一段逻辑从上千次下发降到十次量级）。
  **设备侧独立复测（单卡/双卡、无模型；每 step、50 层投影，比值口径）**：融合后 host 侧降约**四成半**、
  device 侧降约**八成半**，但**绝对节省主要落在主机侧** —— host 省下的量是 device 省的**二十倍量级**
  ⇒ "收益来自**省下发**"独立成立 ✓（绝对值见归档；这也正是"必须做主机 / 设备分解"的原因）。

⇒ **选择判据**：先问"这笔收益来自**带宽/计算量**还是**下发次数**"。

* 来自下发次数 ⇒ Triton 融合是对的（并且要做**主机 vs 设备**的时间分解，别把"省下发"记成"省设备"，
  口径见 `../../perf-gate/references/measurement-discipline.md` §10.1）；
* 来自带宽/计算量 ⇒ **先跟库算子比**：Triton **可能更慢**（⚠️ 该子命题在本环境**尚未独立验证**，
  见上条 —— 别拿它当结论，拿它当"必须实测"的理由）。

**结论**：**同一个功能，两个候选（库算子 / Triton 内核）各测一遍再选**，并且**先比正确性、再比性能**
（口径见 `../../quantization-dev/SKILL.md` §0.1）。

## 三、逆向一个库归约的正姿势：先定"族"，再调参数

要**逐位复现**库里某个归约（均值 / 求和）时，搜索空间不是"参数"，而是"**结合结构的族**"。

**两步法**：

1. **先判形状相关性**：固定一段输入，只改"**调用里放了多少份**"（本仓口径：调用内块数 n 从 1
   变到生产形状），看该段结果是否改变。**逐位不变 ⇒ 存在唯一固定归约树**、形状不是变量
   （本仓实测 0 / 128 不同 ⇒ 与 n 无关），于是可以**脱离调用形状**去逆向它；反之才需把形状当自变量。
2. **再按族穷举**，不要在同一族里调参数。族清单（按先验顺序）：
   **相邻配对树（pairwise）→ 对折（halving）→ 跨步（strided）→ 分块（block + 块内归约）**。

**本仓实测**：在**相邻配对树**族里试了数十种参数组合**全部失败**；换成**对折树**
（`cur[i] += cur[i + L/2]`，步长自 `L/2` 逐次折半到 1）后**一个式子逐位命中**
（数百万个值 0 差异）✓。⇒ 教训：**"搜了很多种都不匹配"通常意味着族选错了**，
不是"不存在这样的结构" ✗。

**配套**：逆向结论必须带**对照**（另一族应当**不**匹配，证明对拍有能力失败），
并写出**运算顺序的完整规格**（步长序列 + 累加方向），否则下次还得重来。

## 四、反模式

* 把"编译通过"当正确性证据（三个陷阱都会编译通过）；
* 只在**一个形状**上对拍就宣布等价（lowering 与 tile/形状相关，等价性常随形状变化）；
* 用生成代码/中间表示"看出来"它做了什么 —— 以**位级对拍 + 同口径计时**为准；
* 为了让 Triton"能跑"而把数据相关的载入与数值算子合并到一个表达式里（陷阱二的成因，**但"必须拆开"本身尚未被验证**）；
* 把"**0 差异**"直接读成"backend 已修好该行为"—— 先确认用例**有能力失败**（除数**不是 2 的幂**、
  且带一条**本应出现差异**的对照），否则 0 差异只是"这个用例不可能失败" ✗（本次陷阱② 的第一版就栽在这里）。

## 维护与更新

* **更新触发条件**：triton-ascend / CANN 版本变化（lowering 是版本行为）；
  内核形状、tile 参数、载入写法变化时，§一 的三条都要**重跑一次最小复现**。
* **证据级别（设备侧复跑后的口径）**：
  * §一 **陷阱① 已复现**（边界采样上不一致样本 ≠ 0；整数 RNE 修法后逐元素、逐块均为 0 差异）；
  * §一 **陷阱③ 已复现，且带"能失败"的对照**（顺序 0 差异 vs 树形成片不符；对照本身也成片不符）；
  * §一 **陷阱② 未独立验证**（两条一维复现路线均 0 差异 ⇒ **既不成立也不推翻**；
    原始观测的**二维块 tile + bf16 混合**条件未复现）⇒ 引用必须带"未独立验证"标注；
    **升级 / 删除条件**：在**目标形状**下能给出可复现条件即升级为已复现；
    若在目标形状下也复现为 0（且用例已被证明有能力失败）则**删除该条**；
  * §二 "**折叠小算子**"已独立复测（host 降约四成半、device 降约八成半，绝对节省 host : device ≈ 20 : 1）；
  * §二 "**bulk 拷贝慢于库算子**"**未在设备侧独立验证** ⇒ 必须带"待验证"标注。
* **两条通则（都不进判据）**：
  1. **比例类数字**（如"约三成"）随数据分布与形状变化，只描述现象、不作为验收线；
  2. **"0 差异"必须先排除"用例不可能失败"**：本次陷阱② 的第一版用例把除数取成 **2 的幂**，
     除法在**任何** lowering 下都精确 ⇒ 差异恒为 0，**照"0 就删条"的规则会误删一条可能成立的条款** ✗。
     正确做法 = 选**非精确除数**（如由 `amax/127` 派生的实数）+ 一条**本应出现差异的对照**。
* **复核方法**：对每条陷阱写一个**最小复现**（几行内核 + 与 torch 同语义写法对拍，报"差异数 / 总数"）：
  ① 标量 bf16 往返是否仍原样返回输入；② 同一算法在"gather 载入"与"先 `index_select` 再规整 tile"
  两种写法下的字节差异数（**必须在目标形状下做**，一维简化不算覆盖）；③ `tl.sum(axis=0)` 与顺序折叠 /
  树形折叠各差多少。三条都**报计数**，不报"看起来一样"；**每条都要附一条"能失败"的对照**。
* **失效信号**：若某条陷阱的差异计数变成 **0**（且用例已被证明**有能力失败**，见通则 2），**删除该条**，
  不要留"以防万一"；反之若出现新的"编译通过但字节不符"的最小复现，按本表格式追加。
