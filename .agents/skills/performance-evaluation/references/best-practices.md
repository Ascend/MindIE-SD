## 1. 评估准备

### 明确所有必需参数

在开始前获得用户对以下参数的明确确认：

- ✅ 模型规格（如T2V-14B）
- ✅ 设备类型（如ATLAS_800_A2_376T_64G）
- ✅ 分辨率（如480×832）
- ✅ 量化方式（如DISABLED）
- ✅ 视频帧数（视频模型，如81）

**禁止**：自动推断或猜测用户未明确指定的参数

### 检查模型规格

如果模型有多个规格，必须列出供用户选择：

```text
模型 Wan2.2 有多个规格可用：
1. Wan2.2-T2V-14B (14B参数，文本到视频)
2. Wan2.2-I2V-14B (14B参数，图像到视频)
3. Wan2.2-T2V-1.3B (1.3B参数，轻量版)

请选择具体规格（输入编号或名称）：
```

### 验证硬件支持

确认目标设备在支持列表中，或获得完整的设备规格：

```bash
python -c "from tensor_cast.device import DeviceProfile; print(list(DeviceProfile.all_device_profiles.keys()))"
```

**未知硬件处理**：如果设备不在支持列表中，**必须暂停**询问规格：

- 设备厂商
- FP32算力（TFLOPS）
- FP16算力（TFLOPS）
- 显存容量（GB）
- 显存带宽（GB/s）

## 2. 多卡评估

### 必须明确并行策略

不要假设默认策略，根据模型类型推荐并确认：

**多模态生成模型**：

- 推荐：`ulysses-size = world-size`
- 示例：4卡 → `--world-size 4 --ulysses-size 4`

**支持CFG的模型**：

- 推荐：`cfg-parallel` + `ulysses-size = world-size / 2`
- 示例：4卡 → `--world-size 4 --cfg-parallel --ulysses-size 2`

### 记录通信开销

多卡时必须记录通信算子详情：

```text
Communication Operators:
+-------------------+----------+----------+
| Op Name           | Time(ms) | Calls    |
+-------------------+----------+----------+
| all_gather        | 523.4    | 28       |
| all_reduce        | 312.8    | 28       |
| reduce_scatter    | 177.0    | 14       |
+-------------------+----------+----------+
Total communication time: 1013.2ms (7.0%)
```

## 3. 日志和记录

### 路径命名规范

严格遵循以下格式：

```text
results/<model>_<spec>_<device>_w<N>_u<N>_cfg<N>/
```

**示例**：

- `wan2.2_t2v-14b_a2-376t-64g_w1_u1_cfg0/`（单卡）
- `wan2.2_t2v-14b_a2-376t-64g_w4_u4_cfg0/`（4卡Ulysses）
- `wan2.2_t2v-14b_a2-376t-64g_w4_u2_cfg1/`（4卡+CFG）

### 完整记录配置

所有用户指定的参数和使用的默认值都必须记录在config.json：

```json
{
  "user_specified": {
    "model_spec": "t2v-14b",
    "resolution": "480x832",
    "frame_num": 81,
    "quantization": "DISABLED"
  },
  "default_used": {
    "seq_len": 64,
    "dtype": "bfloat16",
    "world_size": 1
  }
}
```

### 保存原始日志

每次迭代的完整输出都要保存，不要只保存汇总：

- `iteration_1.log`
- `iteration_2.log`
- `iteration_3.log`

## 4. 结果比较

### 同一场景比较

确保比较的硬件使用完全相同的模型配置：

- 相同模型规格
- 相同分辨率
- 相同量化方式
- 相同并行策略

### 生成比较报告

使用专门的比较脚本生成对比报告：

```bash
python scripts/generate_comparison.py \
    --scenario "wan2.2-480p" \
    --baseline results/wan2.2_t2v-14b_a2-376t-64g_w1_u1_cfg0/ \
    --target results/wan2.2_t2v-14b_a3-752t-128g_w1_u1_cfg0/ \
    --output compare/comparison_wan2.2_480p_20240307.md
```

### 比较报告内容

- 各硬件性能指标对比表
- 算子级差异分析
- 通信开销对比（多卡场景）
- 性价比分析

**保存位置**：`compare/comparison_<scenario>_<timestamp>.md`

## 6. 常见问题处理

### 用户未指定模型规格

必须暂停并显示规格列表：

```text
模型 Wan2.2 有多个规格可用：
1. Wan2.2-T2V-14B (14B参数，文本到视频，480p-720p)
2. Wan2.2-I2V-14B (14B参数，图像到视频，480p-720p)
3. Wan2.2-T2V-1.3B (1.3B参数，轻量版，480p)

请选择具体规格（输入编号或名称）：
```

### 使用多卡但未指定并行策略

根据模型类型推荐并确认：

```text
检测到使用多卡配置（world-size=4）

推荐并行策略：
- Ulysses并行: 4 (ulysses-size=4)
- 适用于: Wan2.2-T2V-14B
- 通信模式: all-gather + all-reduce

是否接受此配置？
[Y] 接受推荐配置
[N] 自定义配置
```

### 视频模型未指定frame-num

必须暂停并要求明确：

```text

视频模型必须明确frame-num（视频总帧数）：

- 81帧（约3秒@27fps）
- 121帧（约4.5秒@27fps）

请输入frame-num: [81]
```

## 7. 性能分析要点

### 算子级分析

重点关注以下算子：

- **MatMul**：通常是主要瓶颈（占比40-50%）
- **FlashAttention**：次瓶颈（占比30-40%）
- **Comm**（多卡时）：通信开销（占比5-15%）

### 内存分析

- 峰值内存不应超过设备容量的80%
- 内存带宽利用率60-70%为正常范围
- INT8量化可减少40-50%内存占用

### 通信分析（多卡）

- all_reduce通常占通信时间的主要部分
- 通信开销应控制在总时间的15%以内
- 如果通信占比过高，考虑优化并行策略
