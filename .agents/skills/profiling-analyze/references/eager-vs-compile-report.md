# compile vs eager 收益对比：双报表口径（聚合 / 分母 / fail-closed）

> **定位**：只要对「同一配置下的 eager（非 compile）与 compile」做收益比较，就必须按本文件口径
> 产出 **overview + detail 两张表**（缺一不可）。本文件是这两张表的**聚合与判定口径单一真源**；
> 载体侧的采集命令、表格骨架与填写示例由各载体自持（dummy 载体见
> `../../dummy-run/references/compile-ab-report-template.md`）。
>
> **与相邻技能的边界**：本文件只定义「怎么聚合、分母取谁、怎么判定记账是否自洽」。
> kernel diff 的三类读数判定见 `performance-analysis-methodology.md` §3.3；逐 pass 负收益的根因
> 目录见 `../../pattern-dev/references/benefit-rootcause-guide.md`；同窗 A/B 与噪声地板见 `perf-gate`；
> 质量门阈值见 `../../accuracy-gate/references/quality-gate.md`。

## 1. 数据窗口与聚合口径

- 两档**各一次** timed 采集 + 对应的 `kernel_details.csv`；两档必须**同窗口、同卡组、同配置**，
  唯一变量是 compile 开/关（跨窗口绝对值不可比，口径见 `perf-gate`）。
- 聚合粒度：按 `kernel_details.csv` 的算子名聚合耗时（us→ms）；**每行耗时 = 该行覆盖 kernel 的
  耗时合计**。
- **站点 → kernel 映射（强制）**：必须结合 **compile 图 dump 的融合后节点**与**非 compile 档的
  分解链**做映射，**禁止仅按 kernel 名近似猜测**；映射过程（聚合脚本 + 数据文件 + 图 dump）随报表
  一并提交，否则报表不可复核。
- **非融合算子不拆行**：GEMM / FA 等未被融合的站点不单独成行，只出现在 detail 的执行序里作为
  「未融合」行（其收益列恒为 0）。

## 2. 收益分母（唯一定义）

- **分母 = 非 compile（eager）下该模型 transformer block 的单步耗时**
  （= eager timed transformer ÷ 步数；无法拆步时退化为 eager transformer timed）。
- 相对收益 = (融合后耗时 − 融合前耗时) / 分母 × 100%。
- 报数时必须写明**用的是哪个分母**——eager block 耗时 / eager transformer timed / 模型级 wall /
  站点 kernel 时间**互不可换**（同一条纪律见 `benefit-rootcause-guide.md` §4.x）。

## 3. 两张表的列契约

**总览表**（overview：按融合算子一行）：

| 序号 | 融合算子 | 融合前组成（eager 被替代链） | 是否完成融合 | 融合前耗时 | 融合后耗时 | 相对融合前 block 耗时的收益 | 质量变化度 |
|---:|---|---|:--:|---:|---:|---:|---|

**明细表**（detail：按 block 算子执行序列行）：

| 算子归属（Attn / FFN(MoE) / …） | 融合后所属算子 | 未融合时的组成 | 融合后性能 | 未融合性能 | 相对未 compile block 耗时的收益 |
|---|---|---|---|---|---|

- detail 的「融合后所属算子」= 该行在 compile 图里的算子名（原算子未变则填原名）；
  「未融合时的组成」= 非 compile 档下该站点的 kernel 组成（原算子未变则填单一算子名）。
- 已完成融合的行，「未融合性能」= eager 侧被替代链的合计；收益 = (未融合性能 − 融合后性能) / 分母。
- detail 行按 block 内**算子执行序**排列；同一单元连续多实例可合并为一行并标注 ×N。

## 4. 未实现行的填充纪律（fail-closed 之一）

尚未实现的融合单元必须成行，且按下列固定写法填，**不得虚填预期收益**：

```text
是否完成融合 = N（预期可融合：{依据}）  融合后耗时 = 融合前耗时  收益 = 0
```

## 5. 质量变化度列（总览表末列，与总览报表同口径）

- 与 `../../model-auto-optimization/references/overview-report.md` §4/§7 的「质量数据」列**同源**：
  **只写相对变化度**（如「位级一致（变化度 0）」「某指标降约几成」「质量基本无感」），
  **不写绝对质量分值**（纪律见 `.agents/README.md` §7）。
- 该结论是**整体 compile vs eager 口径、非逐算子拆分** ⇒ 各行的本列通常取同一份对拍结论，
  **逐行相同属正常**。
- 未测的行标 ❓ + 待测计划，**禁止静默留空或用「—」代替**。
- **明细表不重复登记本列**——逐算子质量变化不单独测，避免把整体口径伪装成逐算子口径。

## 6. fail-closed：收益记账自洽核对

- 与 `../../pattern-dev/references/benefit-rootcause-guide.md` §4.x 同一判据：任何收益行必须
  **同时**写出 ① 该行区域的**理论上限**（区域占 block 耗时比，或该区域的带宽下限）
  与 ② 本次实测收益。
- 实测收益**超过**该行理论上限 ⇒ 判**收益记账错误**（分母错 / 归因错 / 测量范围错）：
  **停止上报**，先把记账修对再报；不得把超限数字当成果。
- 上限是**环境 + 模型特定**的（换拓扑 / 换负载 / 换版本即变），必须**本地重新推导**，
  不得引用历史案例或模板里的数值当本任务上限。

## 7. 输出与归档

- 报表、聚合脚本、数据文件路径**三者同交**，缺一视为未完成。
- 正文只留**比例 / 量级 / 方向**；绝对耗时、绝对显存、绝对质量分值按 `.agents/README.md` §7
  归档到会话产物目录，不进 skill 正文（模板示例数值除外，须标明其模板性质）。
- 本报表是 compile 对比的**专项产物**；5 层递进分析主报告给的是**优化方向**，两者不可互相替代。
