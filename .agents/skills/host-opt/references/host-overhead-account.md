# 固定开销账：口径与字段

**用途**：把 host（辅助）段的固定开销拆成**可测量、可复核、可跨轮对比**的行，作为优化对象选择
与收益验收的共同底稿。标签 `非DiT-host段` 的**占比判据与门限口径不在这里定义**（单一真源在
`../../model-auto-optimization/references/bottleneck-labels.md` §2，含分母、测点与**必须带步数档**的要求）；
本文件只定义**怎么记账**。

> **作用域（强制）**：账里的每个数字都是**一次观测**，它的作用域 = 硬件 / 拓扑 / 软件栈 / 模型 /
> **步数档** / 分辨率 / 帧数 / 部署形态 / 并发形态。换任一项即重测；**报数必须连作用域一起报**，
> 否则与上一轮不可比。本文件不携带任何具体环境的耗时值。

## 1. 每行一段：字段表

| 字段 | 含义 | 必填 |
|---|---|---|
| **段** | 编解码 / 传输（worker→API）/ 落盘 / 权重加载 / 预热（编译 · 图下发 · 镜像容器） | ✓ |
| **类型** | `每请求`（交付搬运）或 `每进程 / 首启`（装载预热）——决定它该进哪个分母 | ✓ |
| **起止测点** | 精确到函数或日志行的两个测点（起 = …，止 = …），且必须落在**真实关键路径**上 | ✓ |
| **耗时** | 该段墙钟（同一台机、同一窗口、同一步数档） | ✓ |
| **占 e2e** | 该段耗时 ÷ **同口径 e2e**（分母写清是哪一个，见 §2） | ✓ |
| **字节数 / 次数** | 该段搬运、写入或读取的字节数，以及每请求发生几次（用于判断是“量”的问题还是“路”的问题） | ✓ |
| **证据** | 日志行 / 计时点输出 / 产物坐标（可复核的最小证据，不是结论截图） | ✓ |
| **口径备注** | 是否含 profiler 开销、是否含预热请求、是否含编码/封装等待 | ✓ |

## 2. 分母与测点口径

- **e2e 主口径**：与同任务其它阶段账**同一个** e2e（服务端墙钟，从请求进到结果可用）。
  交付开销的标准取法是 `e2e − forward` 并继续分解，口径单点在
  `../../perf-gate/references/evidence-toolbox.md`（**本文件不重定义**）；
- **不要用 profiler 内的墙钟当分母**：profiler 会引入自身开销，会把交付段算大（同一文件已注明）；
- **测点必须在关键路径上**：把计时点移到异步分支里，测出来的是“后台耗时”，不是请求代价；
- **每行只归因一次**：同一段被两行同时计入（例如“编码”与“封装”都包含编码）是最常见的错账，
  记账时明确行的边界（起止测点就是边界定义）。

## 3. 固定 vs 每请求：两类必须分开

| | 每请求（交付与搬运） | 每进程 / 首启（装载与预热） |
|---|---|---|
| 典型段 | 编码、通路、落盘 | 权重加载、编译 / 图下发预热、镜像容器预热 |
| 分母 | 单请求 e2e | 进程/服务启动墙钟（**不要**摊进单请求 e2e） |
| 优化判据 | 该段每请求耗时下降，且产物不变 | 首启耗时下降，且**稳态指标不变差** |
| 常见误判 | 把首启成本摊进每请求，导致“交付占比”虚高 | 把预热请求当稳态样本，导致稳态指标失真 |

**首请求与稳态必须分栏报**：预热类改动的收益只体现在首启栏；交付类改动的收益只体现在稳态栏。
两栏混在一张表里，任何方向的结论都不可信。

## 4. 常见错账（逐条自查）

1. **分母漂移**：优化顺带改了请求形态（分辨率 / 帧数 / 步数档），两轮账不可比 ⇒ 该轮作废重做；
2. **重复计入**：一行包含另一行（“编码”里含“落盘”）⇒ 占比之和 >100% 或收益重复计算；
3. **测点在异步分支**：测到的是后台时间，不构成请求代价；
4. **预热形状不符**：预热用的 shape / dtype 与生产不一致 ⇒ 预热出的是另一批缓存条目，
   “预热了但首请求仍然慢”就是这条；
5. **把 profiler 开销算进交付**：分母与分子口径不一致；
6. **只报一个总数**：不给每段拆分与证据，无法判断优化落在哪一段，也无法排除“别的段变慢了”；
7. **跨窗口比绝对值**：共享机器上跨窗口的绝对值不可比，收益必须同窗 A/B（口径引测量纪律）。
