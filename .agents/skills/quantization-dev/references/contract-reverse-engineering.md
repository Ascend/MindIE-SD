# 量化契约逆向六步法

> 用途：拿到一个**没有文档的量化器**（CANN aclnn 算子、框架内建量化、三方 kernel），
> 把它有价值的部分逆向成一份**可与别人共享的契约文档**。
> 来源：Ascend NPU 上 MXFP8(e8m0) 与 int8 量化器的实测逆向（2026-09）。

---

## 为什么不能"从合理推"

量化器的三个自由度——**scale 粒度、舍入模式、溢出行为**——**都不是自明的**：

- 你可能自然地写出 `ceil(log2(amax/448))`（因为"要保证不溢出，所以向上取整"），
  而真实规则是 `floor`（因为 scale 的语义是"归一化进 [256,512)"，越界由**饱和**兜住）。
  两者在 `amax = 450 / 1000 / 230` 上给出**不同答案**。
- 你可能自然地假定 8-bit 转换**饱和**，而它实际**回绕**。
- 你可能自然地假定 scale 数组需要**反 swizzle**，而它其实是**恒等映射**。

**上述三条，实践中全部猜错或差点猜错。**

---

## 第一步：从报错文本取算子签名

**故意传一个非法 kwarg**，报错会打印完整 schema —— 这比读任何文档都准：

```text
npu::npu_dynamic_mx_quant(Tensor input, *, int axis=-1, str round_mode="rint", int dst_type=296,
                          int block_size=32, int? scale_alg=0, float dst_type_max=0.,
                          float max_low_bound=0.) -> (Tensor, Tensor)
```

由此立刻得到：默认 `block_size=32`、`axis=-1`、`round_mode="rint"`（**必须**是 rint，其他取值报 tiling 错 `EZ0026`）、
`dst_type` 是 **int 292**（dtype code，**不是** `torch.dtype`）。

**同时确认返回值语义**：payload 是 `torch.float8_e4m3fn`，scale 是 **`torch.uint8`**（e8m0 位）。

---

## 第二步：用**判别性探针**分离规则（不要穷举扫描）

**判别性 = 差一点点就会给出不同答案的输入。**

要区分 `floor(log2(amax)) - 8` 与 `ceil(log2(amax/448))`，不要去扫一堆 2 的幂（两者在那里恰好一致），
而要挑**两者的分歧点**：

| amax | log2(amax/448) | floor | ceil | **实测** | 判定 |
|---|---|---|---|---|---|
| 440 | -0.025995 | -1 | 0 | **0** | 都可解释 |
| **450** | +0.006426 | 0 | 1 | **0** | **ceil ✘** |
| 672 | +0.584963 | 0 | 1 | **1** | 都可解释 |
| **1000** | +1.158 | 1 | 2 | **1** | **ceil ✘** |
| 1344 | +1.585 | 1 | 2 | **2** | 都可解释 |
| **230** | -0.962 | -1 | 0 | **-1** | **ceil ✘** |

**三个分歧点就足以定案**，成本远低于穷举。

**可迁移要点**：先写出 2–3 个候选规则，再**只测它们互相分歧的输入**。

---

## 第三步：用**标记法**定布局（不要读文档、不要假设）

给每个 group 一个**唯一可识别的 2 的幂 amax**（`amax = 448 * 2**e`），使其指数字节唯一，
然后**在扁平数组里搜该字节的位置**：

| group | 预期 byte | 实测扁平偏移 | `(g//2, g%2)` |
|---|---|---|---|
| 0 | 119 | **0** | (0,0) |
| 1 | 123 | **1** | (0,1) |
| 2 | 127 | **2** | (1,0) |
| 3 | 131 | **3** | (1,1) |
| 5 | 125 | **5** | (2,1) |
| 84 | 133 | **84** | (42,0) |
| 166 | 121 | **166** | (83,0) |
| 167 | 135 | **167** | (83,1) |

**结论：group `g` 位于扁平偏移 `g` ⇒ swizzle 是恒等映射。**
`[T, ceil(c/2), 2]` 只是**形状标注**，不是置换。原始文档的评语：这"removes a whole class of would-be bugs"。

**可迁移要点**：形状里有 `2` 或 `ceil(/2)` 这类因子时，**不要假定它有语义** —— 标记法一次就能证否。

---

## 第四步：写独立参考实现，要求逐字节完全相符（100%）

- **不复用被测代码路径**（独立 numpy/torch 实现）。
- 在**完整张量**上比，报**绝对计数**（`0 / 67 665 920`）而不只是百分比。
- 实测达标示例：scale 字节在**完整生产张量与多组小形状上逐字节完全相符**（对拍规模见会话产物归档 `{run_results_dir}/archive/`）；
  payload 在**全部 165 个 e4m3 中点 × 两个指数域**上**完全相符（100%）**。

**两路独立推导并在每一点一致** —— 交叉验证是低成本高收益的一步。

---

## 第五步：覆盖退化与中点

**完整的对抗性输入清单**（缺一项就可能漏掉一整个 bug 类）：

| 类别 | 具体输入 | 能抓到的 bug |
|---|---|---|
| 常规 | randn / uniform[-1,1] / all-equal-7 | 基本正确性 |
| **中点** | **全部 165 个 e4m3 中点 × 两个指数域** | **舍入模式（RNE vs half-away vs 截断）** |
| 指数边界 | `amax` 恰为 `2^k` / **略高于** `2^k` | 指数字节的 floor/ceil 选择 |
| 退化 | 全零 / 全负 / `1e-38` / bf16 次正规 | **flush-to-zero 规则** |
| 特殊值 | `±inf` / `nan` | scale=255 与整块清零 |
| 饱和 | `>448`（fp8）/ `>127`（int8） | **饱和 vs 回绕** |
| 结构性 | **尾块**（`S % 64 != 0`）、`S=1`、退化 shape | pad-then-slice 逻辑 |

**实践中的覆盖示例**（一组覆盖扫描，每例**完全相符（100%）**）：
奇数 S、`S=1`、退化、全零通道、`1e-30`、`1e4`、全负、混合。

### 退化块实测表（MXFP8）

| 块内容 | scale byte | payload |
|---|---|---|
| 全零 | **0** | 全 0 |
| `amax < 2^-119` | **0** | **全 0** |
| `amax = 2^-110`（byte 9） | 9 | 正常 RNE |
| `±inf` / `nan` | **255** | **整块全 0** |

**陷阱**：byte 0 的**表面规则**（"amax 太小 → 0"）会低估它 —— 真实语义是
**flush-to-zero**（byte 0 要求 `amax < 2^-119` ⇒ 块内每个值都是 bf16 次正规数）。
**用确定性复现确认**：

```text
amax=2.35099e-38 (2**-125)  byte 0   payload [0,0,0,0,0,0]
amax=7.52316e-37 (2**-120)  byte 0   payload [0,0,0,0,0,0]
amax=7.70372e-34 (2**-110)  byte 9   payload [120,2,1,0,0,120]
```

## 第六步：写 corrigendum（**宣布被证伪的公式**）

逆向的产出**不只是一份新公式，还包括一份"哪些看起来合理的公式是错的"**。

必须给出**判别表**（见第二步），让别人能自己验算，而不是只接受结论。
被证伪的候选：`ceil(log2(amax/448))` —— 相符率**约八成**（对拍规模见会话产物归档 `{run_results_dir}/archive/`），
**"约八成相符"正是一个危险信号：它不是随机错，而是边界条件错**。

---

## 附：确定"被量化的是什么"（比公式更容易被忽略）

生产链路 `norm(...) -> bf16 tensor -> quant` ⇒ **amax 与 payload 都基于 bf16 舍入后的值**。

改用 fp32 中间值会"在块 amax 跨越 2 的幂时改变指数 —— 随机数据约每 100 块 1 块"。
**每 100 块错 1 块 ⇒ 逐字节验收必失败，但肉眼与统计指标都看不出来。**
**这类"承重设计选择"必须在契约里显式写出**，否则下一个实现者一定会重新踩。

**验证手法**：拿一个**恰好跨越 2 的幂**的块做对照（而非随机张量），
观察 scale 字节是否差一个指数 → 若是，就是量化对象选错了。

---

## 附：从残差形状反推根因（诊断价值极高）

残差的**分布形状**比残差的**大小**更有诊断力：

| 残差形状 | 根因签名 |
|---|---|
| **错误 scale 字节全部恰好低一个指数**（`{-1: 4374}`） | **amax 取到了低一个 binade** ⇒ 量化器看到的是 `fp32(x)` 而非 `bf16(x)` |
| 差异集中在尾部 / 某个固定位置 | 尾块 / pad-then-slice 未复现 |
| 差异**全局均匀且极小** | 数值敏感度（需先用敏感度基线判定是否算 bug） |
| 差异**局部化、有接缝** | 实现错误（掩码/窗口/索引错行） |

实践中正是靠"**全部 delta = -1**"这一形状，把根因直接指向了 bf16 舍入被静默消除。

## 出处与证据等级（引用前必读）

| 结论 | 证据等级 | 说明 |
|---|---|---|
| MXFP8 字节公式 / 布局恒等 / RNE + ±448 饱和 / 退化块 | **强** | 独立逆向文档 + 两路独立推导 + 独立参考实现完全相符（100%） |
| 除数必须 LOADED（`x*(1/scale)` = 1/2 097 152 差） | **强** | 有隔离实验表 |
| bf16 RNE 整数技巧（262 144 个中点，完全不相符（0%）） | **强** | 两路独立发现（交叉验证） |
| 8-bit 转换回绕而非饱和 | **强** | `inv=1e5` 的 256 个均匀值 |
| **int8 RNE / "truncate 误差差近一半"** | **弱** | **仅有单一来源的一句话记录、未经独立复现**；相关脚本只有实验设计、**原始日志不在手、无交叉验证**；且该数字必然是在**修正 scale 粒度之后**才测得的（粒度错时三种舍入一律约六成） |
| int8 尾块精确复现 | **未完成** | 尚无已验证的复现实现 |

**引用 int8 结论时必须带上"证据弱/未完成"的标注** —— 这正是本文件存在的意义之一。

> **⚠️ 作用域提示**：本文件的每一条契约（MXFP8 字节编码、scale 布局恒等 swizzle、RNE ±448 饱和、退化块规则、
> 「除数必须 LOADED」）都是在**某一块芯片 + 某一个 CANN/软件版本**上逆向出来的，是该版本的实测事实，
> **不是跨版本的通用定律**。换版本（CANN / 算子库 / 硬件代际）必须**按上面六步法重新推导**，不得直接套用；
> 已「证伪」的公式也要重测 —— **在某个版本下被证伪的公式，换一个版本完全可能重新成立**。

**⚠️ 契约本身也会过期（是快照，不是永久事实）**：本文每条契约都只是**某次逆向的快照** —— 算子可能在新版本里
**公开 schema、提供原生 API**（不再需要逆向），数值规则（粒度 / 舍入 / 饱和行为）也可能被修改或修正。
**换版本必须按上面六步法重新推导**，不得把本文当跨版本定律直接套用。
由契约派生的每个绕行（「除数必须 LOADED」、大 tile + 64 行子块 amax…）都要**自带复核触发**：一条探针确认它仍必需，**不再复现即删除**。

## 维护与更新

- **触发条件**：方法学或参考实现变化——第一步的 `npu_dynamic_mx_quant` schema 与 `round_mode="rint"`
  约束（其他取值报 tiling 错 `EZ0026`）、第二步判别性探针的分歧点（`amax` 450 / 1000 / 230）、
  第三步标记法得出的恒等 swizzle、第五步退化块表、第六步 corrigendum 的被证伪公式
  `ceil(log2(amax/448))`；以及逆向对象更换（换一个量化器）带来的新证据类别。
- **复核方法**：换 CANN / 算子库版本后重跑第一步（故意传非法 kwarg 取 schema）与第二步三个分歧点
  探针，核对 floor / RNE / ±448 饱和 / 恒等 swizzle 是否仍成立；`int8` 相关结论按「出处与证据等级」
  继续标**弱 / 未完成**，补齐独立复现后才升级等级。
